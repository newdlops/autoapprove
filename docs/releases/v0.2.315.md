# AutoApprove 0.2.315 · build 342

Codex의 긴 승인창을 자동 승인하지 못하는 문제를 수정했습니다. 기존에는 승인
제목을 마지막 300줄 안에서만 찾고, 제목부터 확인 안내까지 300줄을 넘으면
거부했습니다. 긴 명령이나 여러 파일의 수정 내역이 있으면 전체 승인창을
읽었어도 이 제한 때문에 자동 승인이 멈출 수 있었습니다.

현재 선택된 첫 번째 선택지와 완전한 확인 안내가 있을 때 Codex 승인 제목의
검색 범위를 확장합니다. 실제 전송 전에는 명령·파일·선택지·안내를 포함한
원래 승인창 전체를 다시 비교합니다. 일반 출력의 기본 검색 범위는 유지하며,
Claude의 감지·승인 경로는 변경하지 않았습니다.

승인 제목이나 선택지·안내 자체가 읽힌 화면에서 잘린 경우에는 자동으로
보충하지 않습니다. 일반 질문, 거절 선택 상태, 코드 블록 속 예시와 이후 출력이
붙은 과거 승인창도 자동 승인하지 않습니다. 이번 수정은 내부 IPC나 서버의
승인 정보 대신 기존 터미널 화면 텍스트를 사용합니다.

검증: 수정 전 299줄 본문에서 실패를 재현했습니다. 수정 후 299·300·301·1,200줄
본문의 Swift·AppleEvent 문자열 경로, 1,200개 파일 경로가 있는 수정 승인,
불완전한 승인창 거부와 전송 직전 파일 변경 차단을 검사했습니다. 사용자
터미널에는 시험 입력을 보내지 않았습니다.

전체 디버그 회귀 검사 305개가 통과했습니다. 별도 격리 엔진에서도 1,200줄
승인이 화면 분석부터 자동 전달까지 도달하고, 같은 화면을 반복해서 받아도
한 번만 전달되는 것을 확인했습니다. 실제 터미널 전송 대신 시험 어댑터를
사용했으며 전송 대상에는 승인창 전체 내용이 유지됐습니다.

최종 배포 빌드의 전체 회귀 검사도 276개 모두 통과했습니다.
