# AutoApprove 0.2.182 · build 209

터미널 문자·커서 반영을 앞당기고, 대용량 PTY 입력이 출력 대기와 서로 막히는
문제를 수정했습니다.

- 원본 입력의 마지막 글자 뒤 80ms 대기를 최초 입력 뒤 8ms로 줄였습니다.
  연속 입력이 전송을 계속 뒤로 미루지 않습니다. 화면과 커서는 같은 프레임에 반영합니다.
- PTY는 고정 4ms 창을 쓰고, 응답 대기 중 쌓인 미전달 바이트를 최대 16KB로 합칩니다.
  같은 지연 응답 구간에서 **21→2회 요청**, JSON 본문 **4,771→486B**였습니다.
- PTY 입력 버퍼가 차면 같은 원본의 출력을 비워 쓰기를 진행합니다. 부분 전송의
  처음부터 재쓰기, 불확실한 입력의 자동 재전송은 하지 않습니다.
- 실제 브라우저의 문자 반영 중앙값은 Chromium에서 원본 어댑터 **157→47ms**,
  실제 zsh PTY **48→31ms**, WebKit에서 **145→51ms / 38→24ms**였습니다.
  원본 Chromium 방향키는 **98→47ms**, WebKit PTY 방향키는 **37→25ms**였습니다.
  다른 방향키 조합의 중앙값은 거의 같았습니다. 각 12회 격리 loopback 검사이며
  물리 휴대폰·무선망·OS 화면 표시 시간과 구별합니다.
- 두 브라우저에서 **56,003B Unicode의 실제 자식 수신 일치**, 한글 조합 중간
  전송 금지, 같은 PID/TTY/stream 보존, 응답 유실 후 1회 전달·미전달 초안 보존을 확인했습니다.
  연속 입력을 먼저 보내므로 해당 입력의 총 요청 수가 늘 수 있으며, 전체 망 사용량
  감소를 주장하는 수치는 아닙니다.

최종 Core **451/451**, 원본 복구 **9개**, 브라우저 연결 **11개**, 실제 PTY
**15개**와 네이티브 PTY 통합 **17개**를 통과했습니다. Chromium/WebKit 세 화면 크기와 배포 패키지의
입력 보조 프로그램·서명·네트워크·PTY를 확인했습니다.
