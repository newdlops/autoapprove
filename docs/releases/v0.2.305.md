# AutoApprove 0.2.305 · 빌드 332

- Codex `/status`의 Session ID가 화면에 보여도 카드 상단이 잘리거나 이전 카드와 개수가 같아 ID 갱신이 실패하던 조건을 보완했습니다. 명시적 갱신 때만 원래 Terminal의 기록을 전후 비교하고 새로 추가된 완전한 상태 카드의 UUID를 사용합니다. 기록 내용은 저장하지 않고, 평상시 감시에는 기록 읽기를 추가하지 않습니다.
- Codex ID 조회 전후의 결과 판별은 원래 터미널의 최신 텍스트를 직접 읽습니다. 작업 중 조회, 작성 중인 입력 보호, 질문·승인 충돌 방지, 원래 프로세스 재검증을 유지합니다. Claude ID 조회 경로는 변경하지 않습니다.
- 별도 MCP helper를 Codex 실행 도구에서 시작했을 때, 호출별 메타데이터가 없으면 Codex가 전달한 `CODEX_THREAD_ID` 실행 컨텍스트를 사용합니다. 호출별 메타데이터가 우선하며 도구 인자로 전달한 호출자 정보는 신뢰하지 않습니다.
- 그룹 조회에 `connectionState`를 추가해 확인된 연결(`verified`), 원래 프로세스는 있으나 ID가 미확인인 연결(`identity_unverified`), 끊긴 연결(`disconnected`)을 구분합니다. 기존 `connected`와 작업 전달 권한 조건은 유지합니다.
- 수동 연결 저장·재연결 때 구성원의 상위 관계를 보존합니다. 재연결은 그룹장을 바꾸지 않습니다.
- 로컬 소켓 접근이 샌드박스나 권한으로 차단되면 앱이 꺼졌다는 안내 대신 실제 차단 원인을 표시합니다. 그룹 통신은 계속 같은 Mac의 Unix 소켓과 원래 터미널만 사용합니다.

기존 사용자 CLI·대화·MCP 프로세스는 강제 재시작하지 않습니다. 새 helper 코드는 새 MCP 연결에 적용됩니다. 실제 사용자 터미널의 갱신 성공 여부는 별도 확인이 필요하며, 새 상태 카드가 확인되지 않으면 기존 ID를 유지합니다.

전체 릴리스 회귀 검사 265/265, IP 통신 차단 상태의 그룹 29/29와 MCP stdio 재연결 검사가 통과했습니다.
