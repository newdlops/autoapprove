# 0.2.151 · 터미널 위치 표시 안정화·PR #8·설치 파일 경량화

터미널 열기에서 테두리를 표시하기 위해 Terminal에 창 크기를 묻던 요청을 제거했습니다. 현재 창 ID와 소유 PID가 일치하는 macOS 창 메타데이터를 사용하고, 표시용 패널과 SwiftUI 트리는 하나만 재사용합니다. 무한·잘못된 크기를 거절하고 실제 데스크톱 안으로 제한하며, 취소한 표시가 다시 나타나거나 이전 정리 작업이 새 표시를 닫지 않도록 보완했습니다. 원본 터미널의 크기는 변경하지 않습니다.

긴 자동화 스크립트는 `osascript -e` 명령줄 인자 대신 표준 입력으로 전달합니다. 시간 초과 후 종료 요청을 무시하는 앱 소유 보조 프로세스도 정리합니다. 기존 자동 승인·일반 질문·원본 입력 검증 규칙은 유지합니다. 오늘 Terminal의 창 크기 조절 중 크래시 기록을 확인했지만 AutoApprove가 원인이라고 확정하거나 이 수정으로 해결됐다고 단정하지 않습니다.

머지된 [PR #8](https://github.com/newdlops/autoapprove/pull/8)을 포함합니다. Mac 관리 창은 화면 밖 상세·질문을 늦게 구성하고, 답변 초안·선택지·전송 중·실패 상태를 세션과 질문별로 보존합니다. 일반 질문은 계속 직접 선택·입력해 전송합니다. 실제 네이티브 창의 1040×700·784×612, 세션 전환·초안·중복 전송 차단·연결 오류/복구를 확인했습니다. UI 속도 비교는 창 가림 유효성 조건에 실패해 개선율을 제시하지 않습니다.

설치 DMG에는 macOS가 제공하는 [읽기 전용 ULFO 압축](https://support.apple.com/en-ie/guide/disk-utility/dskutl11888/mac)을 사용하고, 이미지 내부의 미사용 공간을 줄였습니다.

동일한 서명 앱으로 실제 패키징을 8쌍 교대 비교했습니다. 설치 파일 중앙값은 **7,844,206→7,512,125.5바이트**로 약 **4.2%** 줄었고, 최대 크기는 **8,899,065→7,512,143바이트**였습니다. 새 방식의 미사용 영역은 8개 모두 0바이트였습니다.

전체 패키징 시간 중앙값은 20.755→25.595초, 명령에 보고된 CPU는 0.41→0.62초로 늘었습니다. 미리 정한 시간·CPU·메모리 상한을 통과했으며, 실행 중인 앱의 CPU·메모리나 휴대폰 연결 속도의 개선율은 아닙니다.

16개 이미지 전부에서 전체 앱 파일·서명·실행 권한·설치 안내·Applications 링크가 일치했습니다. 별도로 504KB 스크립트 반복 실행·Unicode 보존·시간 초과 보조 프로세스 정리와 합성 창 12회 표시에서 패널/화면 트리 한 개·잘못된 크기·취소·원본 크기 보존을 확인했습니다. 새 라이브러리 설치나 시스템·보안·권한·VPN 설정 변경은 없습니다.

최종 코어 376/376과 서명 앱의 훅·웹/MCP·입력 번들 검사를 통과했습니다. DMG는 **7,567,565바이트**이며 SHA-256은 `269425a74de1afce0661e919271c65544d5590dc0ee929243357fd411f91a417`입니다. 테두리의 반복·좌표 기능 검사는 통과했지만 추가 실제 테두리 화면 캡처는 검증 도구 연결 오류로 완료하지 못했습니다.

macOS 14 이상 Apple Silicon용이며 빌드는 178입니다. 설치 방법은 [설치 안내](../../README.md#설치)를 참고하세요.
