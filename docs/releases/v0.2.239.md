# 0.2.239 · 다른 Mac의 Codex 서버 첫 준비

이전 계정 창은 관리형 서버에 이미 연결된 Codex를 전제로 했습니다. 같은 CLI 버전이어도 해당 홈에 데몬이 준비되지 않으면 연결을 확인할 수 없었습니다. 일반 PATH 실행으로 프로세스 이름이 `codex`로만 기록되는 경우도 실행 파일의 전체 경로를 요구하는 탐색에서 누락됐습니다.

**계정 아이콘 → 계정·로그인**에서 선택한 홈의 CLI 버전과 관리형 서버 상태를 확인합니다. CLI 미설치·구버전/명령 미지원·서버 미준비·실행 중·확인 불가를 구분하며, 지원되는 미준비 상태에는 **관리형 서버 준비**를 표시합니다. 공식 CLI의 `app-server daemon start`만 사용해 준비하고 새 실행 상태를 확인합니다. 이미 실행 중이면 시작을 반복하지 않으며, 기존 서버 재시작·CLI 자동 업데이트·원격 제어 활성화·자동 실행 등록은 하지 않습니다. 설치·업데이트가 필요한 경우 [공식 Codex 안내](https://developers.openai.com/codex/cli)를 엽니다.

대상 파일이 사라진 이전 소켓 링크가 남으면 같은 버전의 공식 CLI에서도 `File exists`로 시작에 실패할 수 있습니다. 현재 사용자의 링크와 사라진 대상을 확인한 경우에만 링크를 임시 보관하고 시작합니다. 정상 실행 확인 뒤 보관 링크를 정리하며, 실패·취소 시에는 새 소켓을 덮어쓰지 않는 방식으로 원래 링크를 복원합니다. 실제 소켓·일반 파일·소유권이나 상태가 불명확한 항목은 이 정리 대상이 아닙니다.

서버가 실행되는 것과 원래 Codex 세션이 연결되는 것은 별개입니다. 실제 원본 프로세스·TTY·소켓 연결을 확인한 세션만 계정 전환 대상으로 사용합니다. 독립 실행 중인 기존 세션은 새 데몬을 시작하는 것만으로 옮겨지지 않으며, 해당 대화를 일반 Codex 실행으로 다시 연 뒤 **연결 다시 확인**을 눌러야 합니다. 연결 증거가 없으면 재연결 버튼은 계속 비활성화합니다.

PATH 실행은 현재 커널의 실행 파일 경로를 읽어 해결하며, 원본 PID·시작 시각·TTY·사용자와 조회 중 신원 유지를 검증합니다. 작업 폴더나 다른 프로세스의 PATH로 실행 파일을 추측하지 않습니다. 홈 경로·기존 소켓·버전 증거가 불명확하면 시작/전환을 보류합니다.

터미널에서 상태만 진단하려면 `/Applications/AutoApprove.app/Contents/MacOS/autoapprove doctor --codex`를 사용합니다. 다른 홈은 `--codex-home /전체/경로`로 지정합니다. 이 진단은 서버 시작·재시작이나 로그인 변경을 요청하지 않습니다.

Apple Silicon·macOS 14 이상이 대상입니다. 실제 합성 프로세스/PTY/Unix 소켓, 가짜 CLI의 지원·실패 분기와 **자격 증명 없는 임시 HOME에서 공식 Codex 0.166.0의 실제 첫 시작·종료**를 검증했습니다. 사용자가 보고한 다른 Mac에 직접 접속해 확인한 결과는 아닙니다. [검증 기록](../../VALIDATION.md).
