# 0.2.152 · 네트워크 이웃 조회 경량화

주기적인 Mac 탐색에서 `arp -an` 프로세스를 실행하는 대신 같은 읽기 전용 OS 이웃 캐시를 앱 안에서 직접 읽습니다. [Apple의 공개 조회 방식](https://github.com/apple-oss-distributions/network_cmds/blob/main/arp.tproj/arp.c)과 설치된 SDK의 자료형을 확인해 구현했습니다. 정상 조회에서 외부 프로세스와 출력 문자열 해석 비용을 줄입니다.

Wi-Fi·유선 인터페이스와 서브넷 필터, 자기 주소·브로드캐스트 제외, 탐색 순서, 원본 2048행·후보 64개 한도와 조회 주기는 유지합니다. 지원하지 않거나 잘못된 스냅샷은 기존 숫자 주소 전용 읽기 방식으로 돌아갑니다. 빈 캐시는 정상 결과로 처리하며, 바이너리 버퍼는 32MiB, 크기 증가 재시도는 최대 세 번으로 제한합니다.

현재 Mac의 실제 최적화 코어로 이전/수정 방식을 **8쌍 교대·16회** 비교했습니다. 각 프로세스에서 인터페이스와 캐시를 한 번 예열한 뒤 캐시를 네 번 조회했습니다.

| 측정값 중앙값 | 0.2.151 | 0.2.152 |
| --- | ---: | ---: |
| 네 번 조회의 부모·종료 자식 CPU | 69.29ms | 1.13ms |
| 네 번 조회의 소요 시간 | 665.84ms | 1.46ms |
| 비교 프로세스의 최대 RSS | 13,926,400바이트 | 12,328,960바이트 |

모든 조회에서 후보 주소 세 개와 순서가 같았고, 수정본 여덟 회의 종료 자식 CPU는 전부 0초였습니다. 사전에 정한 CPU·시간 60% 이하와 메모리 상한을 통과했으며 모든 표본을 보존했습니다. 캐시 조회 경로의 결과이며 전체 앱 CPU·메모리, 휴대폰 접속, VPN 또는 보안 도구 자체의 속도 개선율은 아닙니다.

경계·오류 처리와 실제 캐시 세 번 대조를 포함한 **41개 확인**, 최종 코어 **376/376 검사**를 통과했습니다. 비동기 완료를 고정 시간 뒤에 단정하던 검사도 완료 상태를 기다리도록 보완했으며, 제품의 복구 간격과 동작은 유지합니다.

Mac 앱 화면과 웹 UI 코드는 0.2.151과 같습니다. 네트워크·보안·권한·VPN 설정, 원본 터미널 크기, 자동 승인·일반 질문·입력 확인 규칙은 변경하지 않습니다. 이번 변경으로 Terminal 크래시가 해결됐다고 주장하지 않습니다.

서명 앱의 Claude 훅·웹/MCP·입력 번들 검사와 DMG 마운트 검증을 통과했습니다. 기존 서명 발행자를 유지했고 DMG는 **7,604,063바이트**, SHA-256은 `0b989df8d3dc02bdaff38e27c995e9e6bff238e78bf3ce97f099ee54a7af163f`입니다.

macOS 14 이상 Apple Silicon용이며 빌드는 179입니다. 설치 방법은 [설치 안내](../../README.md#설치)를 참고하세요.
