# 세션 프로필 저장·복원 신뢰성

사용자는 재실행 뒤에도 저장한 각 Codex·Claude 대화를 같은 폴더와 창·탭 구성으로 이어가야 한다. 최신 대화나 같은 폴더의 유일한 대화를 추측해 선택하지 않는다.

현재 설치본 0.2.282의 ‘업무’ 프로필은 세 항목 모두 대화 ID가 비어 있다. 저장 시 캐시된 표시 제목은 초기 제목이지만 수집된 실제 Terminal customTitle에는 정확한 대화 이름이 있다. 또한 복원 전 활성 세션 수집은 이름 연결을 생략하므로 이미 열린 대화도 식별할 수 없다.

구현 범위:

- 실제 기록의 대화 ID, 검증된 명시적 연결, 서버의 고유한 전체 이름과 실제 탭 제목으로 대화를 식별한다. 실제 탭 제목과 오래된 캐시가 다르면 실제 탭을 우선한다.
- 복원 전에도 같은 식별을 수행하고 활성 대화의 키를 비교해 중복을 방지한다. 조회는 홈·작업 폴더별로 이번 작업 동안만 공유한다.
- 새 CLI 저장은 편집기에서 명시적으로 선택한다. 대화 ID 미확인 상태가 대화 저장 성공처럼 보이지 않게 한다. 이전 파일 형식과 명시적 새 CLI 사용은 유지한다.
- 기존 시스템 서체·색·List·체크박스·Picker를 유지한다. 항목과 저장 결과에서 대화 이어가기/새 CLI의 수를 표시한다. 로딩·실패 원인을 보존한다.

합격 기준:

1. 오래된 캐시 제목과 실제 탭 제목이 다른 수집, 잘못된 홈·중복 이름·명시적 연결 실패·동일 PID의 대화 변경 회귀를 통과한다.
2. 저장 파일 재열기와 정확한 resume 명령, 이미 실행 중인 대화 건너뛰기, 부분 선택·순서·미확인 전달 중복 방지 검사를 통과한다.
3. 새 CLI 선택과 대화 미확인 상태, 긴 이름/경로를 네이티브 앱에서 실제 조작하고 700×480·860×640·1100×800 밝음/어두움 렌더링을 별도로 확인한다.
4. 사용자 프로필은 백업 뒤 정확히 확인된 세 대화를 기록하고 실제 앱에서 세 개 모두 이미 열림으로 판정한다. 기존 대화에는 입력하지 않는다. 실제 새 터미널 복원은 격리된 검증용 대화로 수행한다.
5. 일치하는 소스·빌드·서명·DMG/업데이트 ZIP·체크섬을 배포하고 설치본의 실행 버전과 다운로드를 확인한다.
