# AutoApprove 0.2.180 · build 207

터미널 출력의 비트 스키마 압축과 연결 복구를 개선했습니다. 0.2.179의
다른 Mac 검색 개선을 포함하며, 입력 API와 원본 세션 식별은 유지합니다.

## 전송량과 수신 비용

- 양쪽 Mac이 지원하면 wire v3을 사용합니다. 커서·색상 속성·화면 patch/copy의
  반복 필드 이름을 고정 스키마로 대체하고, 속성의 존재와 참/거짓을 비트로
  묶습니다. 누락·false·true, Unicode, 큰 정수의 정밀도를 구별합니다.
- 같은 합성 데이터의 실제 Core gzip 스트림 비교에서 커서 **4.6%**, 추가
  출력 **9.2%**, 색상 출력 **11.7%**, 조밀한 색상 속성 **64.9%**가 줄었습니다.
  PTY 4종은 전송량을 유지했습니다. 전체 앱이나 실물 네트워크 속도의 개선율은 아닙니다.
- Chromium/WebKit의 합성 수신부 7회 중앙값에서 일반 커서·추가·색상 출력의
  디코딩 시간이 약 **49~61%** 줄었습니다. xterm 그리기·앱 전체 CPU·휴대폰
  네트워크 지연을 측정한 수치는 아닙니다. PTY 수신 비용의 회귀 기준도 통과했습니다.
- 구버전과는 v2/SSE로 통신합니다. 처음 받은 형식이 손상됐거나 지원되지 않으면
  같은 대상에서 v3 → v2 → SSE로 내려갑니다. 일시적인 503은 압축 형식을 유지합니다.

## 연결 복구

- 첫 화면에는 최소 10초를 허용해 느린 초기 응답을 반복 취소하지 않습니다.
  연결이 열린 뒤에는 기존의 빠른 무응답 감지와 보조 화면 조회를 유지합니다.
- PTY 단절은 받은 출력을 모두 그린 위치부터 다시 읽습니다. 이전 연결에서
  대기하던 프레임은 입력 권한을 복원하지 못하며, 새 연결의 확인을 기다립니다.
- 전송 중이거나 대기 중인 입력, 바뀐 Mac 식별자, 권한 거부와 영구 오류는
  자동 복구를 중단합니다. 입력을 자동으로 다시 보내지 않습니다.
- 느린 화면의 출력 큐 상한과 Ctrl C, 종료된 터미널의 마지막 화면을 유지합니다.

## 검증

- 전체 Core **451/451**.
- v3 **3,019프레임·57,422분할·정수 38개·손상 35개**, v2 **630프레임·55,732분할**.
  속성 boolean의 모든 **2,187조합**과 10종의 gzip 전송량을 대조했습니다.
- 실제 Core 소유/중계의 **v3·v2·SSE·gzip·네이티브 화면 patch 7개 경로**,
  중계 버퍼 **39개 검사**에서 정확한 바이트·손상·취소·버전 거부를 확인했습니다.
- Chromium/WebKit 각각 압축 복구 **6개**와 실제 Core 원본 연결 **9개** 상황,
  실제 PTY 브라우저 **15개** 상황을 확인했습니다. 검증용 PTY 출력 폭주도
  512KB/64이벤트 상한 안에서 Ctrl C와 재접속을 유지했습니다.
- 머신 검색 지연 **3/3**, 검색 통합 **8개 그룹**을 통과했습니다. 무응답 주소
  16개 뒤의 머신 **4,166ms**, 같은 LAN의 두 번째 머신 **4,059ms**, 저장 IP의
  새 소유자 **2,594ms**로 기존 5.5초 예산을 유지했습니다. loopback 합성 수치입니다.
- 두 브라우저의 **390×844·768×1024·1440×900** 화면과 오류·복구·초안을
  별도로 확인했습니다. 실물 휴대폰·여러 물리 네트워크의 장기 시험은 별도입니다.
- 기존 발행자 서명, 입력 보조 프로그램, 격리된 설치 앱의 네트워크·PTY,
  DMG 마운트·서명·내용 검사를 통과했습니다.
