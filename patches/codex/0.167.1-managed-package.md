# AutoApprove managed Codex 0.167.1

This is an AutoApprove-maintained build, not an official OpenAI release. It
combines the child Goal pause/resume extension and the subagent approval-dialog
fix. The CLI version remains `0.167.1`; `manifest.json` and the executable hash
identify this build. It requires macOS 14 or later on Apple Silicon and uses
AutoApprove's existing local signing identity. It is not Apple-notarized.

The complete official 0.167.1 runtime package is retained, including the
code-mode host, execution server, ripgrep and voice resources. Only `bin/codex`
is replaced, and the voice manifest's CLI checksum is updated. The manifest records every original runtime file hash, the pinned
official archive hash, both source patches and the resulting executable hash.
The original runtime's notices and additional Rust dependency notices are
included. This archive contains no user configuration, credentials or sessions.

The build uses the upstream commit as its runtime compatibility stamp because
the unchanged voice helper requires the exact matching stamp. This does not
identify the CLI as an unmodified upstream build: both source patches and the
new signed executable digest are recorded separately in `manifest.json`.
The CLI's doctor provenance uses `CODEX_BUILD_COMMIT=autoapprove-managed-1671-1`
to identify the maintained build separately from its runtime compatibility stamp.

For a **new, separate Codex home**, the package's CLI can prepare its daemon:

```sh
CODEX_HOME=/absolute/new/codex-home ./bin/codex app-server daemon start
CODEX_HOME=/absolute/new/codex-home ./bin/codex app-server daemon version
```

An existing daemon continues using its selected package when `start` is called.
Upstream's explicit `app-server daemon update --from-cli` operation selects this
complete package and pins it, but **restarts a running daemon**. Do not use it as
a transparent live upgrade: existing conversations and TUI clients must be
drained and reattached with their state verified. This package does not implement
that migration or switch the login group of an existing session. Its extraction
alone does not change any installed CLI or daemon.

The Goal extension is opt-in at build time and exposed only on experimental RPC
clients. It checks loaded parent/child and Goal identity, permits only active ↔
paused transitions, retains accounting, and uses native continuation on resume.
The normal direct-input restrictions and approval policies remain in place.
AutoApprove 0.2.280 or later supplies the durable action receipt and exact-turn
interrupt needed by the Goal UI.

## Rebuilding the companion

Prepare the pinned source with `prepare-codex-child-goal-control.mjs` and
`--with-approval-fix`. From the prepared `codex-rs` directory:

```sh
MACOSX_DEPLOYMENT_TARGET=14.0 CARGO_INCREMENTAL=0 \
CARGO_PROFILE_RELEASE_DEBUG=0 RUST_MIN_STACK=33554432 \
STABLE_GIT_COMMIT=0a94398fa60c4fac0e7659e4213a0a36e613dd46 \
CODEX_BUILD_COMMIT=autoapprove-managed-1671-1 \
cargo build -p codex-cli --bin codex --release \
  --features codex-app-server/autoapprove-goal-control --locked --jobs 2
```

From the AutoApprove checkout, package the completed binary with the exact
official `rust-v0.167.1` `codex-package-aarch64-apple-darwin.tar.gz` asset:

```sh
node scripts/package-codex-managed.mjs --binary=/absolute/release/codex \
  --source=/absolute/prepared/codex-rs --runtime-archive=/absolute/package.tar.gz
```

The packager requires the existing AutoApprove signing identity, verifies the
20 modified source files and pinned official runtime archive, and refuses an
existing staging directory. It does not install the result or restart a server.
