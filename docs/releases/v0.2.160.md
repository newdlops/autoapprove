# 0.2.160 · 빌드 187

여러 세션의 Git 상태를 수집할 때 같은 저장소의 설정 파일을 반복해서 읽는 비용을 줄였습니다. 최대 네 개 작업자가 폴더를 처리하며 공통 설정은 한 번 수집하는 동안만 공유합니다. HEAD·참조·worktree별 설정은 매번 읽고, Git 실행 후의 독립적인 저장 검증도 유지합니다.

공유한 설정은 수집이 끝나기 전에 원문과 파일 식별자를 다시 확인합니다. 변경이나 읽기 오류가 있으면 해당 폴더를 공유 없이 다시 읽습니다. 취소된 수집은 영향받은 결과를 버리고 재실행하지 않습니다. 공유 상한은 설정 **256KiB·64개**, 설정당 **256개 폴더**이며 동시 로더·상한 초과·특수 파일은 기존 읽기 경로를 사용합니다. 폴링 사이에 새 메타데이터 캐시를 두지 않습니다.

0.2.159의 고정 실행 파일과 같은 합성 작업을 **8쌍·5조건·80회** 교대로 비교했습니다. 조건별 CPU·경과 시간 중앙값과 최대 RSS를 사전 기준으로 판정했습니다.

| 합성 조건 | CPU 변화 | 경과 시간 변화 |
| --- | ---: | ---: |
| 18폴더, 공통 저장소·작은 설정 | −13.2% | −8.3% |
| 18폴더, 공통 저장소·128KiB 설정 | −15.9% | −3.5% |
| 독립 저장소 18개 | −10.3% | −12.5% |
| 독립 worktree 18개 | −5.6% | −5.6% |
| 200폴더·100쌍 | +3.1% | +9.7% |

200폴더 조건의 비용 증가는 남아 있으며 모든 조건의 기존 CPU·지연·최대 메모리 한도는 통과했습니다. 워밍업 후 Git 자식 프로세스 생성은 0이고 세션 연결·순서와 HEAD 변경 확인도 통과했습니다. 이 수치는 Git 수집 경로의 합성 비교이며 앱 전체나 휴대폰 연결의 개선율은 별도 측정이 필요합니다. 단독 작업자 묶음 후보는 두 조건의 CPU 절감 기준을 충족하지 못해 제외했고, 공통 메타데이터 공유를 결합한 이번 후보는 원래 정한 별도 기준으로 새로 비교했습니다.

자동화 초기화·재실행 버튼은 웹 **터미널 설정**과 Mac 세션 상세에서 사용할 수 있습니다. [동작과 보존 범위](v0.2.159.md)는 같습니다.
