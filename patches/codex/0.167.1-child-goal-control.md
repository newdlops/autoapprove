# Managed child Goal lifecycle (source preparation)

This opt-in patch targets upstream Codex **0.167.1**, commit
`0a94398fa60c4fac0e7659e4213a0a36e613dd46`. It is not an OpenAI release and is
not installed by the source preparation command or the current AutoApprove app.
The adjacent manifest pins the upstream archive and all six file pre/postimages.
Upstream license and notice are retained in this directory and source archive.

With Cargo feature `codex-app-server/autoapprove-goal-control`, two experimental
RPCs are available:

- `autoapprove/thread/goal/read`: reads a loaded v2 child under its specified,
  loaded parent. Returns the actual Goal UUID and the public Goal from one row.
- `autoapprove/thread/goal/control`: accepts only active → paused or paused →
  active. The caller supplies the observed Goal UUID, objective, status and token
  budget. They are compared under the native Goal mutation permit, after usage
  accounting flush. Changed identity/configuration and changed runtime reject.

The existing `thread/goal/set`, clear and direct child turn restrictions remain.
There is no Goal creation, objective/budget replacement, cold loading, policy
override or parent mutation. Native accounting and rollout events are retained;
resume uses the existing provider-policy validation and Goal runtime continuation.
This is semantic identity comparison, not a monotonic revision or a replay ledger.
The product controller must reserve user actions durably and never automatically
retry an unconfirmed mutation. A new explicit user action requires a fresh read.

Pausing a Goal disables future Goal continuation. To stop the currently running
turn too, the controller must pause first, then interrupt the exact observed turn
through the existing `turn/interrupt` API and confirm idle. It must not interrupt
a replacement turn or claim that work is stopped from Goal status alone.

Prepare a new tree:

```sh
node scripts/prepare-codex-child-goal-control.mjs \
  --archive=/absolute/codex-0.167.1-source.tar.gz \
  --output=/absolute/new/source
```

The archive is obtained from the pinned upstream commit, not a floating branch.
The command also normalizes the upstream lockfile's 171 local workspace versions
to 0.167.1. External dependency revisions remain pinned. Build the app-server with
`--features autoapprove-goal-control`; for a full CLI use
`--features codex-app-server/autoapprove-goal-control`.

Use `--with-approval-fix` when preparing a full CLI that must also retain the
subagent approval-dialog correction. The preparer independently checks the
14 approval preimages against this 0.167.1 archive, verifies that patch's digest,
and checks all 20 postimages. The default remains the six-file Goal patch.
This option changes no installed executable or running session.

Managed daemons run their selected package, not necessarily the CLI issuing
`daemon start`. A loose CLI binary cannot bootstrap a missing daemon: upstream
requires a complete package with its metadata, code-mode host and `rg`. Starting
an already installed daemon preserves its selected package. Therefore matching
version strings alone do not prove this opt-in feature is present.

For an isolated fresh-daemon check, pass a 0.167.1 package as the helper source:

```sh
node scripts/codex-child-goal-transition-check.mjs \
  --codex=/absolute/modified/full-cli \
  --daemon-package=/absolute/official/0.167.1/package \
  --managed-control --swift-helper=/absolute/compiled/codex-subagent-goal-fixture
```

The checker creates a minimal fixture package in a temporary directory, starts
the real daemon installer in a separate owned home, disables its updater, and
compares the selected executable's SHA-256 to the modified CLI before using the
Goal APIs. The supplied package is only read for fixture helpers. Cleanup stops
only this owned daemon; on a stop failure its home remains available for recovery.
This fixture is not a distributable complete Codex package and does not verify
upgrading a running production daemon or preserving existing TUI clients.

Verified on 2026-11-11: the prepared 0.167.1 app-server compiled with the opt-in
feature, and the real-child checker passed through the compiled Swift transport.
It paused the Goal, interrupted the observed child turn, confirmed idle without
automatic continuation, and resumed a new turn for the same child and Goal.
Goal UUID, objective and budget were retained; usage counters were monotonic;
parent turn IDs were unchanged. Wrong parent and stale Goal identity/configuration
were rejected, as was ordinary direct child Goal mutation. The 0.167.0 prototype's
transition matrix unit test also passed. These are isolated functional checks,
not production installation or UI verification.

The first managed run exposed a checker bug: its notification handler replaced
the turn ID used as the pre-resume reference, so a successful resume could never
satisfy the comparison. The checker now freezes the interrupted turn ID and bounds
RPC/helper waits. The corrected check passed against the completed 0.167.1 build.

```sh
node scripts/codex-child-goal-transition-check.mjs \
  --codex=/absolute/managed/codex-app-server --app-server-binary --managed-control \
  --swift-helper=/absolute/compiled/codex-subagent-goal-fixture
```

The checker uses owned temporary homes, a loopback synthetic model and artificial
Goals; it does not use production credentials or conversations. AutoApprove's
native child rows now expose capability-aware Goal controls with durable request
receipts. Swift pause interrupts only the observed turn and reports confirmed idle
separately from Goal status. Safe server bootstrap, deployment of this native
capability and existing-client migration still remain; an ordinary upstream server
does not gain support merely by updating the AutoApprove UI.
