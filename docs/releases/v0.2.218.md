# 0.2.218 · 다중 탭 복구의 반복 조회 축소

- 새 탭 준비와 셸 준비 확인에서 모든 탭의 TTY를 하나씩 조회하던 처리를 묶음 조회로 바꿉니다. 조회 전후의 창 ID와 결과 구조·중복 TTY를 확인하고, 조작할 탭은 정확한 창 ID와 TTY 조건으로 다시 찾습니다.
- 대화 명령 전달은 정확한 TTY 조건으로 대상 하나만 찾습니다. 마지막 선택 복원도 묶음 목록과 정확한 창·TTY를 사용하며, 빈 셸의 프로세스 목록은 한 번 읽습니다.
- 준비가 늦으면 매번 새 목록을 읽습니다. 창 변경·동시 탭 추가·기존 탭 닫힘·중복 대상·권한 오류에서 중단하며, 기존 네이티브 탭 순서와 같은 묶음 검증·명령 단일 전달은 유지합니다.

이전 0.2.217과 같은 합성 네이티브 창에 프로덕션 스크립트를 실행했습니다. 기존 탭에 새 탭 하나를 추가하는 **준비·확인·명령 전달·마지막 선택**의 스크립트 API 요청 합계입니다. 네이티브 AX 확인과 스크립트 프로세스 시작은 제외합니다.

| 기존 탭 | 0.2.217 | 0.2.218 |
| --- | ---: | ---: |
| 1개 | 43회 | 46회 |
| 20개 | 195회 | 46회 |
| 128개 | 1,059회 | 46회 |

명령과 대상 TTY는 같습니다. 한 탭 조건에서는 구조 검증 때문에 3회 늘고, 많은 탭의 반복 조회는 줄어듭니다. **실제 Terminal 전체 복원의 시간이나 배수 개선을 측정한 결과는 아닙니다.** 실제 Terminal 저장·복원과 추가 UI 검증은 자동 실행하지 않습니다.

관련 탭 **37/37**·세션 프로필 **11/11**을 통과했습니다. 최종 전체 회귀는 **607/608**이며, 남은 1건은 이전 버전과 같은 별도 루프백 주소 재사용 검사의 `NWError 49`입니다. 서명·패키지 검사와 DMG 마운트 검증도 통과했습니다. 공개 배포·로컬 설치 결과는 [검증 기록](../../VALIDATION.md)에 남깁니다. 합성 횟수 검사는 `node scripts/terminal-profile-query-check.mjs`로 재현할 수 있습니다.
