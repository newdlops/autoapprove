# AutoApprove 0.2.181 · build 208

관리 페이지의 목록을 변경 직후 갱신하고, 유휴 전송량을 줄였습니다.
터미널은 새 원본 알림이 오면 직전 화면 캐시를 재사용하지 않습니다.

- 지원하는 Mac에서는 조건부 조회가 변경을 기다립니다. 같은 내용은 본문
  없이 확인하고, 새 내용은 바로 전달합니다. 구버전은 기존 조회를 유지합니다.
- 동일한 합성 Core/Chromium 대조에서 목록 반영은 로컬 **2.1~2.2초**,
  원격 **2.1~4.7초**에서 **23~48ms**로 줄었습니다. WebKit은 **25~52ms**였습니다.
- 유휴 16.5초 구간의 브라우저 조회는 **6→1회**, HTTP 헤더·본문은
  **7,104→1,227바이트(82.7% 감소)**였습니다. 두 버전 모두 유휴 원본 화면
  추가 읽기는 0회였습니다. TCP 부하나 전체 앱 CPU를 측정한 수치는 아닙니다.
- 새 화면·커서·제어 알림은 완료된 화면 캐시의 세대를 바꿉니다. 최종 합성
  알림 검사에서 Core→Node 수신부 도착은 **21~65ms**였습니다. 이 수치는
  브라우저의 화면 그리기를 포함하지 않습니다. 별도의 실제 PTY/Chromium
  입력·출력 왕복 5회는 **181~190ms**였습니다.
  기존 폴링 간격과 진행 중 읽기 공유, wire v3 비트 압축·gzip은 유지합니다.
- 대기 조회는 종류별 최대 8개, 공유하는 원격 조회도 최대 8개입니다.
  수동 새로고침·온라인·화면 복귀는 기존 대기를 교체하고, 숨김·종료 시 해제합니다.
  원격 대기 6초/읽기 예산 7초와 브라우저 대기 15초/요청 예산 20초를 적용합니다.
- 원본 Mac/세션 식별, 입력 권한 재확인, 불확실한 입력의 자동 재전송 금지를 유지합니다.

전체 Core **451/451**, 조건부 대기·취소·동시 제한 **6개**, 코덱
**3,019프레임·57,422분할**, 기존 원본 연결 복구 **9개**와 검색 지연
**3개**, 실제 PTY **15개** 검사를 통과했습니다. Chromium/WebKit의 세 화면 크기와 실제 패키지의
서명·입력 보조 프로그램·네트워크·PTY도 확인했습니다.

위 반영 시간과 감소율은 합성 loopback 검사입니다. 실제 휴대폰·물리 네트워크의
지연과 장기 안정성은 별도 검증 범위입니다.
