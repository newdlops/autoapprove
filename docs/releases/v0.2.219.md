# 0.2.219 · 웹에서 Codex 실제 대화 보기

- 웹에서 Codex 세션을 선택하고 **대화 기록**을 누르면 Codex에 저장된 사용자 메시지·진행 안내·답변을 작성자별로 봅니다. Terminal의 현재 화면이나 보관 출력 대신 읽기 전용 대화 API를 사용하므로 원본 스크롤 위치와 무관합니다.
- 기존 출력 복사는 **터미널 기록**으로 구분합니다. 대화 조회에는 셸 화면·도구 출력·추론 내용·첨부 파일 원문을 포함하지 않습니다. 이미지 첨부는 텍스트 안내로 표시합니다.
- 원래 CLI의 대화 또는 같은 폴더에서 전체 서버 이름이 유일하게 일치하는 대화를 연결합니다. 확정하지 못하면 대화를 직접 선택하며 최신 대화를 임의로 고르지 않습니다. 조회 전후의 프로세스·폴더·대화 검증을 유지합니다.
- **이전 대화 / 최신 기록**, 로딩·빈 기록·오류/재시도·선택/닫기·세션 전환을 지원합니다. 최대 세 구간을 렌더링하고 긴 답변의 작성자를 스크롤 중에도 표시합니다. 개별 메시지는 앞 65,536자까지 표시하며 생략을 안내합니다. 기록을 읽어도 원본 입력·메시지 초안·대기열은 바뀌지 않습니다.

현재 실행 중인 Codex에서 새 Core의 실제 조회와 이전 기록 읽기를 확인했습니다. 본문은 출력·저장하지 않았으며 터미널 화면 읽기·입력은 0회입니다. Codex 로컬 서버의 `thread/items/list` 지원이 필요합니다. 프로토콜은 [OpenAI 공식 app-server 문서](https://learn.chatgpt.com/docs/app-server#api-overview)와 현재 CLI가 생성한 스키마로 확인했습니다.

Chromium·WebKit의 실제 Core 직접/중계 조회, 페이지 이동, 명시적 선택, 초안·오류 복구·빈/로딩/닫기·늦은 응답 격리가 통과했습니다. 각 브라우저에서 390×844·768×1024·1440×900의 light/dark 화면을 생성하고 버튼 크기·페이지 넘침을 검사했으며, 최종 대표 6개 화면을 시각 확인했습니다. 사용자 Terminal 복원이나 실물 휴대폰 검사는 아닙니다.

실제 Unix 클라이언트 통신과 기존 터미널 전체 기록 검사도 통과했습니다. 최종 전체 Core 회귀는 **610/611**이며 남은 1건은 이전 버전과 같은 루프백 주소 재사용 검사의 `NWError 49`입니다. 배포·설치와 상세 결과는 [검증 기록](../../VALIDATION.md)에 남깁니다.
