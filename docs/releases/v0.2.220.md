# 0.2.220 · 세션에서 macOS 권한·확인 요청 응답

웹 관리자에서 Codex·Claude 세션을 선택하고 **OS 권한 정책 → 요청 창 보기·응답**을 엽니다. Mac에 열린 요청의 앱·경로·원문과 실제로 관찰한 허용·거부·설정 열기 버튼을 확인할 수 있습니다. 귀속되지 않은 요청은 **이 요청만 이 세션에 연결**을 누른 뒤 응답합니다. 여러 세션이 공유하는 Terminal·Codex 등의 앱을 임의로 특정 세션에 귀속시키지 않습니다.

선택한 버튼을 원래 macOS 창에 한 번 전달합니다. **자동 승인 OFF에서도 이번 요청에 직접 응답**할 수 있으며 자동 승인 정책은 바꾸지 않습니다. 전체 일시정지·오프라인에서는 응답이 잠깁니다. 창·본문·버튼·요청 앱·세션 프로세스가 바뀌면 전달하지 않고, 결과 미확인이나 앱 재시작에도 같은 요청을 반복하지 않습니다.

이 화면은 감지한 macOS 권한 요청의 텍스트와 버튼을 표시합니다. 손쉬운 사용 권한으로 확인 가능한 지원 OS 요청을 대상으로 하며 전체 화면 영상이나 모든 앱의 임의 대화상자를 복제하지 않습니다. 암호·Touch ID·보호된 인증과 AutoApprove 자체의 권한 설정은 Mac에서 직접 처리합니다. 설정 열기 뒤 시스템 설정의 세부 조작도 기존 정책 또는 Mac에서 처리합니다.

[정식 릴리스](https://github.com/newdlops/autoapprove/releases/tag/v0.2.220)에 DMG·서명된 업데이트 ZIP·각 체크섬을 게시하고 공개 다운로드를 확인했습니다. `/Applications/AutoApprove.app` 설치와 실제 실행 **0.2.220/247**, 기존 세션 **19/19개** 보존 및 설치된 웹 UI 파일 일치도 확인했습니다.

권한 관련 Core **14/14** 검사와 실제 Core 직접/중계 HTTP를 사용하는 Chromium·WebKit 검사를 통과했습니다. 자동 승인 OFF에서 허용/거부·세션 연결·오프라인 복구·창 교체·결과 미확인·보호된 인증, 세 화면 크기와 밝음/어두움 표시를 검증했습니다. 격리 AppKit 창에서 원래 거부 버튼 1회 전달과 오래된 버튼/철회 거부도 확인했으며 실제 OS 권한은 변경하지 않았습니다. 전체 Core는 **613/614**이며 남은 1건은 이전 릴리스와 동일한 루프백 주소 재사용 검사의 `NWError 49`입니다. 상세 빌드·배포·정식 설치 결과는 [검증 기록](../../VALIDATION.md)에 남깁니다.
