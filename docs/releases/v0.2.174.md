# 0.2.174 · 빌드 201

일반 터미널 출력에서 질문·허가 메뉴를 찾기 위한 불필요한 행 정규화를 줄입니다. ScreenAnalysis는 마지막300행에 선택 커서가 붙은 번호 행이나 Codex의 Question 제목이 없다는 것을 먼저 확인합니다. 이 필수 조건이 확실히 없을 때만 메뉴 판별을 생략합니다. 허가·질문·모델 선택 정책은 그대로입니다.

native UTF-8의 CR/LF/CRLF 경계를 뒤에서 읽고 끝의 빈 행을 제외합니다. 일반적인 ASCII 행 시작은 문자열 할당 없이 검사합니다. Unicode·제어문자가 불확실한 행은 기존의 행별 NFC·공백 정리·선택지 정규식으로 확인하고, Cocoa 등 비연속 저장소는 원래 경로를 사용합니다. 새 행/판정 캐시·타이머·서비스는 없습니다.

오류·Goal 이어가기와 활동 판별은 계속 실행합니다. 현재 모델 유지·일반 선택 질문의 수동 처리·코드 블록·현재 요청의 원문 검증·최종 입력 전 확인도 유지합니다.

정식173과 후보의 실제 Core를 같은 합성16세션에 연결했습니다. 새16프로세스·8쌍·512구간을 모두 완료했고 사전17기준과 독립 검토를 통과했습니다. 각 쌍에서8개 ABBA/BAAB 구간 비율의 중앙값을 구한 뒤8쌍의 중앙값을 계산했습니다. 아래는 후보/기존 비율이며 절대 시간 중앙값을 나눈 값이 아닙니다.

사전 기준은 ASCII native 변경 CPU≤0.95배·혼합 native 변경 CPU≤0.90배·native 변경 경과≤1.05배, Cocoa 변경과 비변경 CPU≤1.05배·경과≤1.10배입니다. 최대RSS는 max(기존×1.10,기존+1MiB) 이하입니다. 상태4종·읽기/게시 수·실제 저장 형태를 유지했고, 원본16로그/job·512구간·17기준·403입력·양쪽94Core/추가 연결 객체·실행 파일을 별도로 대조했습니다. 표본 제외·기준 완화·이전 시간 표본 재사용은 없습니다.
