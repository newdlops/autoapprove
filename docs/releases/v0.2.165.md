# 0.2.165 · 빌드 192

명령 stdout/stderr를 전체 Data로 보관한 뒤 String으로 한 번 더 복사하던 경로를 16KiB 청크 디코딩으로 바꿨습니다. stdin까지 한 직렬 이벤트 큐에서 비차단 방식으로 처리하고, UTF-8 문자가 청크 사이에서 잘리면 최대 3바이트만 이어 읽습니다. 작은 응답은 그대로 작게 두고 128KiB 이상에서 정해진 출력 예산을 한 번 예약해 큰 문자열 재할당을 줄입니다. 이 예약은 가상 메모리 용량이며 아래 물리 RSS는 실제 측정값입니다.

기본 상한은 stdout **64MiB**, stderr **8MiB**이며 각각 원문과 디코딩한 UTF-8 크기에 적용됩니다. 호출자는 더 작은 제한을 선택할 수 있습니다. 초과하면 잘린 성공 응답 대신 오류를 반환합니다. 명령 실행 이후의 단일 시간 제한이 자식 종료와 세 파이프를 모두 포함하며, 후손이 파이프를 붙잡아도 무기한 기다리지 않습니다. 정리는 해당 호출이 시작한 직접 자식과 소유 파이프에만 적용하고 입력을 재전송하지 않습니다.

정식 0.2.164와 **새 프로세스 128개 · 8조건 · 각 8쌍**을 교대로 비교한 모든 사전 CPU·wall·RSS 기준이 통과했습니다. CPU/wall은 8회의 중앙값이고 최대 RSS는 8회의 최대값입니다.

| 합성 명령 | 호출자 CPU 합계 ms · 기존 → 새 버전 | wall 합계 ms · 기존 → 새 버전 | 최대 RSS MB · 기존 → 새 버전 |
|---|---:|---:|---:|
| 빈 응답 · 5회 | 7.779 → 5.977 | 1355.482 → 1318.747 | 12.03 → 12.08 |
| stdout 4KiB + stderr 1KiB · 5회 | 9.062 → 8.718 | 1348.155 → 1333.185 | 12.11 → 12.14 |
| Unicode stdin 왕복 · 5회 | 10.067 → 8.712 | 1348.237 → 1327.197 | 12.80 → 12.73 |
| stdout 32MiB · 1회 | 17.091 → 17.881 | 294.564 → 314.790 | 80.92 → 45.66 |
| stderr 8MiB · 1회 | 6.581 → 5.554 | 292.359 → 278.393 | 30.59 → 20.48 |
| stdout/stderr 각각 8MiB · 1회 | 12.941 → 7.872 | 295.142 → 279.394 | 66.67 → 29.21 |

32MiB 단일 출력의 CPU는 약 4.6%, wall은 약 6.9% 증가했으며 고정 10% 허용 범위 안입니다. 메모리 절감과 이 비용을 함께 보고합니다. 파이프를 상속한 후손이 2.4초 뒤 닫는 조건에서 기존은 늦은 성공을 반환했고, 새 버전은 1초 제한 오류를 반환했습니다. 후보 wall 중앙값 **1011.827ms**, 최대 **1118.029ms**로 고정 1.25초 이내였습니다.

동일 합성 C 도구를 실행하는 실제 정식 Core와 후보 Core의 호출자 CPU·wall 중앙값과 프로세스 최대 RSS를 비교했습니다. CPU는 자식 도구 CPU를 포함하지 않습니다. 두 번의 준비 실행과 입력 생성·결과 검증은 CPU/wall 밖이며 RSS에는 포함됩니다. 작은 조건은 5회, 큰 출력은 1회의 합계입니다. 앱 전체·실제 터미널·휴대폰·LAN/VPN의 종합 개선율은 아닙니다.
