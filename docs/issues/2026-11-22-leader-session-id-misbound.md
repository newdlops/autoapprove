## 제목
그룹장 구성원의 대화 ID 가 현재 그룹장 세션으로 갱신되지 않고, 현재 세션은 같은 이름의 하위 구성원으로 따로 등록된다

## 증상
사용자가 그룹장 세션을 새 대화로 이어 간 뒤 그룹 상태를 조회하면, 기존 그룹장 구성원과 실제 그룹장 세션이 서로 다른 구성원으로 등록되어 있다.
조회 결과(`get_session_groups`, `get_group_status`, 2026-11-22 19:28 KST)는 아래와 같다.

| 항목 | 기존 그룹장 구성원 (2AD848B1) | 현재 그룹장 세션 (4371FBA4) |
| --- | --- | --- |
| 제목 | 그룹장 PR 점검과 배포 | 터미널 제목 미확인 |
| messagingName | 그룹장 | 그룹장 (두 구성원의 이름이 같다) |
| conversationID | `76ea2627-c589-4691-87eb-82dca95ec47e` (이전 대화) | `8ff56e58-3799-421b-b713-23a82197966d` (지금 쓰는 대화) |
| isLeader | true | false |
| parentMemberID | 없음 | 2AD848B1 (이 세션의 기존 구성원이 상위 구성원이다) |
| canAssign, canAskQuestion | 해당 없음 | 둘 다 false |
| canReconnect | false | true |
| claudeStatus | busy | busy |
| connectionState | verified | verified |
| 모델 설정 기록 시각 | 2026-11-21 14:07:58Z (하루 전) | 2026-11-22 10:28:32Z (지금) |

- 이전 대화 `76ea2627…` 의 대화 기록 파일은 18:57 이후 바뀌지 않았다. 그런데도 기존 그룹장 구성원은 `connected: true`, `verified`, `busy` 로 나온다.
- 현재 세션은 그룹장이 아니라서 `assign_group_task` 로 구성원에게 일을 맡기지 못한다. 그래서 구성원에게 맡길 일을 지금은 서브에이전트가 처리한다.
- `get_diagnostics` 는 모두 정상이다(권한 ok, "그룹 1개 · 수신 미확인 0건 · 전달이 막힌 구성원 없음"). 진단에는 이 불일치가 드러나지 않는다.

## 경과
1. 그룹장 세션을 다시 시작해 새 대화 ID 를 받은 뒤 `get_session_groups` 가 빈 목록을 돌려줬다(`2026-11-22-leader-session-not-recovered.md`).
2. 사용자가 그룹을 새로 만들었다. 그 뒤 그룹 이름은 "펀드"(`65197975-6856-4222-8BA3-2B2ACD397C9D`)이고 구성원은 13명이다.
3. 지금은 기존 그룹장 구성원이 이전 대화 ID 에 그대로 연결되어 있다. 현재 그룹장 세션은 "터미널 제목 미확인" 이라는 새 하위 구성원으로 등록되었다.

## 원인 추정 (확인하지 못함)
- AutoApprove 가 세션과 구성원을 대조할 때 터미널은 기존 그룹장 구성원과 일치한다고 판단했지만, 대화 ID 는 갱신하지 않고 새 구성원을 만든 것으로 보인다. 근거는 두 가지다. 이전 대화는 30분 넘게 기록이 없는데 기존 그룹장 구성원이 `busy` 로 나오고, 이 상태는 지금 세션이 실행 중인 터미널의 상태와 같다. 두 구성원이 같은 터미널을 가리키는지는 도구 응답에 TTY 가 없어 확인하지 못했다.
- 새 구성원의 상위 구성원이 기존 그룹장 구성원인 것으로 보아, AutoApprove 가 이 세션을 그룹장이 띄운 하위 세션으로 판단했을 수 있다.

## 기대 동작
- 같은 터미널에서 대화 ID 만 바뀌면 기존 그룹장 구성원(2AD848B1)의 conversationID 를 새 값으로 갱신하고, 새 구성원을 만들지 않는다.
- 갱신하지 못했다면 같은 messagingName 을 두 구성원에 주지 않고, `get_diagnostics` 나 그룹 화면에서 "그룹장 구성원의 대화가 응답하지 않음" 처럼 불일치를 알린다.
- 대화 기록이 멈춘 구성원을 `busy`, `verified` 로 표시하지 않는다.

## 복구 방법 (사용자가 화면에서 할 일)
- 세션 그룹 창에서 기존 그룹장 구성원(2AD848B1)의 "새 대화로 교체…" 를 열고 현재 Claude 탭(`8ff56e58…`)을 고른다.
- 교체한 뒤 중복으로 생긴 구성원(4371FBA4, "터미널 제목 미확인")을 그룹에서 뺀다.

## 환경
- AutoApprove 0.2.372(빌드 399, api 1), macOS 26.4(arm64)
- Claude Code CLI, 그룹 "펀드" 구성원 13명(Claude Haiku, Sonnet, Opus, Fable 혼합), 그룹장 2명(2AD848B1, A5AF5E8A)

## 요청
- 대화 ID 가 바뀐 그룹장 세션을 새 구성원으로 만들지 말고 기존 구성원의 대화 ID 를 갱신해 주세요.
- 대화 ID 와 터미널이 서로 맞지 않는 구성원이 생기면 진단과 그룹 화면에 표시해 주세요.
