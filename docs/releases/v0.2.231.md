# 0.2.231 · Codex 로그인 변경 후 작업 순차 중단과 서버 전환

다른 터미널에서 `codex login`으로 계정을 바꿀 때 Codex 창·탭을 모두 닫고 다시 열지 않아도 됩니다.

1. **연결 설정 → Codex → 계정 변경 시 같은 대화로 자동 전환**을 켭니다. 기본은 꺼짐이며 세션의 자동 승인 설정과 독립적입니다.
2. 저장된 로그인 변경을 확인하면 AutoApprove 입력을 억제하고 실행 중인 차례를 정확한 ID로 하나씩 정상 중단합니다. 각 차례의 실제 대기 상태를 확인한 뒤 다음 작업을 중단합니다.
3. 모든 대화와 대기열을 다시 확인한 뒤 공식 관리형 공통 서버를 한 번 전환합니다. 원래 Codex가 같은 창·대화로 재연결하며 작성 중인 입력을 다시 제출하지 않습니다.

중단한 작업은 대기 상태로 유지합니다. 기존 오류 복구가 이를 자동으로 다시 시작하지 않으며, 새 차례가 확인되면 기존 복구 설정을 따릅니다. 전환 취소·앱 재실행·잠시 로그아웃·응답 불명확 상태에서도 동일 명령을 자동으로 반복하지 않습니다.

설정에서 **작업 중단 → 서버 전환 → 대화 연결** 단계와 대화 수·대기 사유를 확인합니다. **현재 로그인 확인**으로 다시 확인하고, 서버 전환 전에는 **나머지 전환 중지**로 추가 처리를 멈출 수 있습니다. 이미 중단한 작업은 자동 재개하지 않습니다.

공식 관리형 로컬 Codex **0.166.0 이상**과 같은 버전의 CLI가 대상입니다. 대기 입력·백그라운드 작업·활성 Goal이나 불완전한 상태가 남으면 전환을 기다립니다. 기존 창의 정확한 대화 연결 증거가 부족하면 **확인 필요**로 남으므로 Mac에서 대화를 확인해주세요. 터미널 키 입력·개별 CLI 종료·새 프롬프트·대화 resume 명령은 사용하지 않습니다.

계정·상태 머신·엔진 회귀 검사 **12개**, 합성 Unix RPC 검사, 밝음/어두움 네이티브 상태 렌더와 실제 합성 설정 창 조작을 확인했습니다. 공식 **0.166.0**의 격리된 임시 CODEX_HOME·쓸 수 없는 합성 계정·소유 PTY **2개**로 공통 서버 전환 뒤 원래 PID·대화 ID·폴더·모델·대기 상태와 새 화면에 다시 그려진 초안의 보존을 확인했습니다. 모델 호출은 **0회**이며 실제 사용자 계정·서버를 바꾸지는 않았습니다.

검사 및 공개 배포·설치 결과는 [검증 기록](../../VALIDATION.md)에 남깁니다.

정식 전체 **630/630**, debug 전체 **649/649**와 패키지 검사가 통과했습니다. 공개 파일 4개의 재다운로드 검증과 정식 설치를 완료했고, 실제 실행 **0.2.231/258** 및 원본 실행 세션 **18/18개** 보존을 확인했습니다.
