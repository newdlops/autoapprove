# 0.2.173 · 빌드 200

승인 선택지의 일반 ASCII 문구에서 불필요한 NFC 변환과 세 번의 정규식 치환을 줄입니다. 모든 처리가 원문을 그대로 남기는 경우만 빠르게 반환합니다. 힌트 괄호·연속 공백·앞뒤 공백·마침표·느낌표·제어문자·비ASCII와 연속 저장소를 사용할 수 없는 문자열은 기존 경로를 사용합니다.

`permissionLabel` 다음의 두 번째 정리는 유지합니다. 중첩 힌트와 구두점에서는 두 번의 결과가 다를 수 있으므로 두 단계를 합치지 않습니다. 현재 요청·세션 허가의 우선순위, 영구 허가·일반 작업 선택 거절, 기존 모델 유지와 원문/요청 검증도 유지합니다. 새 결과 캐시·타이머·서비스는 없습니다.

정식172와 수정한 실제 Core의 합성16세션을 엔진8쌍으로 비교하고, 정리/질문 판별을 별도8쌍으로 비교했습니다. **새32프로세스·832구간·사전28기준이 모두 통과**했습니다. 각 쌍에서8개 ABBA/BAAB 구간의 비율 중앙값을 구한 다음 독립8쌍의 중앙값을 사용합니다. 아래 값은 수정/이전 비율이며 절대 시간 중앙값을 나눈 값이 아닙니다.

실제 Core의 허가/작업 선택 판별 CPU는 약34~49% 줄었습니다. private 정리의 ASCII 절감률은 해당 함수 범위의 결과이며 앱 전체의 개선율이 아닙니다. 비ASCII 정리의 CPU는 약4.4%, 경과 시간은 약1.4% 늘었습니다. 정리/질문 판별 프로세스의 최대RSS는 **14,860,288→14,729,216바이트**였습니다. 모든 결과는 합성 입력 범위이며 실물 휴대폰·네트워크·VPN·보안 도구나 앱 전체의 같은 개선율을 측정한 것은 아닙니다.

사전 기준은 ASCII native 변경 CPU≤0.98배·경과≤1.03배, 다른 엔진 CPU≤1.05배·경과≤1.10배입니다. 정리 함수의 ASCII는 CPU≤0.60배·경과≤0.80배, 비ASCII는≤1.10/1.15배, 공개 허가 메뉴는≤0.85/0.95배, 작업 선택은≤0.90/0.95배입니다. 최대RSS는 각 묶음에서 max(이전×1.10,이전+1MiB) 이하여야 합니다. 원본32로그/종료 상태·832구간·판정/체크섬·읽기/발행/상태 계수와399입력·양쪽94Core객체·추가 연결 객체를 별도로 대조했습니다. 표본 제외·재시도·기준 완화와 이전 후보의 시간 표본 재사용은 없습니다.
