# Native Browser Login Implementation Plan

> Use superpowers:executing-plans inline with one fresh whole-branch review.

**Goal:** Native AutoApprove login opens the normal official browser flow, without requiring device-code enablement or copied codes.
**Architecture:** Native AgentAccountServices.codex launches `codex login` in its existing private PTY, removing forced SSH/headless/browser overrides from the child invocation. Official CLI opens the browser and owns its loopback callback, credential storage and completion. Job parsing explicitly distinguishes native browser challenges from remote device-code challenges. Native settings shows waiting/completed/cancel and an allowlisted reopen button without displaying OAuth query data. Web login retains device authentication and encrypted PIN ownership.
**Tech stack:** Swift/SwiftUI, official Codex0.166.0 CLI, existing AgentAccounts private jobs.

**Acceptance:** One native login button opens the official browser; selected home/executable remain literal; no extra logout or credentials read by AutoApprove; stale or foreign URLs never offered for reopen; no native OAuth challenge leaks to remote owners. Successful native login enables automatic transition for that home without depending on an open settings view. QA uses fake CLI and synthetic accounts, without real login, browser credential entry or production Codex restart.

**Review focus:** Browser child must not inherit forced SSH/device-auth behavior; web device flow unchanged; strict official OAuth client/PKCE/loopback URL validation and duplicates rejected; long OAuth query never rendered; shared exclusion/cancellation/privacy unchanged.

**User extension:** Successful native login must apply to every open Codex connected to that login's common server, even with settings closed. Current read-only discovery found one home and five connected Codex processes. The engine owns the completion callback, enables/persists automatic transitions, wakes a parked poller immediately and owns cancellable checks for both manual and automatic entry points. Queued callbacks revalidate manager identity, epoch and stop state. No view owns the effect.

**Stop sequence:** Reserve each original thread durably before any mutation. Revalidate its server and turn, pause only a still-active Goal with automatic origin, terminate its exact Codex background process IDs through official APIs, then normally interrupt a still-running turn. A completed Goal is never changed to paused. Queued messages are preserved and remain a restart barrier after work stops. Cancellation retains the reservation and prevents subsequent effects; uncertain partial delivery requires review rather than replay.

**Reconnect proof:** Official0.166.0 TUIs retain their in-memory thread IDs while the daemon owns rollout files. Verify every original PID/start/TTY and its reciprocal kernel socket handles to the current daemon PID. Read every original conversation's retained history without forcing it to load; require idle or notLoaded. Currently loaded threads must be a subset of the originals with no foreign, active or blocked thread. Check the new server account and repeat the final fresh identity/account/state barrier. No per-TUI rollout descriptor or fabricated per-TUI conversation binding is required, and offscreen conversations are not forcibly attached. Never copy credentials across separate homes. AutoApprove sends no new prompt/resume; already queued TUI input follows Codex's own behavior.

**Evidence:** Initial native-login RED4/7 and all-session RED12/15 reproduced the browser invocation/parser, missing-rollout rejection, stale reconnect completion and settings-view dependency. Fresh independent reviews covered the browser branch, expanded all-session path and new quiescence subsystem. Important callback replacement, queue masking, completed-Goal and stop-between-effects races each failed a focused test before fixes; the parked poller wake also has RED/GREEN evidence. Final focused transition checks pass21/21 and login checks7/7. Unix RPC tests cover exact official mutations, combined queue/work barriers, pagination and error/cancellation races. An isolated official0.166.0 lifecycle with two owned TUIs retained original PIDs/thread IDs/cwd/model/idle and unsent drafts after fresh repaint, confirmed the new server account and made zero model POSTs. Reciprocal-peer tests reject a live old daemon socket after pathname reuse. Real user servers were not restarted for QA.
