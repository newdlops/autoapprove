# Codex 0.167.0 subagent approval hotfix

This AutoApprove-maintained patch fixes the Codex TUI that displays approvals.
It is not an official OpenAI Codex release. AutoApprove's server approval client
and the Codex app-server approval policy are separate from this TUI correction.

Upstream: `rust-v0.167.0`, commit `086ccc833bc9cf01024ad2dd6af7dbd421b6bf9a`.
The adjacent manifest pins the source archive, patch, and every changed file.

The original TUI removes an externally resolved child request from its pending
map, but dismisses a visible approval only when the displayed thread equals the
request's thread. After visiting a subagent and returning to the parent, the
child's dialog survives automatic approval. Clicking it then emits
`Not available in TUI yet for thread …` even after the child command has finished.

The patch dismisses command, file, permission and MCP dialogs by their request
identity across parent/child views. MCP identities now also contain the thread
so a colliding request on another thread is preserved. Ordinary user questions
retain their existing thread restriction. A bounded cache of 256 resolved
identities consumes late approval clicks without another RPC. Unknown operations
still follow the original error handling. Human verification and approval
policies are not bypassed or automatically answered by the TUI patch.

Prepare from the exact official source archive:

```sh
node scripts/prepare-codex-subagent-approval-fix.mjs \
  --archive=/absolute/rust-v0.167.0.tar.gz --output=/new/isolated/source
```

The official source has 171 local workspace lock entries still marked `0.0.0`.
Preparation updates only those local version fields to `0.167.0` and leaves all
external dependency versions unchanged. Build with the upstream Rust toolchain
and macOS 14 deployment target. The local validation used Rust 1.96.0, disabled
incremental/debug information, and `--locked`.

```sh
MACOSX_DEPLOYMENT_TARGET=14.0 CARGO_INCREMENTAL=0 \
CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 RUST_MIN_STACK=33554432 \
cargo test -p codex-tui --lib autoapprove_ --locked --jobs 2
MACOSX_DEPLOYMENT_TARGET=14.0 CARGO_INCREMENTAL=0 CARGO_PROFILE_RELEASE_DEBUG=0 \
STABLE_GIT_COMMIT=autoapprove-subagent-fix-1 \
cargo build -p codex-cli --bin codex --release --locked --jobs 6
```

The recorded local build materialized the exact pinned V8 Git commit
`350c5a859a9b3c84ab8701b3ad51e3b7699b30c0` with `git archive` and used that local
path for the existing V8 patch. This avoided fetching Chromium submodules that
these CLI/TUI targets do not compile. The V8 Rust source was unchanged; its lock
entry became a local path entry, with all external versions preserved.

`scripts/codex-subagent-live-check.mjs` creates an isolated home, loopback-only
model fixture, real Codex server, real spawned child, and optional TUI in a PTY.
It invokes the production Swift approval implementation and checks actual
command output and child turn completion. The TUI case visits the child and
returns to the parent before allowing the approval to arrive. Use
`--expect-stale-tui` only for the unmodified baseline. `--screen` saves only the
owned fixture's terminal text. No existing user session or credential is used.

The companion package installer requires an explicit native binary path and
matches the exact original/patched SHA-256. It preserves a verified backup and
replaces the executable atomically. `--restore` restores that backup. It does
not terminate an existing TUI or daemon; an already running TUI must be reopened
to load the fixed code. A later official Codex update can replace this hotfix.

The macOS 14+ arm64 companion ZIP includes `bin/codex`, `install.mjs`, a pinned
manifest, source patch, and license notices. It uses AutoApprove's existing
local code-signing identity and is not Apple-notarized. From the extracted package:

```sh
node install.mjs --target=/absolute/path/to/existing/native/codex
# Restore the verified original if needed:
node install.mjs --target=/absolute/path/to/existing/native/codex --restore
```

Use the native executable in the npm platform package, not the JavaScript entry
point or a shell shim. This installer accepts only the pinned official macOS
arm64 0.167.0 executable or this exact patched build.
The CLI version string stays `0.167.0` for protocol compatibility; the package
manifest and executable SHA-256 identify this AutoApprove-maintained build.
