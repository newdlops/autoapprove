# AutoApprove

macOS Terminal·iTerm2·Orca·tmux와 VS Code 통합 터미널의 Claude Code·Codex 세션을 관리하는 로컬 앱입니다. 메뉴 막대와 관리 창에서 세션별 자동 승인, 전체 일시정지, 승인 내역, 원래 터미널로 이동을 제공합니다. 휴대폰 브라우저에서도 Mac의 같은 터미널 화면을 보고 입력할 수 있습니다.

**보기 전용 화면 공유와 세션 테스트 지시 · 0.2.51 빌드 62:** 휴대폰의 **화면 공유**를 누르면 선택한 Mac 화면을 바로 봅니다. **세션에 테스트 지시**로 같은 Codex·Claude Code의 질문·메시지 창을 열고, 지시를 보낸 뒤 닫으면 같은 공유 화면으로 돌아갑니다. 직접 선택한 Codex 대화는 대기 입력 관리와 새 메시지에 함께 적용합니다.

**웹 응답 전송·Codex 대기 입력·바로 화면 공유 · 0.2.50 빌드 61:** 질문 편집 상태를 확인하는 중에도 선택한 답변을 보내면 한 번만 전달하며, 실패 이유를 질문 안에 표시합니다. **질문·메시지 → 대기 입력**에서 Codex의 실제 후속 입력 목록을 확인하고 비울 수 있습니다. **테스트 화면**을 누르면 선택한 Mac의 전체 화면 공유를 시작하거나 이미 MCP로 공유한 화면을 바로 엽니다. 휴대폰 설치나 별도 서비스는 필요 없습니다.

**여러 Mac의 입력 연결 유지 · 0.2.49 빌드 60:** Mac 목록 조회 중 한 Mac의 응답이 늦으면 살아 있는 원본 터미널의 연결과 모바일 키보드까지 닫히던 문제를 수정했습니다. 선택한 원본의 실시간 화면 연결을 유지하며, 최신 화면이 확인된 뒤 입력합니다. 온라인 목록에서 확인된 세션 종료·권한 거부·입력 대상 변경은 계속 입력을 멈춥니다. 0.2.47–0.2.48의 자동 복구와 감시 오류 분리도 포함합니다.

**웹 터미널 입력 연결 안정화 · 0.2.47 빌드 58:** 일시적인 핫스팟 연결 끊김과 무응답 화면 스트림을 같은 원본 세션으로 자동 재연결합니다. 기기 목록 조회 오류가 정상 터미널을 끊지 않으며, 복구 중에도 키보드 포커스·한글 조합·미전송 입력을 유지합니다. 같은 원본 연결을 확인한 후 미전송 키를 순서대로 전달하고, 접수 결과가 불확실한 입력은 자동 재전송하지 않습니다. Mac과 휴대폰의 시계 차이도 입력을 막지 않습니다.

**휴대폰 질문·메시지와 테스트 화면 MCP · 0.2.46 빌드 57:** 터미널의 **질문·메시지**에서 여러 질문의 선택지와 직접 답변을 입력하고 같은 대화에 새 메시지를 보냅니다. Claude의 연결된 `AskUserQuestion`은 단일·복수 선택을 원래 훅으로 반환하며, Codex 질문과 새 메시지는 검증된 같은 대화의 메시지 대기열로 전달합니다. Codex·Claude가 로컬 MCP로 질문을 게시하거나 필요할 때 **Mac 전체 테스트 화면**을 공유할 수도 있습니다. 휴대폰에는 설치가 필요 없습니다. 0.2.45의 동시 질문·줄바꿈 자동 승인 복구를 포함합니다.

## 개인 핫스팟에서 휴대폰으로 관리

같은 네트워크의 여러 Mac을 휴대폰 브라우저 하나로 관리할 수 있습니다. **연결 코드나 로그인 없이** 사용하며, 각 Mac이 자기 웹페이지를 게시하고 다른 AutoApprove를 자동으로 찾아 목록을 구성합니다. 처음 실행할 때 자동으로 시작하며, 사용자가 직접 끈 설정은 재실행 후에도 유지합니다.

**0.2.39부터 최신 웹 화면을 우선 엽니다.** 숫자 IP 즐겨찾기나 공용 이름으로 새로 접속하면, 발견된 온라인 Mac의 호환되는 안정 버전·빌드를 비교하고 더 최신인 Mac으로 연결합니다. 최신 Mac이 응답하지 않으면 다음 버전이나 접속한 Mac의 화면을 엽니다. 터미널 세션 링크는 유지합니다. 이미 사용 중인 화면은 입력을 보존하고 ‘최신 화면 열기’로 새 탭을 엽니다. 공용 이름을 맡은 Mac도 더 최신인 기본 포트 Mac에 양보합니다. 이 기능이 없는 구버전은 동작을 자동으로 바꿀 수 없으므로 **즐겨찾기 주소를 제공하는 Mac을 포함해 각 Mac을 한 번 0.2.39 이상으로 업데이트하고 휴대폰에서 새로고침하세요.**

1. 같은 핫스팟에 연결한 각 Mac에서 AutoApprove를 실행합니다. macOS가 로컬 네트워크 접근을 요청하면 허용합니다. 이전에 웹 접속을 꺼둔 Mac은 **연결 설정 → 같은 네트워크에서 웹 접속**을 다시 켭니다.
2. 어느 Mac이든 연결 설정의 **휴대폰으로 공유**로 접속 링크를 전달해 엽니다. 휴대폰에는 앱·프로필 설치나 DNS 설정이 필요 없습니다. 처음 연 링크를 즐겨찾기에 저장하면 같은 주소에서 다시 접속할 수 있습니다. QR도 사용할 수 있습니다. 주소가 여러 개이면 휴대폰과 같은 네트워크의 주소를 선택하세요.
3. Mac들이 서로 자동 발견됩니다. 하나의 주소에서 모든 세션을 검색하고, Mac별 일시정지·재개와 세션별 자동 승인을 조절합니다.
4. 휴대폰에서 Codex·Claude 세션을 선택하면 터미널이 화면을 채웁니다. **0.2.42부터 Mac에서 실행 중인 원본 세션을 그대로 연결합니다.** Mac과 웹에서 같은 PID·TTY·실행 상태를 공유하고, 선택·새로고침·재시도로 대화를 복제하거나 새 PTY를 만들지 않습니다. 지원되는 문자·Enter·방향키·Backspace·Tab·Ctrl C를 같은 터미널로 전달합니다. **질문·메시지**에서 선택지·직접 답변·새 메시지를 입력하고 **상세 보기**에서 자동 승인·처리 내역을 봅니다. 자동 승인 ON에서도 입력하며 승인과 사용자 입력을 순서대로 전달합니다.

## 휴대폰 질문·메시지와 테스트 화면 MCP

터미널 하단의 **질문·메시지**를 열면 여러 질문을 각각 읽고 선택한 뒤 **답변 보내기**로 제출합니다. 선택지만 누르는 동작은 전송하지 않습니다. 새 질문이나 상태 갱신이 도착해도 현재 탭의 초안과 선택을 유지합니다. Codex 질문 또는 자동 응답 가능한 Claude 질문의 선택·입력을 시작하면 그 질문의 자동 응답을 멈추며, 세션의 자동 승인 설정은 유지합니다.

0.2.50부터 자동 응답을 멈추는 편집 요청이 느려도 보내기 버튼을 막지 않습니다. 보낸 응답은 편집 요청 확인 뒤 한 번만 전달합니다. 전송 실패는 질문 바로 아래에 표시하고 선택·추가 설명을 보관합니다. 결과가 불확실한 답변은 자동으로 재전송하지 않습니다.

Claude는 연결된 동기 훅의 `AskUserQuestion`을 웹 폼으로 표시합니다. 각 질문의 단일·복수 선택과 추가 설명을 원래 `questions`를 보존한 `answers`로 돌려줍니다. 이 답변에는 방향키나 텍스트 키 입력을 주입하지 않습니다. 이미 이전 훅이 반환됐거나 지원하지 않는 화면 질문은 **터미널에서 답하기**로 원본을 확인합니다. Codex의 기록에서 감지한 질문은 기존 메시지 대기열 응답 경로를 사용합니다.

**새 메시지**는 선택한 원본 세션에 보냅니다. Codex는 작업 중·대기 중에도 같은 대화의 메시지 대기열에 등록하며, 접수와 즉시 실행을 구분해 표시합니다. 다른 CLI는 현재 원본 입력 연결을 사용하고, 터미널 질문을 처리 중이면 먼저 질문에 답하도록 안내합니다. 작성 전송이 없는 원본 연결은 한 줄 메시지만 지원합니다. 전달 결과를 확인하지 못한 메시지는 자동 재전송하지 않으며 원본을 확인한 뒤 **새 메시지 작성**으로 다음 입력을 시작합니다.

**대기 입력**은 Codex의 `queued follow-up inputs`입니다. **목록 갱신 → 대기 입력 비우기 → 삭제**로 현재 목록에서 아직 처리하지 않은 입력만 삭제합니다. 한 번에 최대 100개를 삭제하며, 새로 들어온 입력과 실행 중인 작업·원본 PID·TTY·자동 승인 설정은 유지합니다. 삭제한 항목이 질문의 답변이면 그 답변 전달도 취소 상태로 바꾸고 다시 답변할 수 있게 합니다. Codex의 공식 로컬 서버 `thread/queue/list`·`thread/queue/delete`를 사용하며 대화 기록 DB를 수정하지 않습니다. 이 기능은 해당 Mac의 AutoApprove 0.2.50 이상과 대기열 API를 제공하는 실행 중인 Codex 서버가 필요합니다. 서버가 없거나 지원하지 않으면 이유를 표시하며 새 서버·CLI·PTY를 실행하지 않습니다.

대화 기록 파일을 직접 열지 않는 최신 Codex에서는 **Codex 대화 연결**을 눌러 같은 작업 폴더의 실행 중인 대화를 선택한 뒤 **이 대화로 연결**을 누릅니다. 공개 서버의 상태에서만 대화 목록을 읽고, 선택한 대화 ID·실행 상태·폴더를 조회/삭제/메시지 전송 전에 확인합니다. 폴더나 최신 기록만 보고 대화를 자동 선택하지 않습니다. 0.2.51부터 이 선택은 대기 입력 관리와 새 메시지에 적용하며, 원본 터미널의 직접 키 입력 대상은 바꾸지 않습니다. 연결한 대화 이름은 메시지 입력 아래에 표시합니다.

**화면 공유** 버튼은 선택한 Mac의 공유를 바로 엽니다. 이미 MCP가 게시한 공유가 있으면 이를 사용하고, 없으면 전체 디스플레이를 10분 동안 공유합니다. 휴대폰의 공유 화면은 보기 전용이며 확대는 휴대폰에만 적용됩니다. **세션에 테스트 지시**로 같은 원본 Codex·Claude Code에 자동 테스트 명령을 보내고, 질문·메시지 창을 닫으면 공유 화면으로 돌아와 결과를 봅니다. 세션이 끝나거나 선택이 바뀌면 지시 버튼을 비활성화합니다. 세션을 선택하지 않은 MCP 링크는 화면만 표시합니다. **공유 종료**는 즉시 접근을 종료합니다. 보기 창 닫기·브라우저 숨김은 이미지 요청을 멈춥니다. 버튼 시작은 해당 Mac의 AutoApprove 0.2.50 이상, 직접 선택한 Codex 대화로 메시지 전송은 0.2.51 이상에서 지원합니다. macOS의 화면 녹음 권한은 Mac에서 허용해야 합니다. 일반 터미널 모드와 목록 갱신은 화면을 캡처하지 않습니다.

Mac에 앱을 설치한 뒤 다음 명령으로 로컬 MCP를 등록합니다. 등록은 실행 중인 대화를 재시작하지 않으며, 다음 Codex·Claude 실행 또는 클라이언트의 MCP 재연결부터 도구를 사용할 수 있습니다. 이미 열린 세션의 도구 목록을 강제로 바꾸지 않습니다.

```sh
codex mcp add autoapprove -- /Applications/AutoApprove.app/Contents/MacOS/autoapprove mcp
claude mcp add --transport stdio --scope user autoapprove -- /Applications/AutoApprove.app/Contents/MacOS/autoapprove mcp
```

| MCP 도구 | 사용 방법 |
| --- | --- |
| `ask_user` | 1~8개 질문과 선택지·복수 선택 여부를 웹에 게시하고 `requestID`·접속 링크를 반환합니다. |
| `get_user_answers` | 같은 MCP 연결이 게시한 질문의 상태와 사용자가 보낸 답변을 조회합니다. `waiting`·만료는 답변으로 처리하지 않습니다. |
| `list_screens` | 현재 공유 가능한 Mac 전체 화면·창 ID를 조회합니다. 캡처는 시작하지 않습니다. |
| `start_screen_share` | 사용자가 화면을 보고 싶어 할 때만 호출합니다. 기본은 Mac 전체 화면, 기본 10분·최대 15분이며 `scope: "window"`와 `sourceID`로 창 하나를 지정할 수 있습니다. |
| `stop_screen_share` | 이 연결이 시작한 공유를 종료하고 메모리에 보관한 이미지를 폐기합니다. |

예: “테스트할 화면을 AutoApprove MCP로 휴대폰에 공유해줘.” 웹의 **화면 공유**를 한 번 누르면 공유 화면이 바로 열립니다. Mac의 화면 녹음 권한이 필요하며, 전체 화면에는 다른 앱도 포함됩니다. 공유 시작만으로 이미지를 찍지 않고, 휴대폰이 화면을 열어 볼 때만 JPEG를 요청합니다. 브라우저에서 닫거나 숨기면 요청을 멈춥니다. **공유 종료**, 만료, MCP 연결의 정상 종료, 웹 접속 끄기 또는 앱 종료는 공유를 해제합니다. 기본 터미널은 계속 텍스트·ANSI 중계를 사용하며 화면 공유는 원본 PID·TTY를 바꾸지 않습니다. 화면 이미지는 파일로 저장하지 않습니다.

MCP는 Mac의 기존 앱과 로컬 소켓으로 통신하고 휴대폰은 기존 핫스팟 웹만 사용합니다. 외부 중계 서비스를 사용하지 않습니다. [Codex MCP 설정](https://learn.chatgpt.com/docs/extend/mcp), [Claude MCP 설정](https://code.claude.com/docs/en/mcp), [Claude 질문 훅](https://code.claude.com/docs/en/hooks).

**원본 동기화 · 0.2.43:** 기본은 SSH처럼 같은 원본 터미널의 출력과 키 입력을 SSE로 중계합니다. 화면 이미지를 캡처하거나 보내지 않으며 화면 녹음 권한도 필요 없습니다. Terminal·iTerm2는 기존 텍스트, Orca는 기존 PTY의 ANSI 셀·커서, VS Code 계열은 Bridge 0.2.8이 연결한 원본 ANSI 출력·커서를 제공합니다. 앱 재접속 중에도 VS Code 출력 읽기를 유지합니다. 출력 연결 전부터 실행된 명령은 지난 ANSI를 읽을 수 없다는 이유를 표시하고 같은 기존 터미널에 입력합니다.

실제 Mac 창을 보고 싶을 때만 **화면 설정 → Mac 창 보기**를 켭니다. Terminal·iTerm2와 확인된 VS Code 계열 창의 색상·커서를 표시하며 같은 창의 분할 영역과 주변 UI도 포함합니다. 끄기·새로고침·다른 세션 선택·브라우저 숨김은 이미지 전송을 중단하고 기본 터미널로 돌아갑니다. 보기 전환은 PID·TTY·입력 연결을 바꾸거나 새 PTY를 만들지 않습니다. **원본 터미널 연결**은 같은 기존 탭을 확인하며 Mac 창 보기가 켜졌을 때만 화면 녹음 권한을 요청합니다. VS Code 계열은 **편집기 확장 설치**로 업데이트하세요. 휴대폰에는 설치가 필요 없습니다. 구형 Mac은 기존 조건부 조회를 유지하며 선택형 이미지 모드는 0.2.43 빌드 51 이상에서 지원합니다.

**빌드 54의 Terminal 직접 입력 설정:** Mac의 **연결 설정 → 원본 터미널 화면·입력 → 직접 입력 연결**을 사용합니다. 정상 연결된 기존 서비스는 재설치하거나 종료하지 않습니다. 새 연결은 앱 내부의 서비스 정보를 Apple `SMAppService`로 등록하고 **시스템 설정 → 일반 → 로그인 항목 및 확장 프로그램**에서 AutoApprove의 백그라운드 실행을 허용합니다. 관리자 셸로 서비스 파일을 복사하는 이전 설치 경로는 제거했습니다. 새 등록에는 Developer ID로 서명하고 Apple 공증을 받은 앱이 필요하며, 현재 자체 서명 후보에서는 기존 연결을 확인하고 유지할 수 있습니다. 보안 경고 이력 삭제나 EDR 무탐지를 보장하지 않습니다. [Apple 서비스 등록 안내](https://developer.apple.com/documentation/servicemanagement/smappservice).

**무료 tmux 공유 · 0.2.44 빌드 55:** 유료 Apple 개발자 계정이나 관리자 입력 서비스 없이 Mac과 휴대폰이 **같은 tmux 창의 원본 색상·커서·입력**을 공유합니다. tmux의 control mode에서 출력 변경을 받아 SSE로 전달하고, 키 입력도 계속 연결된 같은 창으로 보냅니다. 웹 접속·재시도·연결 해제는 새 PTY나 대화를 만들지 않으며 Mac 창 크기를 바꾸지 않습니다. 자동 승인 ON에서도 직접 입력할 수 있습니다.

공유할 **각 Mac에 tmux를 설치**하고, 공유 대상 CLI를 tmux 안에서 실행합니다. **휴대폰에는 설치하지 않습니다.** Homebrew를 사용하는 Mac은 `brew install tmux`로 설치하고 `tmux -V`로 확인합니다. Mac의 **연결 설정 → tmux로 같은 터미널 공유 → 시작 명령 복사**를 사용하거나 아래 명령을 실행한 뒤 그 안에서 Codex 또는 Claude를 시작하세요. 이미 tmux 안에서 실행 중이면 **연결 확인**만 하면 됩니다.

```sh
tmux new-session -A -s autoapprove
```

이미 tmux 밖에서 실행 중인 CLI는 그대로 유지합니다. tmux 설치만으로 기존 작업을 이전할 수는 없습니다. 기존 대화를 tmux 안에서 이어가려면 사용자가 해당 CLI의 이어하기 기능을 선택해야 합니다. 다른 창에도 입력하는 `synchronize-panes`가 켜져 있거나 tmux가 복사 모드이면 입력을 거부하고 원본 상태를 확인하도록 안내합니다. tmux 3.7c와 격리한 실제 창에서 검증했으며 원본 앱의 사용자 지정 16색 팔레트는 제공되지 않아 기본 팔레트를 사용합니다. [tmux 공식 설치 안내](https://github.com/tmux/tmux/wiki/Installing), [control mode](https://github.com/tmux/tmux/wiki/Control-Mode).

**새 터미널**은 별도의 독립 터미널이 필요할 때만 사용합니다. Mac·폴더·셸/Codex/Claude Code를 선택해 만들고, 화면이나 **키보드**를 눌러 입력합니다. 원본 ANSI·실제 커서·대체 화면을 표시하고 화면 키보드의 크기를 PTY의 열·행에 반영합니다. 브라우저를 닫아도 프로세스를 유지하고, 새로고침하면 같은 PTY의 현재 화면을 복원합니다. 다른 브라우저가 최근 입력 중이면 입력 차례를 기다리며, 결과 미확인 입력은 재전송하지 않습니다. **화면 설정 → PTY 종료** 또는 Mac 앱 종료는 앱이 만든 PTY의 작업을 종료합니다. 독립 PTY에는 손쉬운 사용 권한이 필요 없으며 자동 승인은 CLI 감지 후 적용하고 기본으로 꺼져 있습니다.

종료한 PTY는 실행 중 목록과 세션 수에서 즉시 빠지고, 열어둔 화면에는 마지막 출력과 종료 코드를 유지합니다. 새로고침해도 닫힌 PTY를 자동 재실행하지 않습니다. Mac의 원본 세션을 선택하면 그 원본에 연결합니다.

화면이나 **키보드**를 눌러 문자·완성된 한글과 Enter·Esc·Ctrl C·방향키·Backspace·Tab을 지원되는 원본에 전달합니다. 이미지 연결은 Mac이 실제로 그린 커서를 표시하고, Orca·VS Code의 ANSI 연결은 소유 터미널이 제공한 위치·모양·숨김을 사용합니다. **빌드 53의 Terminal 직접 입력은 기존 TTY에 바이트를 전달합니다.** 손쉬운 사용이나 선택 창에 의존하지 않으며 새 CLI를 만들지 않습니다. Mac에 설치한 보조 서비스는 같은 발행자로 서명된 앱·CLI만 받아 원본 PID·정밀한 시작 시각·TTY·전경 작업을 확인합니다. 원본 CLI가 직접 입력을 받는 모드여야 하며 전달한 입력을 자동 재전송하지 않습니다. Terminal 출력 읽기는 기존 자동화 권한을 사용합니다. 연결이 없으면 Mac 설정 안내를 표시하며 작성창을 자동으로 열지 않습니다. 작성 모드를 선택한 경우, 작성 전송이 없는 원본 연결의 내용은 초안으로 보관하고 전송을 비활성화합니다. 자동 승인 ON에서도 같은 원본에 직접 입력할 수 있습니다. 실제 관리자 서비스·원본 입력 검증 여부는 [VALIDATION.md](VALIDATION.md)에서 확인하세요.

**화면 설정**에서 글자 크기·줄바꿈·원본 색상·아래로 따라가기를 조절합니다. **작성 후 Enter 전송**을 선택하면 작성 입력창을 열고, Enter로 텍스트와 Return을 함께 보냅니다. 이 작성 모드에서 Shift Enter는 줄바꿈입니다. 직접 입력 모드의 Shift Enter는 Return이며, Tab은 터미널로 보내고 Shift Tab으로 포커스를 벗어납니다. 키보드 크기에 맞춰 터미널 높이를 바꾸며 전송 중에도 키보드·초안·스크롤·선택을 유지합니다. 단일 줄 붙여넣기는 바로 전달하고 여러 줄은 작성 입력에 보존해 확인 후 Enter로 보냅니다. 연결 끊김·세션 변경·전달 결과 미확인 때 직접 입력을 멈추고 미전송 문자를 원래 세션의 작성 영역에 순서대로 보존하며 자동 재전송하지 않습니다.

기존 터미널의 화면 중계에는 Mac에서 해당 터미널의 화면 연결이 필요하며, 훅만 연결된 세션은 화면 연결 안내와 지원되는 질문 응답을 제공합니다. 웹페이지를 닫거나 웹 접속을 꺼도 Mac의 원본 터미널은 계속 실행됩니다.

**VPN·Zscaler와 함께 사용:** 접속 주소와 자동 탐색은 실제 Wi-Fi·유선 LAN을 기준으로 하며 Wi-Fi 주소를 우선 표시합니다. VPN의 `utun`·`ipsec` 주소는 제외합니다. Mac 사이의 IPv4 통신에는 해당 LAN의 출발 주소와 인터페이스 종류를 지정하고, 현재 LAN 밖의 이전 IP에는 연결하지 않습니다. VPN·시스템 라우트 설정은 변경하지 않습니다. Zscaler 정책이 LAN을 차단하면 관리자가 핫스팟 내 AutoApprove의 TCP 접속을 허용해야 합니다. 기본 포트는 8765이며 앱에 표시된 실제 포트를 기준으로 합니다. 이름 자동 검색에는 UDP 5353도 사용하지만 직접 IP 탐색으로 보완합니다. [Zscaler의 macOS LAN·방화벽 설정](https://help.zscaler.com/client-connector/blocking-lan-access).

외부 도메인·주소 등록·중계 서비스는 사용하지 않습니다. 순수 핫스팟에서 처음 접속할 때는 Mac의 링크를 한 번 전달해야 하며, DHCP로 Mac IP가 달라지면 새 링크를 공유해야 합니다. `localhost`는 휴대폰 자신을 가리키므로 Mac 접속 주소로 사용할 수 없습니다.

각 Mac은 Bonjour와 같은 네트워크의 주소 탐색으로 다른 AutoApprove를 찾습니다. 주소 탐색은 연결된 사설 IPv4 범위의 기본 포트 **8765**만 확인하며, 큰 네트워크는 현재 IP의 /24 범위로 제한합니다. 기본 포트가 다른 Mac은 Bonjour로 발견하거나 **Mac 추가**에서 그 주소와 포트를 입력합니다. 핫스팟의 IP 테이블을 받거나 휴대폰 브라우저가 직접 스캔하는 방식은 아닙니다. Mac 사이의 통신 자체를 차단하는 핫스팟에서는 기기 간 통신을 허용해야 합니다. 앱의 웹 접속을 끄거나 종료하면 해당 Mac의 접속도 끝납니다. 켜기/끄기와 주소로 추가한 Mac은 재실행 후 유지됩니다. 개인용 폐쇄망 안의 기기가 로그인 없이 제어하는 사용 방식입니다.

기본 포트는 **8765**이며 다른 프로그램이 사용 중이면 macOS가 빈 포트를 배정합니다. 연결 설정의 주소·QR 코드에 실제 포트가 표시되고 재실행 때 저장된 포트를 먼저 사용합니다. 그 포트도 사용 중이면 새 포트를 배정합니다. CLI도 `autoapprove serve` 실행 시 같은 기본값을 적용합니다. `serve --web`으로 명시적으로 켜거나 실행 중인 앱에 `autoapprove web on`, `autoapprove web off`, `autoapprove web`으로 설정·주소를 확인합니다. 별도 검증 인스턴스는 `serve --web --web-port 8766 --home /tmp/autoapprove-web`처럼 포트를 지정할 수 있습니다.

공용 이름은 기본 포트의 Mac 하나가 맡고 다른 Mac은 함께 사용합니다. 담당 Mac이 종료되면 다른 기본 포트 Mac이 이름을 이어받습니다. IP가 바뀌어도 같은 이름을 사용하며 컴퓨터 이름·라우터·hosts 설정을 바꾸지 않습니다. 공용 이름이 충돌하거나 기본 포트를 사용하는 Mac이 없을 때는 연결 설정에 표시되는 Mac별 `autoapprove-<식별자>.local:<포트>` 주소 또는 QR 코드로 접속합니다. **핫스팟을 제공하는 아이폰·안드로이드에서는 `.local` 이름이 열리지 않을 수 있으므로 ‘휴대폰으로 공유’로 직접 접속 링크를 전달하세요.** 공용 이름은 ‘이름으로 접속 · 지원되는 네트워크’에 별도로 표시합니다. 휴대폰에서 주소를 **즐겨찾기나 홈 화면에 저장**할 수 있으며, 핫스팟 재연결로 IP가 달라지면 새 링크를 공유합니다.

실제 PTY는 프로그램이 보내는 원본 ANSI 색상과 서식을 표시합니다. 기존 탭의 웹 중계도 **AutoApprove Bridge 0.2.5 이상으로 연결한 VS Code**에서 원본 색상을 표시합니다. RGB·256색·테마의 16색, 배경색, 굵기·밑줄 등을 전달하고 문구를 보고 색을 추측하지 않습니다. **원본 색상**을 끄면 단색으로 읽을 수 있으며 설정은 브라우저에 저장됩니다. 확장은 Mac의 **연결 설정 → VS Code 확장 설치**에서 업데이트합니다. 이미 실행 중인 CLI의 지난 ANSI 출력은 읽을 수 없어 확장을 적용한 뒤 새로 실행한 CLI부터 표시합니다.

**기본 Terminal·iTerm2의 일반 출력 연결은 텍스트를 제공합니다.** 원본 ANSI 색상을 복구할 수 없다는 안내와 단색 화면을 표시합니다. 실제 색상은 선택형 **Mac 창 보기**로 확인할 수 있습니다. Orca는 영구 daemon 프로토콜 32–36의 검증된 원본 ANSI 스냅샷을 읽으며 RGB·서식·커서를 유지합니다. 소유자의 사용자 지정 indexed 팔레트가 제공되지 않으면 기본 팔레트를 사용합니다. 기존 세션을 종료하거나 바꾸지 않습니다. 출력과 입력 직후의 빠른 갱신, 동일 화면 전송·그리기 생략, **아래로 따라가기** 및 텍스트 선택 보존은 유지합니다.

설치 파일은 [**최신 AutoApprove 릴리스**](https://github.com/newdlops/autoapprove/releases/latest)에서 받습니다. 검증 범위와 남은 확인 항목은 [VALIDATION.md](VALIDATION.md)에 기록합니다.

세션을 발견하는 기능과 자동 승인 가능한 연결을 구분하며, 실제 설치 환경에 따라 지원 범위가 달라집니다.

0.2.30은 **Terminal 창을 탭으로 묶은 뒤 일부 탭에서 자동 승인이 되지 않던 문제**를 수정합니다. Terminal은 탭을 묶어도 탭마다 창 하나로 알려 주는데, 이 창 목록에 더 이상 읽을 수 없는 항목이 섞일 수 있습니다. 승인 입력 단계가 그 항목에서 멈춰, 목록상 그 뒤에 있는 탭은 요청을 감지하고도 입력하지 못하고 직접 확인으로 남았습니다. 이제 읽을 수 없는 창과 탭은 건너뛰고 대상 탭에만 1번을 입력합니다. 입력 직전의 화면·CLI 재확인과, 전달 여부를 알 수 없는 입력은 다시 보내지 않는 규칙은 그대로입니다.

0.2.29는 **Codex 하위 에이전트의 승인 요청이 이어서 뜰 때 자동 승인이 멈추던 문제**를 수정합니다. 메인 대화의 승인에 답한 직후 같은 자리에 뜨는 하위 에이전트 요청(`Thread: …`, 하단 `… or o to open thread`)을 승인 창으로 인식하지 못해 상태 미확인으로 멈췄습니다. 이제 같은 승인 창으로 인식해 해당 세션의 자동 승인 설정대로 1번으로 응답하며, 요청한 대화 이름을 승인 내역에 남깁니다. 1번 선택 확인과 입력 직전 재확인은 그대로입니다.

0.2.28은 **iTerm2와 Orca의 Claude Code·Codex 세션**을 훅 없이 Terminal처럼 연결합니다. `연결 설정`에서 iTerm2·Orca를 각각 연결하면 세션을 인지하고, 지원하는 승인 화면에 해당 세션에만 1번으로 응답하며, 해당 탭으로 이동합니다. 어느 앱의 터미널인지는 프로세스 계보와 CLI 실행 환경의 정해진 변수로만 판별하며, 계보로 확인된 Terminal·VS Code 세션은 이전과 같게 처리합니다. Warp·Ghostty 등은 앱 이름만 표시하고, tmux·screen·Zellij 안의 세션은 연결하지 않습니다.

0.2.27은 **두 번째 선택지가 긴 승인 화면에서 가끔 대기하던 문제**를 수정합니다. Codex의 `Yes, and don't ask again for commands that start with …`처럼 명령 전체가 들어간 선택지가 줄바꿈되어 다음 줄이 `>`(리다이렉트·화살표 함수)나 `2.`로 시작해도 같은 선택지로 인식합니다. 번호 위치의 커서나 뒤따르는 입력창은 계속 거부합니다. 훅 없이 화면으로 연결한 Claude Code 2.1.28x 세션의 `Yes, and don’t ask again for: <명령>`, 권한 모드 전환(`switch to auto mode`, `switch to accept edits … for this session`), `allow reading from …`과 하단의 `Esc to cancel · Tab to amend`도 인식해 1번 `Yes`로 응답합니다. Claude 질문 훅도 같은 문구를 반복 허가로 처리합니다. 다른 작업을 고르는 선택지와 하단 안내가 없는 Claude WebFetch 권한 화면은 계속 직접 확인합니다.

0.2.26부터 **앱을 Applications 폴더로 드래그하는 DMG**로 배포합니다. DMG에는 앱·Applications 바로가기·설치 안내가 있으며, 별도 설치 프로그램이나 터미널 명령 없이 복사해 설치합니다. 최초 실행의 개발자 확인 경고는 아래의 시스템 설정 절차로 허용합니다.

0.2.23은 여러 VS Code 창의 반복 등록과 일반 터미널 출력으로 발생하던 전체 재계산·화면 갱신을 줄입니다. 실제 세션 변경은 즉시 반영하고, 긴 질문 목록의 중복 검사를 한 번씩 순회하도록 개선했습니다. 격리 성능 검사는 릴리스 빌드 후 `node scripts/performance-check.mjs --assert-quiet`로 재현할 수 있습니다.

0.2.22는 **작업 완료와 오래 기다린 질문만 알립니다.** 질문 대기는 기본 **10초**이며 **연결 설정 → 질문 대기 시간**에서 1~3600초로 바꾸고 저장할 수 있습니다. 앱 재실행 후에도 유지하며, 대기 중인 질문은 처음 기다리기 시작한 시점을 기준으로 새 시간을 적용합니다. Claude의 앱 승인과 Codex 질문 대기열에서 자동 응답이 예약된 동안에는 배너·소리·새 알림 배지를 만들지 않습니다. 질문과 카운트다운은 상세에 계속 표시하며, 자동 승인 OFF·일시정지·일반 선택 질문·터미널에서 직접 답해야 하는 요청도 설정한 시간 동안 미응답 상태여야 한 번 알립니다. 그 전에 답하거나 해결된 질문의 알림은 취소합니다. 작업 완료 알림은 유지합니다.

Codex의 `Allow / Allow for this session / Always allow / Cancel` 도구 승인도 **이번 요청의 Allow**로 응답합니다. 선택지 옆의 설명과 좁은 터미널의 줄바꿈을 인식하며, 실제 요청 내용과 선택된 1번을 다시 확인한 뒤 입력합니다.

0.2.21은 **Claude 요청을 앱에서 직접 허용**합니다. 현재 요청의 `허용`·`예` 버튼은 이번 요청에만 답하며, `허용하고 자동 승인 켜기`는 메인과 연결된 백그라운드의 다음 지원 요청까지 이어서 처리합니다. 새 Claude 요청은 질문마다 5초 후 자동 응답하고, 대기 중 앱이 잠시 재시작되거나 응답이 유실돼도 같은 요청을 이어받습니다. 응답과 감사 내역을 함께 저장해 재시도 시 중복 승인하지 않습니다. 지원하는 동기 훅을 최대 10분 유지하며 `터미널에서 답하기`로 원래 질문에 넘길 수 있습니다. 이미 반환된 예전 훅과 일반 작업 선택 질문은 터미널에서 답해야 합니다.

0.2.20은 **이미 열린 Claude 백그라운드 질문의 상태를 복원**합니다. 새 훅이 없어도 현재 실행의 입력 대기를 메인 행에 표시하며, 작업 ID·대화 ID가 일치하는 현재 질문의 전문과 선택지를 함께 보여줍니다. 상태가 바뀌면 요청을 지우고, 늦게 읽힌 대기 기록이 새 훅에서 처리한 질문을 다시 열지 않도록 합니다. 연결 전에 이미 반환된 훅에는 답을 보낼 수 없으므로 이번 요청을 터미널에서 처리해야 한다는 안내를 표시합니다. 자동 응답은 훅이 연결되고 자동 승인을 켠 세션의 다음 지원 질문부터 적용됩니다.

0.2.19는 **메인에서 시작한 Claude 백그라운드 세션을 한 행으로 합칩니다.** 메인의 자동 승인 스위치를 공유하고 질문·알림·처리 내역을 메인 상세에 모읍니다. 메인을 열람하면 자식 배지도 함께 읽음 처리합니다. 실제 프로세스 관계 또는 검증된 Claude 작업 ID로 연결하며, 같은 프로젝트라는 이유만으로 묶지 않습니다. 메인이 종료되면 상속 자동 승인을 멈추고 독립된 세션으로 표시합니다.

**허용 / 항상 허용 / 거부** 선택지도 인식하고 이번 요청의 `허용`으로 응답합니다. Claude 질문 훅과 Codex 질문 대기열에서는 순서가 바뀌어도 원래 일회 허용 라벨을 전달합니다. 반복 허용만 있거나 일회 허용 답이 모호하면 직접 확인하며, 지원되는 권한 확인 화면에서도 같은 한글 선택지를 구분합니다. 메인에 합쳐진 백그라운드 질문은 실제 질문을 보낸 자식의 훅으로 응답합니다. 이미 훅에서 반환된 과거 질문을 소급해 답하지 않습니다.

0.2.18은 세션마다 **표시 이름·메모·색상**을 저장하고 이름과 메모로 검색할 수 있습니다. **새 질문·작업 완료 알림 배지**는 해당 세션을 열람하면 사라지고 읽음 상태를 유지합니다. Terminal 자체 탭·Dock의 배지 복제는 지원하지 않습니다. Claude 백그라운드 실행기의 가상 TTY는 일반 탭과 구분하며, 한글 예·아니오 질문에 응답하지 않은 경우 자동 승인 꺼짐·일시정지 사유를 표시합니다.

0.2.17은 앱 안에 **버전 정보와 도움말**을 제공합니다. 관리 창의 물음표 버튼, 도움말 메뉴, 메뉴 막대 아이콘에서 시작 방법·자동 응답 규칙·문제 해결을 읽을 수 있습니다. 빈 서식 메뉴와 보기 메뉴를 정리하고, 편집과 창 이동에 필요한 기본 동작을 유지합니다. 앱 설치와 다운로드 차단 해제는 아래 설치 절차로 함께 처리합니다.

0.2.16은 **새 Codex 확인 질문에 5초 후 Yes·Allow로 자동 응답**합니다. 카운트다운과 질문별 취소를 제공하고, 직접 선택·입력을 시작하면 해당 질문의 자동 응답을 멈춥니다. 과거·중복 질문과 이미 답했을 수 있는 질문은 직접 확인하며, 전송 준비 중 일시정지한 질문은 재개 후 새로 5초를 기다립니다.

0.2.15는 **빠른 화면 갱신 중 승인 확인이 반복 실패하면 대기에 고정되는 문제**를 수정했습니다. 입력 미전달이 확실한 경우 0.25초부터 최대 4초까지 간격을 늘리며 새 화면에서 다시 확인합니다. 잠깐 불완전하게 그려진 화면은 이전 승인 상태를 지우지 않으며, 입력 성공·결과 미확인은 재전송하지 않습니다. 승인 직후 0~50ms 뒤 다음 명령을 표시하고 이전 결과를 늦게 보내는 검사를 추가했습니다.

0.2.14는 **Codex 승인창이 연속으로 나타날 때 다음 요청을 놓치는 문제**를 수정했습니다. 화면 조회 사이에 다른 명령의 승인창으로 바뀌면 이전 요청의 승인 여부·재시도 상태를 이어받지 않습니다. 같은 요청의 줄바꿈·공백·단축키 표시 변화는 중복 승인하지 않으며, 전송 직전에는 명령과 선택지 원문 전체를 다시 확인합니다. Claude 실행이나 훅 설치 없이 Codex 화면 연결만으로 동작합니다.

기존 터미널에서는 **Claude Code 또는 Codex가 실행 중인 세션만 표시합니다.** 앱이 만든 PTY는 셸 상태에서도 표시합니다. 목록 상단의 **대기 중 N개** 또는 **대기 중** 필터로 두 도구 중 다음 지시를 기다리는 세션을 찾을 수 있습니다. 상세에는 대기 감지 후 경과 시간과 판정 근거를 표시합니다. 일반 셸과 다른 명령만 실행 중인 터미널은 목록과 상태 개수에 포함하지 않습니다.

프로젝트명 바로 아래에 **터미널 제목**을 표시하고 제목으로도 검색할 수 있습니다. Terminal은 탭의 사용자 지정 제목을 우선하며, 선택된 탭 또는 단일 탭에서는 창 제목도 사용합니다. 제목을 읽지 못한 비활성 탭에 다른 탭의 제목을 대신 붙이지 않습니다. VS Code는 기존 확장이 보내는 터미널 이름을 사용합니다.

터미널 제목 아래에는 **현재 폴더의 Git 브랜치**를 표시합니다. 폴더·브랜치 변경을 자동으로 다시 확인하며, 같은 저장소의 연결된 워크트리도 각자의 브랜치를 표시합니다. 긴 이름은 목록에서 줄이고 툴팁과 상세에서 전체를 확인할 수 있으며, 브랜치명으로 검색할 수 있습니다. Detached HEAD는 짧은 커밋 해시, Git 저장소가 아닌 폴더는 `Git 저장소 아님`으로 구분합니다. 읽기 실패 시 다음 갱신에서 재시도하며 자동 승인 상태에는 영향을 주지 않습니다.

목록의 세션을 **더블클릭**하면 해당 터미널을 열고 강조합니다. 한 번 클릭하면 상세를 선택하며 자동 승인 스위치는 별도로 동작합니다. 우클릭의 **터미널 열기**와 기존 상세 버튼도 사용할 수 있습니다.

행을 **드래그**하면 터미널 순서를 바꿀 수 있습니다. 바꾼 순서는 새로고침과 앱 재실행 후에도 유지되며, 새로 발견한 세션은 저장된 순서 뒤에 표시합니다. 검색·필터 상태에서는 보이는 항목끼리 순서를 바꾸고 숨겨진 항목의 위치는 유지합니다. 우클릭의 **위로 이동 / 아래로 이동**도 사용할 수 있습니다. 순서는 개별 실행 세션에 저장되므로 같은 폴더의 터미널도 구분하며, 종료 후 새로 실행한 세션은 새 항목으로 취급합니다.

0.1.1에서는 Terminal 탭에 없는 `name` 속성 조회로 발생한 `-1728` 연결 오류와, `ps` 열 정렬 공백 때문에 이름이 `claude` 또는 `codex`로만 표시된 프로세스가 누락되는 문제를 수정했습니다. 목록에 TTY·PID를 함께 표시하며 닫힌 탭 하나가 다른 탭의 연결을 중단하지 않도록 처리합니다.

## 설치

[GitHub Releases](https://github.com/newdlops/autoapprove/releases/latest)에서 **DMG 파일**을 받습니다. **macOS 14 이상, Apple Silicon(arm64)**용이며 Claude Code·Codex는 별도로 설치해야 합니다.

1. 실행 중인 AutoApprove가 있으면 메뉴 막대에서 종료합니다.
2. DMG를 열고 **AutoApprove.app을 Applications 폴더로 드래그**합니다.
3. 기존 앱이 있으면 교체를 선택하고, Finder가 권한을 요청하면 시스템 창에서 인증합니다.
4. 복사가 끝나면 Finder의 **응용 프로그램 → AutoApprove**를 엽니다. DMG는 추출해도 됩니다.

터미널을 열거나 명령어를 입력할 필요가 없습니다. 기존 설정과 승인 내역은 앱 밖에 저장되므로 유지됩니다.

**처음 열 때 개발자 확인 경고가 표시되는 경우:** 공식 배포 파일임을 확인한 뒤 경고를 닫고 **시스템 설정 → 개인정보 보호 및 보안 → AutoApprove의 ‘그래도 열기’ → 열기**를 선택하세요. 현재 앱은 **Developer ID 서명·Apple 공증을 받지 않았으므로**, macOS의 최초 허용을 자동으로 생략할 수 없습니다. 관리형 Mac은 관리자 정책에 따라 허용이 제한될 수 있습니다. [Apple의 실행 허용 안내](https://support.apple.com/ko-kr/102445).

**‘손상됨’ 경고가 표시되면** 공식 릴리스에서 DMG를 다시 받아 설치해주세요. 동일한 경고가 반복되면 경고에 나온 파일 이름과 문구를 확인해야 원인을 좁힐 수 있습니다. DMG 전환이나 드래그 복사가 다운로드 차단 속성을 자동으로 제거하지는 않습니다. 0.2.43부터 앱은 재사용하는 자체 코드 서명 인증서로 서명하며 Developer ID 공증은 포함하지 않습니다.

**Terminal 직접 입력이 안 되면:** 빌드 53부터 입력 보조 서비스를 사용하므로 손쉬운 사용 권한이 필요하지 않습니다. Mac의 **연결 설정 → 원본 터미널 화면·입력**에서 연결 상태를 확인하세요. 빌드 54에서 승인 대기 상태라면 **허용 설정 열기**로 macOS의 백그라운드 실행을 허용합니다. 서명·실행 오류가 있는 기존 서비스는 자동 교체하지 않고 이유를 표시합니다. 화면 기록은 Mac 창 보기를 선택할 때만 필요합니다. 이전 빌드 52의 키 이벤트 입력 경로에는 별도의 손쉬운 사용 허용이 필요합니다.

## 실행

설치한 AutoApprove 또는 직접 빌드한 `dist/AutoApprove.app`을 엽니다. 앱은 세션 탐색부터 시작하며 자동 승인은 기본적으로 꺼져 있습니다.

1. **연결 설정**에서 필요한 연결을 설정합니다.
2. 목록에서 세션의 연결 상태를 확인합니다.
3. 해당 세션의 **자동 승인**을 켭니다. 여러 행을 선택하면 한꺼번에 변경할 수 있습니다.

관리 창을 닫아도 메뉴 막대에서 실행됩니다. 앱을 종료하면 자동 승인도 중지됩니다. 전체 일시정지는 승인 자동화만 멈추며 터미널의 작업은 종료하지 않습니다. 이미 전송된 승인은 되돌리지 않습니다.

**터미널 열기**를 누르면 해당 Terminal 창을 복원·선택하고, 파란 테두리와 프로젝트명·도구·TTY를 약 3초간 표시합니다. 표시는 클릭과 키보드 입력을 가로채지 않습니다. VS Code는 확장 0.2.3에서 이동한 터미널의 이름·TTY 알림과 임시 상태 표시를 제공합니다.

0.2.4부터 터미널 프롬프트와 체크 표시를 조합한 전용 앱 아이콘을 사용합니다. 버튼·필터·자동 승인 스위치·상태·기록 결과에 포인터를 올리면 기능과 현재 상태에 맞는 macOS 툴팁이 표시됩니다. [아이콘 원본과 생성 기록](assets/README.md).

0.2.12는 질문 선택지·직접 답변·전송 버튼, 순서 이동 메뉴, 연결 설정의 아이콘, 오류·로딩 표시에도 툴팁을 보완했습니다. 비활성 버튼은 빈 답변·전송 중·연결 필요·목록의 처음과 끝 등 현재 사용할 수 없는 이유를 안내합니다.

## 버전 확인과 도움말

**AutoApprove → AutoApprove 정보**에서 실행 중인 앱의 버전과 빌드 번호를 확인합니다. 관리 창의 **도움말(물음표)** 또는 **도움말 → AutoApprove 도움말**에서도 버전을 확인하고, macOS 버전과 함께 복사할 수 있습니다. 세션이나 요청 내용은 복사 정보에 포함하지 않습니다.

도움말의 **시작하기 / 자동 응답 / 문제 해결**은 인터넷 연결 없이 읽을 수 있습니다. **최신 릴리스**, **사용법 문서**, **문제 보고**는 브라우저에서 GitHub를 엽니다. 자동 업데이트를 설치하는 기능은 아닙니다.

| 단축키 | 동작 |
|---|---|
| ⌘O | 관리 창 열기 |
| ⌘, | 연결 설정 열기 |
| ⇧⌘H | 승인 내역 보기 |
| ⌘/ | 도움말 열기 |
| ⌘R | 관리 창 새로고침 |
| ⌘Q | 앱 종료 |

연결 설정은 툴바·앱 메뉴·도움말에서 같은 창으로 열립니다. 관리 창을 모두 닫아도 메뉴 막대 아이콘에서 관리 창·도움말·버전 정보를 다시 열 수 있습니다.

## 승인 내역

세션 상세의 **최근 승인 내역**에서 ‘승인 입력 전달’ 등 결과 행을 누르면 해당 항목의 **전체 요청·전달한 답변·출처**를 바로 펼칩니다. 다시 누르면 접히며 여러 항목을 각각 열어 비교할 수 있습니다.

관리 창 툴바의 **승인 내역**, 세션 상세의 **전체 내역 보기**, 메뉴 막대의 **승인 내역 보기**로 저장된 기록을 엽니다. 프로젝트·명령·도구·TTY를 검색하고 응답 전달·확인 필요·터미널 응답으로 필터링할 수 있습니다. 100건 단위로 이전 기록을 탐색하며, 선택하면 정확한 시각·프로젝트 경로·도구·PID·TTY·요청 내용·전달 결과를 확인하고 복사할 수 있습니다. 질문에 자동으로 답한 기록에는 **선택한 답**도 표시합니다.

세션 종료와 앱 재실행 이후에도 기록을 유지하며 2,000건 초과 시 자동 삭제하던 제한을 제거했습니다. 화면 승인 시도는 전송 전에 저장하고 전달 결과를 같은 기록에 갱신합니다. 결과를 확인하지 못한 시도도 남습니다. 기록 저장에 실패하면 해당 새 승인 입력을 보내지 않고 앱에 오류를 표시합니다.

Claude 훅은 도구 요청 인자를 보존하며, 화면 연결은 읽을 수 있는 요청 내용만 기록합니다. 이전 버전의 기록에 없던 프로젝트·TTY 정보와 이미 삭제된 오래된 기록은 복원할 수 없습니다. **승인 전달은 명령 실행 성공을 뜻하지 않습니다.**

Terminal 연결을 한 번 켜면 앱 재실행 후에도 복원합니다. 명시적인 연결 해제는 유지하며, macOS 자동화 권한 거부 시에는 설정을 허용하고 다시 연결해야 합니다. 0.2.1 이전 버전은 연결 설정을 저장하지 않았으므로 업데이트 후 연결을 한 번 켜주세요. 자동 승인이 켜져 있어도 연결이 끊긴 세션은 목록 상단과 행에 이유를 표시합니다.

**iTerm2와 Orca**도 훅 없이 Terminal과 같은 방식으로 연결합니다. `연결 설정`에서 각각 연결하면 앱 재실행 후에도 복원하며, 다른 터미널의 연결에는 영향을 주지 않습니다. iTerm2는 자동화 권한으로 세션별 현재 화면을 읽고 해당 세션(분할 창 포함)에만 입력합니다. 입력 직전에 iTerm2가 알려주는 포그라운드 작업이 해당 CLI인지도 확인합니다. Orca는 앱에 포함된 `orca` 명령줄 도구로 렌더링된 화면을 읽고, 입력 직전에 화면을 다시 확인한 뒤 해당 터미널에만 `1`과 Enter를 보냅니다. 별도 권한은 필요 없고 Orca가 실행 중이어야 합니다.

어느 앱의 터미널인지는 프로세스 계보와 CLI 프로세스의 실행 환경 변수(`TERM_PROGRAM`, `__CFBundleIdentifier`, `ITERM_SESSION_ID`, `ORCA_TERMINAL_HANDLE`, `TMUX`, `TMUX_PANE` 등 허용한 이름만)로 판별합니다. Warp·Ghostty처럼 화면 연결이 없는 앱도 이름을 표시하지만 제어 가능한 것처럼 표시하지 않습니다. Cursor 등 VS Code 계열은 브리지로 연결합니다. tmux는 서버 PID·시작 시각·소켓 소유자·pane ID와 같은 CLI의 PID·TTY를 검증한 전용 중계를 사용합니다. screen·Zellij와 확인되지 않은 중첩 PTY는 연결하지 않습니다.

## 연결별 동작

| 연결 | 지원 | 조건과 한계 |
|---|---|---|
| 프로세스 탐색 | 기존 Claude·Codex, PID·TTY·프로젝트·터미널 앱 | 도구가 실행된 터미널만 표시. 도구 종료 시 활성 목록에서 제외. 터미널 앱은 계보와 허용한 실행 환경 변수로 판별 |
| Claude 훅 | `PermissionRequest` 직접 승인, 단일 예·아니오 확인, 질문·선택지 표시, 작업 이벤트 | 훅 설정을 읽은 세션부터 가능. 터미널로 반환된 권한 요청은 지원하는 화면 연결이 있을 때 감지·승인 |

| iTerm2 | 세션의 승인 감지·원본 창·직접 키 입력·탭 이동 | iTerm2 자동화 권한과 창 표시의 화면 기록 권한 필요. 같은 창의 분할 화면도 캡처. 입력 직전 포그라운드 작업 확인. 이전 승인 경로는 iTerm2 3.7.3에서 실제 Codex·Claude로 검증 |

| Codex app-server | 이번 버전의 실행 경로에 포함하지 않음 | 확인한 기존 CLI에 공유 서버 소켓이 없어 터미널 연결을 사용 |

확장 설치 전에 시작한 VS Code 명령의 이전 ANSI 바이트는 공식 API로 복구할 수 없습니다. 이 경우 출력 제한을 표시하고 같은 기존 터미널 객체에 키를 보냅니다. 사용자가 원할 때 Mac 창 보기를 켤 수 있습니다. 확장 설치 후 시작한 명령은 앱 연결이 끊겨도 출력 읽기를 유지해 재접속합니다. 실제 명령 종료·읽기 실패는 감지를 중지합니다. 기존 Claude의 승인은 훅으로도 연결할 수 있습니다. SSH 원격 호스트, Dev Containers, WSL은 지원하지 않습니다.

화면 감지는 승인 창 제목·선택된 일회 승인 옵션·거부 옵션·화면 끝을 함께 확인합니다. 입력 전 화면 내용과 실행 중인 프로세스를 다시 확인하지만, 터미널의 화면 확인과 입력은 원자적 작업이 아닙니다. 훅 연결은 해당 요청에 직접 응답합니다.

0.2.2는 긴 명령의 승인 창, 한글 정규화 차이, Codex 요청 위쪽 기록 변경을 처리합니다. Claude는 확인 제목 위에 표시되는 명령도 함께 검증합니다. 0.2.15부터 화면 검증에서 입력 미전달이 확인되면 횟수 소진으로 멈추지 않고, 간격을 늘리며 새 화면에서 재시도합니다. 전송 성공 또는 결과 미확인 상태에서는 같은 화면에 입력을 반복하지 않습니다. 내용까지 동일한 두 승인 요청 사이의 화면 변화를 관찰하지 못하면 직접 확인이 필요할 수 있습니다.

자동 승인을 켠 Claude 세션에서는 **단일 예·아니오 질문**에 ‘예’를 전달합니다. 0.2.5부터 ‘미커밋·브랜치 현황을 훑어볼까요?’처럼 질문 문구가 달라도 두 선택지에 명확한 예·아니오가 있으면 처리합니다. 추천 표시와 예·아니오 뒤에 붙은 설명도 인식하며 선택지 순서에 의존하지 않습니다. 질문·선택지·선택한 답은 승인 내역에 저장합니다. [Claude 공식 훅 응답 형식](https://code.claude.com/docs/en/hooks#pretooluse-decision-control)의 `updatedInput.answers`를 사용합니다. 이 응답은 새 훅 요청부터 적용되며 이미 반환된 질문을 과거 기록으로 다시 실행하지 않습니다.

0.2.12부터 **Claude Code와 Codex의 승인 화면**, **Claude의 단일 훅 질문**에서 `Yes / Yes, don't ask again / No`처럼 같은 허가의 반복 범위만 다른 선택지는 세 개 이상이어도 처리합니다. 일반 `Yes` 또는 이번 요청만 허용하는 답을 고르며, `and don't ask again`, `don’t`, 세션 내 허용, 단축키·추천 표시, 터미널 줄바꿈을 인식합니다. 단축키는 `y / a / esc`, `y / p / esc` 조합과 `(y)`·`[y]` 표시를 지원합니다. Claude 훅에서는 선택지 순서와 무관하게 원래 답 라벨을 반환합니다. 화면 방식은 현재 일회 승인 항목이 1번으로 선택된 활성 승인 창만 처리하며, 다른 항목을 가리키고 있으면 입력하지 않습니다. 0.2.27부터 줄바꿈된 선택지 문구는 라벨의 들여쓰기로 구분하고, Claude Code의 `don’t ask again for: <명령>`·권한 모드 전환·`allow reading from …`도 같은 반복 범위로 처리합니다.

그 밖의 프로젝트·환경·계획 선택, 서로 다른 작업을 고르는 삼지선다, 여러 질문과 다중 선택은 **응답 필요**로 표시합니다. 반복 허가만 있거나 일회 승인 답이 모호한 여러 선택지도 직접 확인합니다. 계획 모드 확인도 직접 처리합니다. 전체 일시정지와 세션 자동 승인 끄기는 예·아니오 자동 응답에도 적용됩니다. 사용자 정의 화면이나 지원하지 않는 메뉴 형식은 추가 대응이 필요합니다. Codex 비동기 질문은 아래 질문 대기열의 5초 자동 응답 규칙을 따릅니다.

자동 처리할 수 없는 질문이 **설정한 시간 동안 미응답 상태로 남으면 macOS 알림**으로 알려줍니다. 기본 10초이며 `연결 설정 → 질문 대기 시간`에서 변경합니다. 그 전에 답하거나 해결되면 알림을 취소합니다. 알림 또는 ‘터미널 열기’를 누르면 해당 세션으로 이동해 기존 강조 표시를 띄웁니다. 같은 질문은 한 번만 알리고, 해결되면 알림을 정리합니다. Claude의 일반 권한 알림이 원래 질문을 덮어쓰지 않습니다. 종료된 세션의 알림으로 다른 터미널을 열지 않습니다.

처음 실행할 때 알림을 허용해주세요. `연결 설정 → 질문 · 작업 완료 알림`에서 상태를 확인하고 시스템 알림 설정을 열 수 있습니다. 배너·소리는 macOS와 집중 모드 설정을 따릅니다. [Apple 알림 권한 안내](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications).

## 작업 완료 알림

Claude Code·Codex가 **최종 응답을 마치면** 프로젝트명·도구·응답 요약을 macOS 알림으로 보냅니다. 알림을 누르면 원래 터미널을 열고 강조합니다. 자동 승인을 끄거나 전체 일시정지해도 완료 알림은 동작합니다.

- **Claude Code**: 설치된 훅의 `Stop`을 사용합니다. 도구 하나의 종료나 하위 에이전트 종료는 완료로 알리지 않습니다. 훅이 진행 중인 백그라운드 작업·예약된 후속 작업을 보고하거나 직접 답해야 할 질문이 남으면 보류합니다. [Claude Stop 훅](https://code.claude.com/docs/en/hooks#stop).
- **Codex**: 질문 대기열과 동일한 루트 대화의 로컬 완료 기록을 읽습니다. 최신 턴의 `completed`만 알리고 `failed`·`interrupted`는 제외합니다. Codex 0.155.1 기록 형식을 기준으로 하며, 기록 읽기 오류는 세션 상세에 표시합니다. [Codex 턴 상태](https://developers.openai.com/ko-KR/docs/app-server).

첫 관찰의 과거 기록·단순 입력 대기·연결 끊김·프로세스 종료는 완료로 추정하지 않습니다. 완료 신호 후 3초 안에 새 작업이 확인되면 알림을 취소하고, 같은 완료는 한 번만 알립니다. 새 작업을 시작하거나 세션이 종료되면 해당 완료 알림을 정리합니다. 알림 권한을 나중에 켰을 때 오래된 완료가 몰리지 않도록 완료 알림은 최근 5분만 유지합니다.

완료는 **해당 응답이 끝났다는 뜻**이며 요청한 결과의 정확성이나 모든 명령의 성공을 보증하지 않습니다. Claude 훅이 없는 연결, 백그라운드 정보를 제공하지 않는 이전 Claude 버전, 다른 훅이 뒤늦게 작업을 재개하는 경우에는 완료 감지에 한계가 있습니다.

## Codex 질문 대기열

자동 승인이 켜진 연결 세션에서 **새로 들어온 예·아니오 질문이 응답 대기로 5초 이상 유지되면 Yes·Allow·허용을 자동 전송**합니다. `Allow`·`Allow once`·`허용`을 긍정 응답으로 인식하고 `Deny`·`Don't allow`·`거부`는 부정 응답으로 구분합니다. `Always allow`·`항상 허용` 같은 반복 허용 선택지가 함께 있으면 이번 요청만 허용하는 원래 선택지 문구를 전달합니다. 질문마다 처음 감지한 시점부터 시간을 재며 반복 조회로 초기화하지 않습니다. 질문 아래에 남은 초와 보낼 답변을 표시하고, 서로 다른 작업을 고르는 질문은 직접 답합니다.

**선택지를 체크하거나 입력란에 포커스를 두고 답변을 작성하기 시작하면 해당 질문의 자동 응답을 즉시 멈춥니다.** ‘자동 응답 취소’를 눌러 질문 하나만 취소할 수도 있습니다. 직접 답변·개별 취소 상태는 반복 조회, 전체 재개, 앱 재실행 후에도 유지합니다. 작성한 답변은 ‘답변 보내기’를 눌러야 전달됩니다.

앱 실행이나 루트 대화 변경 때 처음 읽은 질문은 **이전에 받은 질문**으로 표시하고 자동으로 답하지 않습니다. 같은 문구가 여러 번 나온 질문과 인용 없는 후속 사용자 메시지가 있어 이미 답했을 수 있는 질문도 직접 확인하도록 표시합니다. 전송 직전에도 최신 기록에서 중복·후속 메시지를 확인합니다.

질문 정리·내용 변경·기록 읽기 실패·연결 해제·세션 종료·전체 일시정지·자동 승인 끄기는 예약을 취소합니다. 다시 처리 가능한 상태가 되면 새로 5초를 기다립니다. 전송 준비 중 일시정지한 경우도 실제 실패와 구분해 재개할 수 있습니다. 직접 답변·개별 취소한 질문은 자동으로 재개하지 않으며, 실패하거나 접수 결과를 확인하지 못한 답변도 자동으로 반복 전송하지 않습니다. 자동 답변은 질문·답변·출처를 승인 내역에 저장합니다.

AutoApprove 안에서 **선택지를 체크하거나 직접 답변을 입력한 뒤 ‘답변 보내기’**를 누를 수 있습니다. 여러 선택과 추가 설명을 함께 보낼 수 있으며, 선택만으로 전송하지 않습니다. 답변은 질문 원문과 함께 해당 대화의 Codex 메시지 대기열에 등록합니다. **전달 대기**는 Codex가 접수한 상태이며 실행 중인 작업에 즉시 반영되었다는 뜻은 아닙니다. 원래 질문과 보낸 답변은 승인 내역에 저장합니다.

전송 직전에 살아 있는 프로세스·루트 대화·질문을 다시 확인합니다. 전송 중 중복 클릭을 막고, 접수 결과를 확인하지 못한 경우에는 앱 재실행 후에도 재전송하지 않습니다. 연결된 Claude의 구조화된 질문은 휴대폰 웹 폼으로 답할 수 있습니다. 이미 반환된 훅·지원하지 않는 질문 화면, 연결 오류, 전송 결과 미확인 상황에서는 **터미널에서 답하기**로 해당 터미널을 열고 강조합니다. 전체 일시정지는 자동 승인만 멈추며 사용자가 누른 질문 답변에는 적용하지 않습니다.

Codex가 비동기로 묻고 계속 작업하는 질문도 세션 상세의 **질문 대기열**에 모읍니다. 작업 상태는 그대로 유지하고 목록에 **질문 대기 N건**을 추가하며, **확인 필요** 필터·메뉴 막대 개수·알림에 포함합니다. 여러 질문은 각각 유지되고 일반 메시지나 도구 완료로 사라지지 않습니다. 질문을 인용한 답변이 정확히 한 항목과 일치할 때 그 질문만 정리합니다.

Codex의 로컬 기록에는 권위 있는 미응답 상태가 없어, 인용 없는 답변·취소·동일 문구의 중복 질문은 해결됐다고 추정하지 않습니다. 이미 처리한 항목은 **목록에서 정리**로 AutoApprove 목록에서 정리할 수 있고 이 설정은 앱 재실행 후에도 유지됩니다. 이 버튼은 답변을 보내거나 이미 등록된 답변을 취소하지 않습니다. 기존 기록에서 복원하므로 오래된 미확인 질문이 처음에 표시될 수 있습니다. 읽기 오류에는 마지막 목록과 오류를 함께 보여줍니다.

Codex가 기록 파일을 갱신해 잠시 읽을 수 없으면 마지막 질문 목록을 유지하고 자동으로 다시 조회합니다. 첫 두 번의 일시적 실패는 경고를 띄우지 않으며, 세 번 연속 실패하면 갱신 중이라는 안내를 표시합니다. 실제 형식 미지원·파일 접근 실패는 즉시 구분해서 표시하고, 정상 조회가 되면 안내를 지웁니다. 질문 조회와 완료 조회는 독립적으로 복구합니다.

실행 중인 프로세스가 열고 있는 세션 파일로 연결하므로 프로젝트 경로가 같은 다른 터미널이나 하위 에이전트 질문을 섞지 않습니다. 하나의 프로세스에 루트 세션이 여러 개면 추정하지 않고 연결 오류로 표시합니다. `thread_history_1.sqlite` 형식이 없는 버전·원격 실행은 이 경로를 지원하지 않습니다. 공유 daemon을 시작하거나 Codex 설정·질문 기록을 수정하지 않습니다. 사용자가 입력해 둔 다음 작업의 메시지 큐(`codex queue`)는 별개이며 이 목록에 포함하지 않습니다.

승인 내역의 `승인 전달` 또는 `승인 입력 전달`은 응답 전송 기록이며 해당 명령의 성공을 뜻하지 않습니다. 영구 허용 규칙은 추가하지 않습니다.

## 대기 상태

- **Claude Code**: 훅의 응답 완료·입력 대기 이벤트를 우선 사용하며 새 입력이나 도구 실행 이벤트가 오면 작업 중으로 전환합니다.
- **Claude·Codex 화면 연결**: 지원하는 입력창과 하단 안내를 함께 확인하고, 대기 상태가 2초 이상 유지될 때 대기로 표시합니다. 작업 중단 안내가 있거나 입력 준비를 확인할 수 없는 백그라운드 작업은 작업 중으로 처리합니다.
- **대기 중 · 모니터링**: 다음 지시를 받을 수 있고 백그라운드 작업만 남아 있으면 안테나 아이콘과 함께 표시합니다. 대기 필터·대기 수에 포함하며, 배경 출력이 바뀌어도 입력 준비가 유지되면 대기로 봅니다. Claude의 응답 종료 훅이 백그라운드·예약 작업을 보고한 경우도 포함합니다. 모든 작업이 끝났다는 뜻은 아니며 이 상태 자체로 완료 알림을 보내지 않습니다.
- **확인 불가**: 화면 미연결·해제, 알 수 없는 화면 형식, 새 화면 수신 중단은 상태 미확인으로 표시합니다. 출력 정지나 CPU 사용량만으로 대기를 판정하지 않습니다.

0.2.13은 3지 승인 화면의 마지막 No 선택지와 확인 안내가 여러 줄로 나뉘어도 인식합니다. VS Code의 입력 전달 확인이 8초 동안 오지 않으면 승인 내역에 시간 초과를 남기고 알림 대상으로 전환합니다. Terminal·VS Code에서 입력을 전달한 뒤에도 같은 요청이 새 화면에서 계속 확인되면 8초 뒤 터미널 확인을 안내합니다. 입력 미전달이 확인된 경우의 제한적 재시도는 유지하며, 전달 여부가 불명확하면 같은 입력을 반복하지 않습니다. 구형 macOS에서의 실제 재현은 아직 확인하지 못했습니다.

대기 시간은 앱이 대기를 감지한 시점부터 계산하며 앱 실행 이전의 시간을 복원하지 않습니다. 사용자 정의 CLI 화면과 다른 훅이 완료 이벤트 이후 이어가는 작업은 상태 추론의 한계가 있습니다.

## 빌드

macOS 14 이상, Swift 6 이상, Node.js 22 이상이 필요합니다. Swift 쪽은 외부 패키지 없이 시스템 SQLite를 사용합니다.

```sh
bash scripts/build.sh
open dist/AutoApprove.app
```

빠른 개발 빌드:

```sh
AUTOAPPROVE_BUILD=debug bash scripts/build.sh
```

확장 패키지는 `dist/autoapprove-bridge.vsix`에 생성되어 앱에도 포함됩니다. 네이티브 앱은 동일한 발행자 인증서를 재사용해 업데이트가 기존 개인정보 접근 허용 대상과 일치하도록 서명합니다. 외부 배포용 Developer ID 서명·공증은 포함하지 않습니다.

개발용 기본 서명은 `.runtime/code-signing/`의 전용 비공개 키체인을 사용합니다. 최초 생성 후 macOS 코드 서명용 인증서 신뢰 확인이 필요합니다. 이 폴더를 비공개로 보관·백업하고 Git이나 배포 자산에 포함하지 마세요. 발행자 인증서를 바꾸면 기존 사용자의 접근 허용을 다시 받아야 합니다. 별도 발행 인증서는 `AUTOAPPROVE_SIGNING_IDENTITY`와 선택적 `AUTOAPPROVE_SIGNING_KEYCHAIN`으로 지정할 수 있습니다.

release 빌드 후 설치용 DMG와 SHA-256 파일을 만듭니다.

```sh
node scripts/package-dmg.mjs
```

앱의 버전·아키텍처를 읽어 `dist/AutoApprove-<version>-macOS-<arch>.dmg`를 생성합니다. DMG에는 AutoApprove.app·Applications 바로가기·설치 안내만 포함합니다. 이미지 체크섬과 읽기 전용 마운트 후 앱 서명·실행 파일·버전 정보·바로가기·안내 원문을 검사하며, PKG나 실행 스크립트가 섞이면 실패합니다.

`node scripts/package-dmg.mjs /path/to/AutoApprove.app`으로 별도 준비한 앱을 패키징할 수도 있습니다. GitHub Release에는 해당 소스 커밋의 버전 태그와 DMG·`.sha256`만 게시합니다. 이전 PKG 생성기와 검사는 개발용으로 남아 있으며 기본 DMG 생성 과정에서는 실행하지 않습니다.

macOS의 신뢰 저장소를 사용하는 네트워크 환경에서 npm 인증서 오류가 발생하면, TLS 검증을 끄지 말고 다음과 같이 시스템 인증서를 사용합니다.

```sh
NODE_OPTIONS=--use-system-ca bash scripts/build.sh
```

## 검증

전체 Xcode가 없는 Command Line Tools 환경에서도 실행할 수 있도록 핵심 검증은 독립 Swift 실행 파일로 제공합니다.

```sh
swift build --disable-sandbox --cache-path .build/cache
.build/debug/autoapprove-checks
npm --prefix extensions/vscode test
node scripts/terminal-window-check.mjs --release --visual
node scripts/terminal-view-check.mjs --release
node scripts/terminal-view-check.mjs --release --bridge
node scripts/terminal-keyboard-check.mjs --release
node scripts/signing-tool-check.mjs
node scripts/terminal-signing-check.mjs dist/AutoApprove.app
node scripts/original-terminal-screen-check.mjs --release
node scripts/orca-terminal-stream-check.mjs
node scripts/orca-engine-check.mjs --release
node scripts/integration-check.mjs
node scripts/claude-parent-integration-check.mjs
node scripts/claude-hook-integration-check.mjs .build/debug/autoapprove
node scripts/screen-integration-check.mjs
node scripts/codex-queue-integration-check.mjs
node scripts/network-integration-check.mjs
node scripts/network-package-check.mjs dist/AutoApprove.app
node scripts/live-input-stability-check.mjs --release
node scripts/web-interaction-browser-check.mjs --release
node scripts/codex-queue-transport-check.mjs --release
node scripts/terminal-signing-check.mjs dist/AutoApprove.app
node scripts/install-check.mjs
```

`integration-check`는 임시 앱 데이터와 테스트 이벤트만 사용하며 기존 Claude 설정이나 사용자 세션에는 승인을 보내지 않습니다. `screen-integration-check`는 직접 만든 무동작 프로세스를 별도의 PTY에서 실행하고 가짜 확장으로 승인 메시지를 확인합니다. 실제 CLI의 화면 형식이나 VS Code UI 입력 성공을 검증하는 테스트는 아닙니다.

`claude-hook-integration-check`는 비활성 PTY와 격리 소켓에서 실제 helper의 앱 승인·다음 5초 자동 응답·서버 재시작·응답 유실 재전달·중복 방지·터미널 넘기기를 확인합니다. `claude-parent-integration-check`는 메인·백그라운드 연결과 정책 상속을 검사합니다.

`network-integration-check`는 합성 터미널을 가진 두 격리 엔진의 Bonjour 발견·Mac별 제어·화면 조회·입력·중복 방지·끊김과 복구를 검사합니다. `--serve`로 유지한 검증 서버의 `preview.json` 경로를 `network-browser-check.mjs`에 전달하면 Playwright·Chromium이 있는 환경에서 휴대폰·태블릿·데스크톱 화면과 조작을 확인합니다. `--http-lan`을 붙이면 테스트용 `.local` 주소를 루프백에 매핑해 일반 HTTP 환경과 UUID 대체 경로도 확인합니다. `network-package-check`는 먼저 패키징한 앱을 사용하며, 임시 복사본·프로필에서 포트 충돌·웹 설정 복원·웹 끄기와 번들 리소스를 확인합니다.

`live-input-stability-check`는 Chromium과 두 격리 Swift 서버의 실제 HTTP/SSE 중계를 사용합니다. Mac 목록 일부의 시간 초과·원본 화면 조회 실패·백그라운드 감시 오류 중에도 연속 한글 입력과 키보드 포커스를 유지하고, 세션 종료·권한 거부 때에는 입력을 차단하는지 검사합니다. 입력은 테스트 어댑터에만 전달하며 실제 사용자 CLI나 물리 휴대폰을 조작하지 않습니다.

`web-interaction-browser-check`는 실제 Chromium·Swift HTTP·MCP·Claude 훅과 합성 세션으로 선택 응답, 느린 편집 확인, 인라인 오류/초안 보존, Codex 후속 입력의 조회·삭제·새 입력 보존, 화면 공유 버튼·권한 거부·종료를 검사합니다. `--baseline-question`은 이전 0.2.49 웹 파일로 보내기 버튼 차단을 재현하는 실패 검사입니다. `codex-queue-transport-check`는 실제 Swift 대기열 클라이언트를 격리된 Unix WebSocket 서버에 연결해 초기화·페이징·UTF-8·분할 프레임·ping·서버 승인 요청 거부·부분 삭제 결과를 확인합니다. 두 검사 모두 사용자 CLI나 Mac 화면을 조작하지 않습니다.

`terminal-signing-check`는 같은 발행자 인증서를 보유한 배포 환경에서만 실행합니다. 업데이트의 지정 요구사항 호환성과 같은 bundle ID를 쓰는 다른 서명의 거부를 검사하며, 인증서·키체인을 새로 생성하지 않습니다. `signing-tool-check`는 도구 호출을 대역으로 바꿔 암호가 프로세스 인자와 오류 메시지에 포함되지 않는지 검사합니다.

`install-check`는 별도 서명한 테스트 앱을 임시 폴더에 설치해 다운로드 차단 속성 제거·재설치·실행 중 교체 방지·실패 시 복원을 검사합니다. 관리자 인증과 앱 열기는 대역으로 확인하며 실제 비밀번호를 요청하거나 사용자 앱을 실행하지 않습니다.

연속 승인 부하 검사는 같은 CLI 프로세스·화면 세대에서 작업 화면 없이 명령을 바꿉니다. 10건마다 같은 요청과 줄바꿈된 화면을 다시 보내 중복 입력을 검사하고, 마지막에는 전체 SQLite 내역의 요청 수·전달 결과를 대조합니다. `--stress`는 **터미널당** 횟수이며 진행 건수·승인 메시지 수신 지연·프로세스 메모리 표본을 출력합니다. 실제 프로세스 확인을 매번 수행하므로 많은 횟수는 오래 걸릴 수 있습니다.

```bash
node scripts/screen-integration-check.mjs .build/release/autoapprove --stress 1000
node scripts/screen-integration-check.mjs .build/release/autoapprove --stress 1000 --stress-terminals 8 --stress-report /tmp/autoapprove-stress.json
node scripts/screen-integration-check.mjs .build/release/autoapprove --race
```

`--race`는 승인 직후 다음 요청까지 0·1·5·10·25·50ms 간격, 250/1,500ms 지연 응답·이전 실패 응답, 불완전한 화면 재그리기·일시정지, 연속 미전달 후 자동 복구를 검사합니다. `--race-retry`로 미전달 복구만 실행할 수 있습니다.

이 검사는 배포 엔진과 모의 VS Code 연결을 사용합니다. 실제 Terminal의 키 입력 성공률이나 구형 Mac의 최대 처리량을 측정하는 것은 아닙니다.

핵심 검증은 세션 분리, 기본 비활성, 중복 요청, 일시정지, 일반 질문, 화면 변경, 다중 세션 승인, 훅 전환 시 취소, 한국어·영어 환경의 동일한 세션 식별, 설정 병합, 영구 저장을 다룹니다.

## CLI와 데이터

```sh
.build/debug/autoapprove scan
.build/debug/autoapprove doctor
.build/debug/autoapprove status
```

앱 설정과 승인 내역은 `~/Library/Application Support/AutoApprove/state.sqlite`에 저장됩니다. 화면과 요청은 외부 서버로 전송하지 않습니다. 로컬 소켓은 같은 사용자만 연결할 수 있습니다.

`AUTOAPPROVE_HOME` 또는 CLI의 `--home PATH`로 별도 데이터 경로를 사용할 수 있습니다. VS Code에는 `autoapprove.socketPath` 설정이 있습니다.

Claude 훅 설치는 `~/.claude/settings.json`을 먼저 백업하고 기존 설정과 훅을 보존합니다. 앱의 훅 제거 버튼은 AutoApprove 항목만 제거합니다. 앱이 꺼져 있거나 2초 내 응답하지 않으면 훅은 원래 승인 흐름을 유지합니다.

구조와 범위는 [DESIGN.md](DESIGN.md), 실제 검증 결과는 [VALIDATION.md](VALIDATION.md)에 기록합니다.
