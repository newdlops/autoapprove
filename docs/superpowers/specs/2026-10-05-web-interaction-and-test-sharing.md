# 휴대폰 질문·메시지와 테스트 화면 공유

기존 개인 핫스팟 관리 화면을 확장한다. 터미널의 원본 PID·TTY와 자동 승인 상태는 유지하고, 휴대폰 사용자는 터미널 키 조작 없이 질문의 선택지와 추가 답변을 입력한다.

## 화면과 동작

- 기존 시스템 글꼴, 파란 주 동작, 의미 색상, 8px 모서리와 44px 터치 영역을 재사용한다. 새 시각 언어를 만들지 않는다.
- 휴대폰 집중 화면에도 ‘질문·메시지’를 표시한다. 요청 수를 함께 표시하고 사용자가 열면 질문 목록과 새 메시지 작성기를 제공한다. 질문 도착만으로 키보드나 화면을 바꾸지 않는다.
- Codex 기록의 질문은 기존 검증된 메시지 대기열로 답한다. Claude의 살아 있는 AskUserQuestion 훅은 원래 questions 배열을 유지하면서 answers를 전달한다. 여러 질문은 각각 선택·추가 설명을 입력하고 명시적 보내기에서 한 묶음으로 전송한다.
- 일반 메시지는 Codex 대기열 또는 연결된 원본 터미널 입력으로 전달한다. 다른 질문을 선택 중인 터미널에는 일반 메시지를 잘못된 답변으로 입력하지 않는다. 결과 미확인 입력을 재전송하지 않는다.
- MCP의 질문 도구는 구조화된 질문을 게시하고, 별도 조회 도구로 사용자가 보낸 답변만 반환한다. 선택의 기본값은 보내지 않는다.
- 테스트 공유는 Mac 전체 화면을 기본으로 한다. MCP 호출에서 명시적으로 시작하고, 휴대폰과 MCP 모두 종료할 수 있다. 제한 시간 만료·앱 종료에서 종료하며 웹 보기 닫기·숨김 동안 이미지 요청을 중단한다. 화면은 메모리에만 보관하고 사용자 기록과 배포 파일에 넣지 않는다.
- 질문과 테스트 공유는 기존 웹 서버·LAN 중계를 사용한다. 휴대폰 설치·외부 서비스·연결 코드는 추가하지 않는다.

## 확인 기준

390×844, 768×1024, 1440×900에서 빈 상태·여러 긴 질문·단일/복수 선택·초안 유지·전송 중·실패·연결 끊김과 키보드 접근을 확인한다. 원본 세션 선택·질문 응답·화면 공유에서 새 PTY 생성은 0건이어야 한다. 실제 원본 입력은 격리한 tmux 시험 창에서만 확인한다. MCP 초기화·도구 목록·질문 게시/응답·공유 시작/종료와 종료 후 캡처 거부를 확인한다. 화면 권한 부족은 Mac에서 허용해야 한다고 표시한다. 버전을 올리면 로컬 설치와 GitHub 릴리스·다운로드 검증까지 마친다.
