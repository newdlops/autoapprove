# 0.2.167 · 빌드 194

오류 감지 전에 여러 줄을 합치고 문자별로 공백을 정리하던 경로에서, 첫 printable ASCII 바이트가 원래 오류 접두사로 시작할 수 없는 셀은 정규화를 생략합니다. Unicode·공백·빈 줄과 실제 오류 접두사는 기존 식을 분리한 함수로 처리합니다. 오류 키워드 검색은 NSString의 canonical range로 필요한 일치 가능성만 먼저 확인합니다. 예비 검색에서 일치한 경우에는 원래 String.contains를 다시 실행해 기존 결합문자·정규화·문자 경계 판정을 보존합니다. 인증·설정 오류 우선순위, 미분류 오류 복구, Goal 상태·초안·정확한 원본 재검증·중복 전송 방지는 유지합니다. 새 캐시·폴링·타이머·상주 서비스는 없습니다.

합성 변경 화면의 실제 Core 갱신 CPU가 **31.7~36.5% 감소**했습니다. 비변경 제어군과 지연·메모리도 함께 확인했습니다.

실제 최적화 정식 0.2.166/193과 후보 Core의 새 16프로세스·8쌍을 교대로 실행하고 문자열 종류 순서를 회전했습니다. 합성 16세션을 변경/비변경 각각 256회 갱신한 CPU·wall 합계의 8회 중앙값입니다. 변경 시 16개 과거 본문이 모두 바뀌며 4개 입력 대기의 tail은 그대로입니다. 준비/2.2초 정착은 CPU·wall 밖, RSS에는 포함됩니다. 단독 helper·이전 비교의 시간 표본은 재사용하지 않았습니다. 앱 전체·실물 휴대폰·LAN/VPN의 종합 개선율이 아닙니다.

구현 전 고정한 기준은 모든 문자열 종류의 변경 CPU ≤0.85배, 비변경 CPU ≤1.05배, 모든 wall ≤1.10배, 최대 RSS ≤max(기존×1.10, 기존+1MiB)입니다. 모든 8작업량·표본·상태·게시 횟수·실제 저장 형태를 포함해 통과했습니다.
