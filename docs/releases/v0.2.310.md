# AutoApprove 0.2.310 · 빌드 337

탭 하나가 승인을 기다리거나 입력창에 글이 남아 있으면, 같은 터미널 앱의 모든 탭을 0.5초마다 다시 읽던 문제를 고쳤습니다. 이제 세션마다 자기 상태에 맞는 간격으로 따로 읽습니다.

Terminal 앱은 AutoApprove가 화면을 읽을 때마다 macOS 권한 서비스(tccd)에 권한을 확인하고, tccd는 그때마다 앱 서명을 검증합니다. 탭 24개 가운데 하나만 입력창에 글이 있어도 30초에 권한 확인이 약 1,380건 발생했고, tccd가 CPU를 30% 안팎 사용했습니다.

- 기존 읽기 간격 값을 세션마다 따로 적용합니다. 입력을 보내는 중이면 0.35초, 승인 확인이나 질문, 모델 대기 중이면 0.5초, 중단 확인은 2초, 작업 중이면 1.5~2.5초, 대기 중이면 3초입니다. 수동 세션과 일시 중지 상태는 4초입니다.
- 보내지 않은 글만 입력창에 남은 세션은 0.5초 대신 2초 간격으로 읽습니다. 글을 보내기 전에는 승인할 요청이 생기지 않습니다. 질문이나 승인 요청이 함께 있으면 0.5초를 유지하고, 휴대폰에서 입력 중이면 0.35초로 읽습니다.
- 다음에 읽을 시각이 0.25초 안으로 가까운 세션은 한 번에 함께 읽습니다.
- 세션 목록이 바뀌거나, 자동 승인을 켜고 끄거나, 휴대폰에서 화면을 열거나, 읽기가 실패한 뒤에는 예전처럼 모든 탭을 한 번에 다시 읽습니다.
- 연결 상태에 표시하는 세션 수에는 이번에 읽지 않은 탭도 직전 읽기 결과에 따라 포함합니다.

설치한 앱에서 탭 24개를 30초 동안 측정했습니다. Terminal 앱의 권한 확인은 약 1,380건에서 84건으로 줄었고, tccd의 평균 CPU는 30% 안팎에서 수 % 수준으로, AutoApprove의 CPU는 5~9%에서 1~2%로 낮아졌습니다. Terminal 앱의 CPU 사용률(14~19%)은 대부분 실행 중인 세션의 출력을 화면에 그리는 데 쓰여서 크게 바뀌지 않았습니다.
