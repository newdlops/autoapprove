# 0.2.159 · 빌드 186

입력이 꼬였을 때 사용할 **자동화 초기화·재실행** 버튼을 추가했습니다.

- 웹: 세션을 선택하고 **터미널 설정 → 자동화 초기화·재실행**을 누릅니다.
- Mac: 세션 상세의 자동 승인 영역에서 같은 버튼을 누릅니다.

선택한 세션과 같은 자동 승인 설정을 공유하는 Claude 하위 세션의 대기 작업·재시도·감지 캐시를 즉시 비웁니다. 이후 최신 원본 화면·질문을 다시 읽어 자동화를 시작합니다. 초기화 전에 시작된 느린 조회나 취소된 작업이 돌아와 새 상태를 덮거나 후속 입력을 보내지 않도록 실행 세대를 구분합니다.

원본 터미널과 대화, 작성 중인 초안, 자동 승인 OFF·전체 일시정지, 저장된 설정·감사 내역은 유지합니다. 이미 전송 중인 입력은 취소만으로 되돌릴 수 없으므로 해당 요청의 중복 방지 기록을 보존합니다. 실제 Codex 대기 입력을 삭제하거나 원본 CLI를 재실행하는 버튼은 아닙니다.

복구 버튼은 진행 중·완료·실패와 재시도를 표시하며 구버전·오프라인·종료 세션에서는 비활성화합니다. 설정 메뉴는 화면과 관리 영역의 남은 높이에 맞춰 위·아래에 열리고 한 열 안에서 스크롤됩니다. 키보드가 떠 있는 모바일과 짧은 데스크톱 창에서도 버튼을 먼저 볼 수 있습니다. 새 폴링·상주 서비스는 추가하지 않았습니다.

검증:

- Release 전체 **392/392**, 초기화 회귀 **9/9**. 승인·오류 복구·Codex 답변의 전송 전 취소와 전송 중 중복 방지, 늦은 화면 조회, Claude 원본 소켓의 깨움·재연결, 다른 세션 격리와 OFF·일시정지·편집 보존을 검사했습니다.
- 서명 패키지의 Claude 훅·로컬 웹·입력 구성 검사 **3개**와 Chromium·WebKit의 기존 목록/경고/연결 복구 및 새 초기화 UI **26그룹**이 통과했습니다. 웹은 **390×844·768×1024·1440×900**, 280px 키보드 모사, 650px 데스크톱 창, 밝음/어두움·포커스·진행/성공/실패·구버전/연결 해제/복구 상태를 확인했습니다.
- Impeccable 검사 결과는 빈 목록이며 Web Interface Guidelines로 변경 범위를 검토했습니다. Mac 네이티브 미리보기는 컴파일했지만 CUA 도구 연결 오류로 버튼 클릭·창 크기별 시각 검증은 완료하지 못했습니다. 실물 휴대폰 시험도 수행하지 않았습니다.
- 원본 터미널에 시험 입력이나 캡처를 보내지 않았습니다. 시스템 자동 실행·새 서비스 등록, 관리자 권한 상승, 보안 도구·TCC·VPN 정책 변경은 없습니다.

설치 파일은 기존 발행자 서명과 같은 요구식을 유지합니다. DMG는 **7,717,870바이트**, SHA-256은 `6bb008072d2ae4849df70d9f47a2197b25d893a9522d6c4101afee8370e77023`입니다.
