# Maintained Codex native runtime

This is an AutoApprove maintained build based on OpenAI Codex 0.167.1,
commit `0a94398fa60c4fac0e7659e4213a0a36e613dd46`. It is not an official
OpenAI release. The build label is `autoapprove-managed-1671-2`.

It includes the managed1 subagent approval and Goal controls, plus the
opt-in private native observation, selected input lease, terminal input
hold and process registration patch. `AUTOAPPROVE_NATIVE_RUNTIME_ROOT`
must identify an existing private canonical directory owned by the user.
Without that environment variable or explicit private endpoint variables,
these controls are disabled. An existing unmodified client is not upgraded
by creating the directory.

Registration records locate endpoints. They do not establish complete
session ownership or authorize migration. AutoApprove checks live kernel
process identities and the exact displayed connection separately. Existing
servers and clients are never silently restarted to enable these features.

The source manifest sets `releaseReady: true` after the integration checks below.
`migrationAuthorized: false` remains deliberate: each move requires live app
observations and native leases, rather than permission from a package manifest.
Two actual standalone TUI sizes, 120×36 and
80×24, passed endpoint discovery, Swift connection binding, terminal input
hold/release and exact unsent-draft preservation. These standalone checks alone
do not establish complete group migration or client/cohort ownership; the
application integration below covers that path.

The staged development CLI also passed the same live connection, terminal input
hold, selected server input lease and draft checks through the full CLI entry
point. App preparation against an empty test home started the matching managed
binary, forwarded its private registration root and preserved the kernel process
identity on repeated preparation. A separate debug app bundle passed deep code
signature verification and the embedded-runtime reader. These checks did not
install or launch that debug app, or perform a conversation migration.

Current source additionally checks a home's persistent ownership policy before
resuming a conversation, starting/steering/recovering turns and dispatching known
thread mutations. A shared startup lock now uses the same per-home lock as the
migration journal and remains held through manager publication. Policy storage
now publishes its complete private directory atomically and uses revision checks
for incoming, retired and active states. Twelve filesystem, lock and storage
checks and the complete Core/app-server code check passed. Storage transitions
still require independent native authority and writer-closure checks. This
additional source is not in the staged development CLI above.
The ordinary archive handler can proceed after a shutdown timeout, so its
acknowledgment alone cannot establish the writer closure required for migration.

The current standalone app-server and Swift migration coordinator have now
completed an isolated source shutdown, retirement, destination incoming
reservation, archive/Goal import, activation and durable journal completion.
The destination resumed the same thread with its paused Goal, Goal identity
and counters preserved; the source rejected resume after ownership moved.
The fixture submitted no model turns. A separate import check also covered
retry after an interrupted partial copy. These checks use owned temporary homes
and synthetic client membership; they do not prove the application's live TUI
census, terminal exit/restart or complete UI migration flow.

The rebuilt full CLI also passed the current 120×36 owned-PTY fixture with
the application's Swift connection collector, runtime discovery, physical
input hold/release, selected server lease, cohort observation and journal FD
loan. Navigation preserved the exact unsent draft. The fixture used two local
fake-model responses and no real model API. It exposed and corrected two Swift
interpretation errors: a channel without an explicit handoff owner belongs to
the displayed backend, and a displayed channel's active flag/replay history
does not mean a turn is running.

An additional owned-PTY check now runs the real application's
`prepareCodexSessionMove` and `performCodexSessionMove` APIs against two full-CLI
servers and registered login groups. It completed preparation, native handoff,
archive/Goal import and reconnection in the original shell and TTY. The same
conversation and paused Goal identity were retained and the completed recovery
entry was cleared, without submitting a model turn. That integration exposed
and corrected canonical home comparisons, blocked read-only account inspection
during a selected hold, and unbracketed `/exit` input being retained as a draft.
The test covers one user conversation; it does not substitute for UI checks or
final packaged delivery. The runtime is included with AutoApprove 0.2.281.

The package retains the matching official voice resources and dependency
notices. Its CLI is signed before its binary and voice checksums are recorded.
Embedding it in an app must preserve those bytes. `manifest.json` records
the final CLI checksum and source patch checksums; `native-runtime.patch`
and `native-runtime.manifest.json` describe the additional native changes.
