# AutoApprove 0.2.208 · build 235

Codex·Claude가 테스트 프로그램의 OS 권한창을 기다릴 때 **해당 세션의 정책으로 승인**합니다. 기본은 직접 확인이며 다른 세션의 정책을 가져오지 않습니다.

- **설정:** Mac 앱 또는 웹에서 원래 CLI 세션을 선택하고 **OS 권한 정책**을 엽니다. 현재 요청에서 **이 세션에서 … 허용**을 누르거나 **허용할 권한·등록 앱**에서 종류를 선택합니다. 다른 앱 제어·손쉬운 사용·화면 기록·카메라·마이크·파일·로컬 네트워크·전체 디스크 접근·앱 관리와 **기타 OS 접근 권한**을 구분합니다. 기타는 연락처·위치 등 별도로 분류하지 못한 접근 요청을 포함합니다.
- **앱 범위:** OS 요청의 앱 이름·경로·내용을 확인해 **이 앱을 이 세션에 등록**합니다. 같은 경로와 서명 신원을 만족하는 앱에만 정책을 적용합니다. **이 요청만 이 세션에 연결**하면 현재 요청과 그 요청에서 연속되는 설정 단계에만 적용합니다. Terminal·브라우저·Codex/Claude Computer Use처럼 여러 작업이 공유하는 앱은 현재 요청만 연결할 수 있습니다.
- **승인:** Apple이 서명한 알려진 OS 권한 UI와 요청 앱의 PID·시작 시각·서명·경로, 원래 CLI 실행과 현재 정책을 새로 확인합니다. 허용 버튼을 한 번 누르거나 OS 설정을 열어 정확한 앱의 꺼진 스위치만 켭니다. 설정 조작은 30초의 원래 요청 범위에 묶이며 끝난 뒤 사용자가 다시 끈 권한을 재활성화하지 않습니다.
- **대기와 중지:** 전체 일시정지·세션 자동 승인 OFF·종류/앱 등록 해제·사용자 입력·CLI 교체·연결/창 변경은 후속 조작을 멈춥니다. 권한 대기 중에는 Codex 30분 진척 확인과 관련 터미널 자동 입력을 보류하고, 대기가 끝나면 새 관찰부터 시작합니다. 귀속 미확인 OS 창이 있을 때도 진척 확인을 보류하지만 다른 세션이 실제로 권한을 요청했다고 표시하지 않습니다.
- **직접 확인이 필요한 경우:** 암호·Touch ID·관리자 인증, 조작할 수 없는 OS 버튼/설정, 앱 또는 창의 신원 미확인, 지원하지 않는 화면은 Mac에서 직접 처리합니다. AutoApprove 자체의 초기 손쉬운 사용 권한도 먼저 필요합니다. TCC 데이터베이스나 보안 설정을 직접 바꿔 우회하지 않습니다.
- **관리 앱의 초기 설정:** AutoApprove 자신이 요청한 로컬 네트워크 등의 권한은 CLI 정책에 연결하거나 자동 승인하지 않습니다. Mac에서 직접 설정할 때까지 안내를 유지하되 다른 CLI의 승인 감지·진척 확인은 계속합니다. 다른 경로로 앱을 실행하면 macOS가 네트워크 권한을 다시 요청할 수 있습니다.
- **기록과 복구:** 조작 전에 감사 기록과 전달 영수증을 저장합니다. 입력 결과가 불확실하거나 재시작 후 이전 조작이 남으면 자동 반복하지 않습니다. **Mac에서 처리 완료로 표시**는 직접 확인한 대기 표시를 정리하는 기능이며 권한을 부여하는 버튼이 아닙니다. 정책은 원래 CLI의 PID·시작 시각·TTY에 묶이므로 새 CLI 실행이나 프로필 복원에 자동 상속하지 않습니다. 정책 해제는 macOS가 이미 부여한 권한을 회수하지 않습니다.

검사 범위와 실제 OS/합성 권한창의 구분, 배포·설치 결과는 [검증 기록](../../VALIDATION.md)에 남깁니다.
