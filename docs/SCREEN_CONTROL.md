# 공유 화면에서 키보드·마우스 사용

1. Mac의 **연결 설정 → 터미널 중계·화면 공유 → 화면 조작 허용**을 누릅니다. 시스템 설정의 **개인정보 보호 및 보안 → 손쉬운 사용**에서 AutoApprove를 허용합니다. 화면 기록 권한도 필요합니다.
2. 같은 네트워크 또는 기존 Cloudflare 주소를 브라우저에서 열고 **화면 공유**를 시작합니다.
3. 공유 화면의 **조작하기**를 켭니다. 기본 화면은 보기 전용이며, 새로 열 때마다 조작을 직접 켭니다.

화면에서 클릭·드래그·더블 클릭·우클릭·휠 스크롤을 사용할 수 있습니다. **키보드 입력**을 선택해 한글·텍스트를 입력하거나 붙여넣으면 바로 전달합니다. Tab·방향키·Enter와 Mac의 전체 선택·복사·붙여넣기·실행 취소는 화면 아래 버튼으로도 보냅니다. Mac 단축키 버튼은 Mac의 클립보드에 작동하며, 기기 사이의 클립보드를 읽거나 동기화하지 않습니다.

휴대폰에서는 화면을 탭하거나 드래그합니다. **터치 보조 클릭**을 켜면 다음 탭이 우클릭이 됩니다. 두 손가락으로 스크롤할 수 있고 키보드 입력란을 눌러 소프트웨어 키보드를 엽니다. 화면의 확대는 보기 전용 상태에서 사용할 수 있습니다.

**Esc 키**는 원격 조작을 종료합니다. Mac에 Esc를 보내려면 화면 아래 **Esc 버튼**을 누릅니다. **조작 종료**·대화상자 닫기·화면 숨김·공유 종료도 입력 연결을 끝냅니다. 연결이 끊기거나 최신 화면을 받지 못하면 조작을 멈추고 눌린 마우스 버튼을 해제합니다. 전송 여부가 불확실한 입력을 자동으로 다시 보내지 않습니다. 아직 보내지 않은 텍스트는 현재 페이지의 메모리에만 남으므로 원본을 확인하고 다시 보내세요.

한 Mac은 동시에 한 화면에서만 조작합니다. 창 하나를 공유했다면 그 창이 가려지지 않게 하고 먼저 클릭해 선택한 뒤 키보드를 입력합니다. 다른 창에 가린 지점에는 클릭하지 않습니다. 창이 닫히거나 소유 프로세스가 바뀌면 조작을 종료합니다. 같은 터미널을 조작하는 동안 자동 승인은 수동 입력에 우선권을 양보합니다.

조작 중에는 최대 1280px JPEG 화면을 더 자주 받고, 입력은 지속 WebSocket의 작은 바이너리 레코드로 전달합니다. WebSocket을 쓸 수 없는 경로는 첫 입력 전에 순서가 보장되는 HTTP로 선택합니다. 표시한 ms는 입력 확인의 왕복 시간이며 화면 전체의 프레임 지연과 다릅니다. 현재 화면 방식은 JPEG 갱신이며 고정 60fps 영상은 아닙니다. 일부 앱은 macOS Unicode 입력 이벤트 대신 물리 키 코드를 사용하므로 해당 앱의 한글/특수키 동작은 별도로 확인해야 합니다.

0.2.194부터 화면을 새로 확인해도 이미지가 같으면 이미지 본문을 다시 보내거나 디코딩하지 않습니다. 권한·공유 수명·실제 관찰 시각은 매번 확인합니다. 조작 중에는 요청 시작 간격 150ms를 기준으로 응답에 쓴 시간만큼 다음 대기를 줄이고, 동시에 여러 화면을 요청하지 않습니다. 연결 확인 요청에 화면 조작은 3초, 일반 터미널 입력은 7.5초 안에 응답이 없으면 연결을 종료합니다. 유휴 원본·별도 터미널은 기존 복구 경로로 다시 연결하고, 화면 조작은 원본을 확인한 뒤 **조작하기**를 다시 켭니다. 전송 중이던 입력은 자동 재전송하지 않습니다.

구형 호스트에는 조작 버튼을 표시하지 않습니다. 브라우저의 **최신 버전 확인**으로 호스트와 웹을 맞출 수 있습니다. Cloudflare의 도메인·PIN·연결 설정과 PortManager의 주소 배정은 그대로 사용합니다.

0.2.195부터 고해상도 스크롤의 소수 픽셀 이동을 누적하고, 같은 지점·방향·보조키의 연속 스크롤은 16ms 간격으로 모아 보냅니다. 클릭·키 입력·버튼 해제의 순서는 유지합니다. 두 손가락 스크롤은 시작 지점을 기준으로 전달합니다. 터미널과 화면 입력의 송신 버퍼가 잠시 차면 비워진 뒤 추가 입력 없이 전송을 재개합니다. 대기가 20초 이상 지속되면 연결을 종료하고 기존 복구 규칙을 따르며, 미확인 입력을 다시 보내지 않습니다.
