# 0.2.175 · 빌드 202

0.2.174에서 native 문자열에 적용한 일반 출력 판별을 Cocoa/foreign 문자열에도 확장합니다. 메뉴의 필수 행이 없다는 것이 확실하면 전체 정규화 행을 만들지 않습니다. 허가·일반 선택 질문·현재 모델 유지·오류/Goal·최종 원문 확인 정책은 그대로입니다.

Cocoa 원본 UTF-16은 최대4,096단위(데이터8KiB)의 정렬된 임시 버퍼로 읽습니다. CR/LF/CRLF와 끝의 빈 행·마지막300행 범위를 유지하며, 불확실한 Unicode/제어문자는 기존 scalar slice·NFC·공백 정리·선택지 정규식으로 확인합니다. 원문 UTF-8 예산은 정규화 행 없이 정확한 NSString UTF-8 길이로 계산합니다. 변환 실패/0은 기존 Swift UTF-8 계산으로 돌아갑니다. native 판별은 유지하며 관측 밖의 새 캐시·타이머·서비스는 추가하지 않습니다.

정식174와 후보의 실제 Core에 같은 합성16세션을 연결했습니다. **새16프로세스·8쌍·512구간·사전17기준**을 모두 통과했습니다. 구간8개 ABBA/BAAB 비율의 중앙값을 구한 뒤 독립8쌍의 중앙값을 계산했습니다. 아래는 후보/기존 비율이며 절대 시간 중앙값을 나눈 값이 아닙니다.

Cocoa 변경 화면의 CPU 영문12.7%·혼합문자15.9%, 경과 시간 12.4%·17.7% 줄었습니다. native/비변경의 작은 변동은 표에 포함합니다. native 비변경 CPU 증가는 최대약1.9%, 경과 시간 증가는 약2.0%로 기준 안입니다. 최대RSS는 30,294,016→30,392,320바이트로 33,323,417.6바이트 한도 안입니다. 메모리 감소를 주장하지 않습니다.

사전 기준은 Cocoa 변경 CPU≤0.90배·경과≤0.95배, native 변경과 비변경 CPU≤1.05배·경과≤1.10배입니다. 최대RSS는 max(기존×1.10,기존+1MiB) 이하입니다. 모든 상태·읽기/게시·실제 native/foreign 저장 형태를 유지했고 원본16로그/job·512구간·17기준·405입력·양쪽94Core/추가 연결 객체·실행 파일을 따로 대조했습니다. 표본 제외·기준 완화·이전 시간 표본 재사용은 없습니다.
