# AutoApprove 0.2.318 · build 345

Codex 프로세스가 살아 있는데도 AutoApprove가 확인해 둔 대화 ID를 버려 그룹
통신을 막는 경로를 수정했습니다. 정상 작업 화면에 남아 있는 과거 시작 배너를
새 대화로 오인하던 것이 원인입니다.

시작 배너가 있다는 이유만으로 ID를 지우지 않습니다. 대화·작업 기록이 있는
화면에서는 확인한 ID를 유지하며, 대화 기록 없이 초기 환영 화면만 표시되는
경우에는 기존처럼 과거 ID의 사용을 중단해 재확인을 요구합니다. 그룹 구성과
역할은 유지합니다. 화면 관찰은 추가 `/status` 입력을 발생시키지 않습니다.

수정 전 격리 재현에서는 `/new` 없이 정상 작업을 마쳤는데도 ID가 삭제되어,
같은 프로세스의 그룹 연결 판정이 true에서 false로 바뀌었습니다. 수정 후
Terminal·iTerm2 회귀 검사에서 작업 중·완료·이전 출력·안내 문구와 과거 사용자
메시지가 남은 화면의 ID 유지를 확인했습니다. 새 대화 초기 화면에서는 과거
ID로 전달하지 못하고, 저장된 그룹 구성은 보존하는 것도 확인했습니다.

검사는 가짜 터미널 어댑터와 합성 대화를 사용했습니다. 사용자 터미널을
재시작하거나 시험 입력을 보내지 않았습니다. 이 변경은 확인한 오삭제 경로를
고칩니다. 특정 세션의 다른 연결 장애까지 모두 해결됐다는 의미는 아닙니다.

최종 검증: 디버그 전체 310/310, 릴리스 전체 279/279 검사를 통과했습니다.
실제 공식 Codex 0.169.0을 사용하는 격리된 두 터미널 검사에서도 선택한
로그인 홈만 이동하고 대화·그룹 역할·미확인 메시지·수신 확인을 보존했습니다.
실행 응답 유실 후 복구에서도 대상 터미널별 한 번만 실행되며 대화를 재실행하지
않는 것을 확인했습니다. 이 검사도 사용자 터미널을 조작하지 않았습니다.
