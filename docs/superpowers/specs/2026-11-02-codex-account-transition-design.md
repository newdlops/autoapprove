# Codex 계정 변경 후 창·대화를 유지한 자동 전환

상태: 사용자 지정 순서로 구현. 2026-11-02 요청: 로그인 변경 감지 → 작업 순차 정상 중단·대기 → 공통 서버 전환 → 기존 대화 연결.

## 목적과 확인한 근거

다른 터미널에서 `codex login`으로 계정을 바꾼 뒤 탭을 일일이 닫고 다시 여는 번거로움을 없앤다. 사용자 터미널 UI·창·탭, 작업 폴더·정확한 대화를 유지하고 내부 서버만 새 인증으로 전환한다. 완전 무재시작으로 표시하지 않는다.

설치된 CLI와 현재 관리형 공통 서버는 공식 0.166.0이다. 직접 login은 저장 인증을 바꾸지만 실행 중인 인증 관리자는 캐시를 쓰며 오류 복구의 재읽기는 동일 계정에 한정한다. 공식 TUI의 daemon 메뉴는 서버 재시작 후 자동 재연결을 지원한다.

## 검토한 방식과 선택

1. **선택한 자동 전환의 구현 방향:** 관리형 공통 서버의 인증과 전체 대화 상태를 확인한 뒤 공식 lifecycle로 서버를 한 번 재시작한다. TUI는 원래 대화로 재연결한다. 개별 탭 종료/재개 입력 없이 UI와 실행 설정을 유지한다.
2. 개별 CLI 종료+resume는 이번 초기 범위에서 제외한다. 새 CLI도 기존 공통 서버의 옛 인증을 재사용할 수 있다. PID 교체만으로 전환 성공을 증명할 수 없으며 argv/유효 설정·셸·초안 보존도 별도 구현이 필요하다.
3. Codex 자체의 명시적 인증 reload는 이후 검토한다. 별도 Codex 배포·업데이트 관리가 필요하다.

## 사용자 흐름과 UI

- 기존 연결 설정의 Codex 영역에 `계정 변경 시 같은 대화로 자동 전환`을 추가한다. 초기 기본값은 꺼짐이며 켜면 앞으로의 변경을 감지한다. 세션 자동 승인과 독립적인 설정이다.
- 외부 로그인이 완료되고 새 계정이 확인되면 해당 CODEX_HOME 서버의 전환 한 건을 예약한다. AutoApprove의 생성 입력을 억제하고 실행 중 turn을 정확한 ID로 하나씩 `turn/interrupt`한다. 각 turn의 실제 종료·idle을 확인한 뒤 다음 turn을 중단한다. 탭은 닫지 않는다. 대기 입력·백그라운드 작업·활성 Goal은 임의 삭제하거나 재개하지 않으며 남아 있으면 전환을 보류한다.
- 처음 켰을 때도 저장된 계정과 서버의 실제 계정이 다르면 전환 대기를 표시한다. `현재 로그인으로 전환`은 즉시 재확인/예약하는 수동 경로다.
- 준비 / 계정 확인 / 순차 작업 중단 / 작업 대기 / 서버 전환 / 재연결 확인 / 완료 / 확인 필요·지원 불가, 대상 대화 수와 사유를 표시한다. 서버 전환 전에는 나머지 중단을 취소할 수 있다. 이미 중단한 작업은 자동 재개하지 않는다. 제출 후 중복 제출하지 않는다.
- 기존 SwiftUI의 시스템 서체·의미 색·Toggle·기본 버튼·간격을 유지한다. 600×660 연결 설정에서 긴 경로·여러 홈·많은 대화는 기존 내용 영역에서 스크롤한다. 필요한 세부 상태만 펼치며 키보드 초점·대기/진행/오류/비활성/지원 불가 상태를 확인한다.

## 계정 감지

- CODEX_HOME별 CLI 실행 파일·관리형 서버·사용자 소유 Unix socket을 검증한다. 홈이 다르거나 외부/관리되지 않는 서버는 합치지 않고 지원 불가로 표시한다. 초기 지원은 공식 관리형 로컬 서버 0.166.0 이상과 확인된 RPC 기능에 제한한다.
- 공식 CLI의 별도 stdio app-server에서 `accountSession/list`와 `refreshWorkspaceMetadata:false`로 저장된 활성 사용자/선택 workspace의 안정된 ID를 조회한다. 기존 서버에도 같은 메타데이터 RPC로 유효 계정을 조회한다. 사용자 ID+workspace ID의 비공개 해시만 비교하고 이메일·토큰·본문을 UI/로그/공개 API에 싣지 않는다. sessionId/lastUsedAt/토큰 갱신 시각은 계정 키로 쓰지 않는다.
- auth.json·키체인 토큰을 직접 읽거나 복사하지 않는다. 추론 turn·사용자 대화 로드·모델 호출을 생성하지 않는다. 자체 조회 프로세스는 사용자 세션에서 제외하고 종료한다.
- 파일 metadata 변화는 재확인 신호일 뿐이다. 키체인 변경도 확인하도록 활성 홈만 30초마다 메타데이터를 비교한다. 중첩 조회를 합치고 10초 timeout/실패 backoff를 적용한다. 안정된 ID 미제공·RPC 미지원·조회 실패는 지원 불가/재확인으로 표시한다. 로그인 실패·취소·로그아웃 중간 상태에는 재시작하지 않는다.

## 서버 전환과 성공 판정

- 저장된 새 계정과 기존 서버의 계정 차이가 확인됐을 때만 예약한다. 같으면 변경 없음으로 처리하며 같은 계정 재로그인·토큰 갱신으로 재시작하지 않는다.
- `thread/loaded/list` 전체 페이지와 각 대화 상태·`thread/queue/list`를 읽는다. 현재 화면뿐 아니라 서버를 공유하는 다른 대화·하위 에이전트도 검사한다. 실행 중 turn은 순차 정상 중단하고 종료를 확인한다. queued submission·백그라운드 작업·활성 Goal·진단 실패가 남으면 보류한다. 중단 중 새 turn이 시작되면 다시 중단하지 않고 확인 필요로 남긴다. 부분 조회·timeout·unknown을 idle로 판정하지 않고 직전 상태를 재검증한다.
- 제출 직전 계정·서버 신원·전체 대화 멤버십과 queue를 다시 읽고 변화가 있으면 보류한다. 전환/확인 중에는 같은 서버 대상의 AutoApprove 자동 승인·오류 복구·진척 확인 등 생성 입력을 일시적으로 억제한다. 사용자의 영속 설정은 변경하지 않고 종료 뒤 현재 설정을 따른다.
- 정확한 홈·기존 CLI에서 공식 `codex app-server daemon restart`를 한 번 요청한다. update·feature 설정 변경·전체 Codex kill·터미널 키 입력은 하지 않는다. 공식 명령은 정상 종료 유예 뒤 강제 종료할 수 있으므로 ‘절대 작업 중단 없음’으로 주장하지 않는다. 전체 idle/대기열 확인 뒤에만 제출하며 이후 경합/timeout은 확인 필요로 드러낸다.
- 새 서버의 버전·소유권·유효 계정이 선택 계정과 일치하는지 확인한다. 원래 TUI PID/TTY 유지와 정확한 대화 재연결도 읽기 전용으로 확인한다. 일부 미복구는 개수와 사유를 표시한다. 새 PID나 성공 종료 코드만으로 완료하지 않는다.
- 개별 TUI의 새 서버 연결과 정확한 대화 연결을 증명할 수 있어야 재연결 완료로 표시한다. 대화가 전역 loaded 목록에 있다는 이유만으로 해당 TUI가 복구됐다고 판단하지 않는다. 증거가 부족한 항목은 ‘확인 필요’로 남긴다.
- 실제 대화 재연결은 Codex TUI가 수행한다. AutoApprove는 thread/resume·새 프롬프트를 제출하지 않고 초안·모델·프로필·권한·자동 승인 설정을 다시 만들지 않는다.
- 전환 journal은 기존 오류 복구와 별도로 비공개 저장한다. 예약/제출/확인 단계를 영속 기록해 앱 재시작·중복 클릭·동시 변경에서 동일 전환을 반복하지 않는다. 제출 후 결과 불명확은 자동 재시도하지 않는다. 미제출 요청만 최신 계정에 합칠 수 있다.

## 검증과 완료

먼저 실패하는 검사로 계정 키/같은 계정 갱신/로그아웃 실패·별도 홈·키체인 비교·관리형 소유권, 전체 loaded thread와 queue·경합·불확실 상태, 중복/취소/앱 재시작/두 번째 계정 변경·유효 서버 계정 판정을 고정한다. 격리된 합성 CODEX_HOME과 공식 CLI 서버·TUI 여러 개로 PID/TTY·대화/초안/설정 보존, 재시작 1회·재연결을 검증한다. 생산 사용자 서버를 QA로 재시작하거나 실제 계정을 바꾸지 않는다. CUA가 차단한 Terminal/시스템 알림 조작을 우회하지 않는다.

동일 소스 빌드·검사·커밋·태그·GitHub DMG/서명 ZIP와 각각의 체크섬·공개 재다운로드·로컬 설치/실행 버전 확인까지 완료한다. 미완료 알림 이동 수정은 따로 보존하고 이번 릴리스에 섞지 않는다.
