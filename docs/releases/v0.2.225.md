# 0.2.225 · QUIC 실패 뒤 HTTP2 전환 기회 보장

UDP/QUIC 접속이 실패할 때 커넥터가 같은 전송을 재시도하다 앱의 60초 준비 기한에 교체돼, HTTP2 대체 경로를 시도하지 못하는 경우를 보완합니다.

- 공식 cloudflared의 주소별 재시도 한도를 2회로 지정합니다. `--protocol auto`와 IPv4/IPv6 자동 선택을 유지하며 QUIC이 정상인 환경은 그대로 사용합니다.
- 커넥터 자체가 HTTP2로 전환할 수 있도록 하고 기존 앱의 재접속 속도 제한·인증 gateway·원본 입력의 재전송 방지는 유지합니다. TLS 검증·방화벽·네트워크 설정을 변경하지 않습니다.
- 현재 시험 네트워크에서는 QUIC 응답 시간 초과와 HTTP2 TLS 핸드셰이크 리셋이 모두 관찰됐습니다. 이 수정은 대체 전송을 시도할 기회를 복구하며, 해당 네트워크에서 Cloudflare 터널 연결 성공을 보장하는 수정으로 표시하지 않습니다.

실제 외부 회귀는 제품 controller/gateway와 공식 커넥터를 사용하되 격리된 임시 터널에 합성 GET 응답만 제공합니다. 운영 계정·도메인·사용자 대화는 사용하지 않습니다. 상세 결과는 [검증 기록](../../VALIDATION.md)에 남깁니다.

같은 제품 경로의 수정 전 검사는 55초 동안 QUIC timeout 6회·대체 전환 없음으로 실패했습니다. 수정 후에는 timeout 3회 뒤 **29.24초에 HTTP2 전환**을 확인했습니다. 이는 전체 터널 연결 준비 성공을 뜻하지 않습니다.

최종 전체 Core **616/616**, 기존 터널 설정·인증 브라우저 회귀 6개 검사군이 통과했습니다. 전체 검사 중 발견한 합성 PTY 파일 기록 대기 조건도 보완했으며, 제품 계정 입력 동작은 바꾸지 않았습니다.
