# AutoApprove

macOS Terminal과 VS Code 통합 터미널의 Claude Code·Codex 세션을 관리하는 로컬 앱입니다. 메뉴 막대와 관리 창에서 세션별 자동 승인, 전체 일시정지, 승인 내역, 원래 터미널로 이동을 제공합니다.

현재는 **0.2.6 연결 시제품**입니다. 세션을 발견하는 기능과 자동 승인 가능한 연결을 구분하며, 실제 설치 환경에 따라 지원 범위가 달라집니다.

**Claude Code 또는 Codex가 실행 중인 터미널만 표시합니다.** 목록 상단의 **대기 중 N개** 또는 **대기 중** 필터로 두 도구 중 다음 지시를 기다리는 세션을 찾을 수 있습니다. 상세에는 대기 감지 후 경과 시간과 판정 근거를 표시합니다. 일반 셸과 다른 명령만 실행 중인 터미널은 목록과 상태 개수에 포함하지 않습니다.

프로젝트명 바로 아래에 **터미널 제목**을 표시하고 제목으로도 검색할 수 있습니다. Terminal은 탭의 사용자 지정 제목을 우선하며, 선택된 탭 또는 단일 탭에서는 창 제목도 사용합니다. 제목을 읽지 못한 비활성 탭에 다른 탭의 제목을 대신 붙이지 않습니다. VS Code는 기존 확장이 보내는 터미널 이름을 사용합니다.

0.1.1에서는 Terminal 탭에 없는 `name` 속성 조회로 발생한 `-1728` 연결 오류와, `ps` 열 정렬 공백 때문에 이름이 `claude` 또는 `codex`로만 표시된 프로세스가 누락되는 문제를 수정했습니다. 목록에 TTY·PID를 함께 표시하며 닫힌 탭 하나가 다른 탭의 연결을 중단하지 않도록 처리합니다.

## 실행

빌드된 `dist/AutoApprove.app`을 엽니다. 앱은 세션 탐색부터 시작하며 자동 승인은 기본적으로 꺼져 있습니다.

1. **연결 설정**에서 필요한 연결을 설정합니다.
2. 목록에서 세션의 연결 상태를 확인합니다.
3. 해당 세션의 **자동 승인**을 켭니다. 여러 행을 선택하면 한꺼번에 변경할 수 있습니다.

관리 창을 닫아도 메뉴 막대에서 실행됩니다. 앱을 종료하면 자동 승인도 중지됩니다. 전체 일시정지는 승인 자동화만 멈추며 터미널의 작업은 종료하지 않습니다. 이미 전송된 승인은 되돌리지 않습니다.

**터미널 열기**를 누르면 해당 Terminal 창을 복원·선택하고, 파란 테두리와 프로젝트명·도구·TTY를 약 3초간 표시합니다. 표시는 클릭과 키보드 입력을 가로채지 않습니다. VS Code는 확장 0.2.3에서 이동한 터미널의 이름·TTY 알림과 임시 상태 표시를 제공합니다.

0.2.4부터 터미널 프롬프트와 체크 표시를 조합한 전용 앱 아이콘을 사용합니다. 버튼·필터·자동 승인 스위치·상태·기록 결과에 포인터를 올리면 기능과 현재 상태에 맞는 macOS 툴팁이 표시됩니다. [아이콘 원본과 생성 기록](assets/README.md).

## 승인 내역

세션 상세의 **최근 승인 내역**에서 ‘승인 입력 전달’ 등 결과 행을 누르면 해당 항목의 **전체 요청·전달한 답변·출처**를 바로 펼칩니다. 다시 누르면 접히며 여러 항목을 각각 열어 비교할 수 있습니다.

관리 창 툴바의 **승인 내역**, 세션 상세의 **전체 내역 보기**, 메뉴 막대의 **승인 내역 보기**로 저장된 기록을 엽니다. 프로젝트·명령·도구·TTY를 검색하고 응답 전달·확인 필요·터미널 응답으로 필터링할 수 있습니다. 100건 단위로 이전 기록을 탐색하며, 선택하면 정확한 시각·프로젝트 경로·도구·PID·TTY·요청 내용·전달 결과를 확인하고 복사할 수 있습니다. 질문에 자동으로 답한 기록에는 **선택한 답**도 표시합니다.

세션 종료와 앱 재실행 이후에도 기록을 유지하며 2,000건 초과 시 자동 삭제하던 제한을 제거했습니다. 화면 승인 시도는 전송 전에 저장하고 전달 결과를 같은 기록에 갱신합니다. 결과를 확인하지 못한 시도도 남습니다. 기록 저장에 실패하면 해당 새 승인 입력을 보내지 않고 앱에 오류를 표시합니다.

Claude 훅은 도구 요청 인자를 보존하며, 화면 연결은 읽을 수 있는 요청 내용만 기록합니다. 이전 버전의 기록에 없던 프로젝트·TTY 정보와 이미 삭제된 오래된 기록은 복원할 수 없습니다. **승인 전달은 명령 실행 성공을 뜻하지 않습니다.**

Terminal 연결을 한 번 켜면 앱 재실행 후에도 복원합니다. 명시적인 연결 해제는 유지하며, macOS 자동화 권한 거부 시에는 설정을 허용하고 다시 연결해야 합니다. 0.2.1 이전 버전은 연결 설정을 저장하지 않았으므로 업데이트 후 연결을 한 번 켜주세요. 자동 승인이 켜져 있어도 연결이 끊긴 세션은 목록 상단과 행에 이유를 표시합니다.

## 연결별 동작

| 연결 | 지원 | 조건과 한계 |
|---|---|---|
| 프로세스 탐색 | 기존 Claude·Codex, PID·TTY·프로젝트·터미널 종류 | 도구가 실행된 터미널만 표시. 도구 종료 시 활성 목록에서 제외 |
| Claude 훅 | `PermissionRequest` 직접 승인, 단일 예·아니오 확인, 질문·선택지 표시, 작업 이벤트 | 훅 설정을 읽은 세션부터 가능. 터미널로 반환된 권한 요청은 지원하는 화면 연결이 있을 때 감지·승인 |
| Terminal | 선택한 탭의 승인 화면 감지·단일 입력, 탭으로 이동 | macOS 자동화 권한 필요. 도구·버전별 지원하는 화면 형태만 감지 |
| VS Code 확장 | 터미널 등록·이동, 명령 출력 복원·단일 입력 | shell integration 필요. 확장과 앱 연결 후 시작한 실행부터 출력 감지 |
| Codex 질문 기록 | 화면 밖 비동기 질문 대기열·질문별 알림 | 실행 중인 CLI의 유일한 루트 기록과 로컬 이력 DB를 읽기 전용으로 연결. Codex 0.155.1 기록 형식에서 검증 |
| Codex app-server | 이번 버전의 실행 경로에 포함하지 않음 | 확인한 기존 CLI에 공유 서버 소켓이 없어 터미널 연결을 사용 |

VS Code 확장을 뒤늦게 연결하면 이전 출력은 복구할 수 없습니다. 기존 Claude는 훅 연결을 시도할 수 있고, 기존 Codex는 연결 후 CLI에서 대화를 이어하기 해야 출력 감지가 가능합니다. 연결이 끊긴 VS Code 스트림은 다음 명령부터 다시 제어합니다. SSH, Dev Containers, WSL은 지원하지 않습니다.

화면 감지는 승인 창 제목·선택된 일회 승인 옵션·거부 옵션·화면 끝을 함께 확인합니다. 입력 전 화면 내용과 실행 중인 프로세스를 다시 확인하지만, 터미널의 화면 확인과 입력은 원자적 작업이 아닙니다. 훅 연결은 해당 요청에 직접 응답합니다.

0.2.2는 긴 명령의 승인 창, 한글 정규화 차이, Codex 요청 위쪽 기록 변경을 처리합니다. Claude는 확인 제목 위에 표시되는 명령도 함께 검증합니다. 화면 검증에서 입력 미전달이 확인된 경우에만 새 화면을 받고 최대 3번 재시도합니다. 전송 성공 또는 결과 미확인 상태에서는 같은 화면에 입력을 반복하지 않습니다. 두 승인 요청 사이의 화면 변화를 관찰하지 못하면 직접 확인이 필요할 수 있습니다.

자동 승인을 켠 Claude 세션에서는 **단일 예·아니오 질문**에 ‘예’를 전달합니다. 0.2.5부터 ‘미커밋·브랜치 현황을 훑어볼까요?’처럼 질문 문구가 달라도 두 선택지에 명확한 예·아니오가 있으면 처리합니다. 추천 표시와 예·아니오 뒤에 붙은 설명도 인식하며 선택지 순서에 의존하지 않습니다. 질문·선택지·선택한 답은 승인 내역에 저장합니다. [Claude 공식 훅 응답 형식](https://code.claude.com/docs/en/hooks#pretooluse-decision-control)의 `updatedInput.answers`를 사용합니다. 이 응답은 새 훅 요청부터 적용되며 이미 반환된 질문을 과거 기록으로 다시 실행하지 않습니다.

그 밖의 프로젝트·환경·계획 선택, 삼지선다, 여러 질문과 다중 선택은 **응답 필요**로 표시합니다. 계획 모드 확인도 직접 처리합니다. 전체 일시정지와 세션 자동 승인 끄기는 예·아니오 자동 응답에도 적용됩니다. 사용자 정의 화면이나 지원하지 않는 메뉴 형식은 추가 대응이 필요합니다.

자동 처리할 수 없는 질문은 **macOS 알림**으로 알려줍니다. 알림 또는 ‘터미널 열기’를 누르면 해당 세션으로 이동해 기존 강조 표시를 띄웁니다. 같은 질문은 한 번만 알리고, 해결되면 알림을 정리합니다. Claude의 일반 권한 알림이 원래 질문을 덮어쓰지 않습니다. 종료된 세션의 알림으로 다른 터미널을 열지 않습니다.

처음 실행할 때 알림을 허용해주세요. `연결 설정 → 응답 알림`에서 상태를 확인하고 시스템 알림 설정을 열 수 있습니다. 배너·소리는 macOS와 집중 모드 설정을 따릅니다. [Apple 알림 권한 안내](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications).

## Codex 질문 대기열

Codex가 비동기로 묻고 계속 작업하는 질문도 세션 상세의 **질문 대기열**에 모읍니다. 작업 상태는 그대로 유지하고 목록에 **질문 대기 N건**을 추가하며, **확인 필요** 필터·메뉴 막대 개수·알림에 포함합니다. 여러 질문은 각각 유지되고 일반 메시지나 도구 완료로 사라지지 않습니다. 질문을 인용한 답변이 정확히 한 항목과 일치할 때 그 질문만 정리합니다.

Codex의 로컬 기록에는 권위 있는 미응답 상태가 없어, 인용 없는 답변·취소·동일 문구의 중복 질문은 해결됐다고 추정하지 않습니다. 이미 처리한 항목은 **확인 완료**로 AutoApprove 목록에서 정리할 수 있고 이 설정은 앱 재실행 후에도 유지됩니다. 이 버튼은 Codex에 답변을 보내지 않습니다. 기존 기록에서 복원하므로 오래된 미확인 질문이 처음에 표시될 수 있습니다. 읽기 오류에는 마지막 목록과 오류를 함께 보여줍니다.

실행 중인 프로세스가 열고 있는 세션 파일로 연결하므로 프로젝트 경로가 같은 다른 터미널이나 하위 에이전트 질문을 섞지 않습니다. 하나의 프로세스에 루트 세션이 여러 개면 추정하지 않고 연결 오류로 표시합니다. `thread_history_1.sqlite` 형식이 없는 버전·원격 실행은 이 경로를 지원하지 않습니다. 공유 daemon을 시작하거나 Codex 설정·질문 기록을 수정하지 않습니다. 사용자가 입력해 둔 다음 작업의 메시지 큐(`codex queue`)는 별개이며 이 목록에 포함하지 않습니다.

승인 내역의 `승인 전달` 또는 `승인 입력 전달`은 응답 전송 기록이며 해당 명령의 성공을 뜻하지 않습니다. 영구 허용 규칙은 추가하지 않습니다.

## 대기 상태

- **Claude Code**: 훅의 응답 완료·입력 대기 이벤트를 우선 사용하며 새 입력이나 도구 실행 이벤트가 오면 작업 중으로 전환합니다.
- **Claude·Codex 화면 연결**: 지원하는 입력창과 하단 안내를 함께 확인하고, 같은 대기 화면이 2초 이상 유지될 때 대기로 표시합니다. 중단 안내·실행 중인 백그라운드 작업 표시는 작업 중으로 처리합니다.
- **확인 불가**: 화면 미연결·해제, 알 수 없는 화면 형식, 새 화면 수신 중단은 상태 미확인으로 표시합니다. 출력 정지나 CPU 사용량만으로 대기를 판정하지 않습니다.

대기 시간은 앱이 대기를 감지한 시점부터 계산하며 앱 실행 이전의 시간을 복원하지 않습니다. 사용자 정의 CLI 화면과 다른 훅이 완료 이벤트 이후 이어가는 작업은 상태 추론의 한계가 있습니다.

## 빌드

macOS 14 이상, Swift 6 이상, Node.js 22 이상이 필요합니다. Swift 쪽은 외부 패키지 없이 시스템 SQLite를 사용합니다.

```sh
bash scripts/build.sh
open dist/AutoApprove.app
```

빠른 개발 빌드:

```sh
AUTOAPPROVE_BUILD=debug bash scripts/build.sh
```

확장 패키지는 `dist/autoapprove-bridge.vsix`에 생성되어 앱에도 포함됩니다. 네이티브 앱은 로컬 개발용 ad-hoc 서명을 사용합니다. 외부 배포용 Developer ID 서명·공증은 포함하지 않습니다.

macOS의 신뢰 저장소를 사용하는 네트워크 환경에서 npm 인증서 오류가 발생하면, TLS 검증을 끄지 말고 다음과 같이 시스템 인증서를 사용합니다.

```sh
NODE_OPTIONS=--use-system-ca bash scripts/build.sh
```

## 검증

전체 Xcode가 없는 Command Line Tools 환경에서도 실행할 수 있도록 핵심 검증은 독립 Swift 실행 파일로 제공합니다.

```sh
swift build --disable-sandbox --cache-path .build/cache
.build/debug/autoapprove-checks
npm --prefix extensions/vscode test
node scripts/integration-check.mjs
node scripts/screen-integration-check.mjs
```

`integration-check`는 임시 앱 데이터와 테스트 이벤트만 사용하며 기존 Claude 설정이나 사용자 세션에는 승인을 보내지 않습니다. `screen-integration-check`는 직접 만든 무동작 프로세스를 별도의 PTY에서 실행하고 가짜 확장으로 승인 메시지를 확인합니다. 실제 CLI의 화면 형식이나 VS Code UI 입력 성공을 검증하는 테스트는 아닙니다.

핵심 검증은 세션 분리, 기본 비활성, 중복 요청, 일시정지, 일반 질문, 화면 변경, 다중 세션 승인, 훅 전환 시 취소, 한국어·영어 환경의 동일한 세션 식별, 설정 병합, 영구 저장을 다룹니다.

## CLI와 데이터

```sh
.build/debug/autoapprove scan
.build/debug/autoapprove doctor
.build/debug/autoapprove status
```

앱 설정과 승인 내역은 `~/Library/Application Support/AutoApprove/state.sqlite`에 저장됩니다. 화면과 요청은 외부 서버로 전송하지 않습니다. 로컬 소켓은 같은 사용자만 연결할 수 있습니다.

`AUTOAPPROVE_HOME` 또는 CLI의 `--home PATH`로 별도 데이터 경로를 사용할 수 있습니다. VS Code에는 `autoapprove.socketPath` 설정이 있습니다.

Claude 훅 설치는 `~/.claude/settings.json`을 먼저 백업하고 기존 설정과 훅을 보존합니다. 앱의 훅 제거 버튼은 AutoApprove 항목만 제거합니다. 앱이 꺼져 있거나 2초 내 응답하지 않으면 훅은 원래 승인 흐름을 유지합니다.

구조와 범위는 [DESIGN.md](DESIGN.md), 실제 검증 결과는 [VALIDATION.md](VALIDATION.md)에 기록합니다.
