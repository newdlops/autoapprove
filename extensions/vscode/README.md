# AutoApprove Bridge

AutoApprove macOS 앱과 로컬 VS Code 통합 터미널을 연결합니다.

1. AutoApprove 앱을 실행합니다.
2. 확장을 설치합니다. 기존 창에는 `Developer: Reload Window`가 필요할 수 있습니다.
3. 연결 후 터미널에서 Claude Code 또는 Codex를 실행합니다.
4. 앱에서 해당 세션의 자동 승인을 켭니다.

기존 터미널도 등록되어 원래 터미널로 이동할 수 있습니다. 공식 VS Code API의 ANSI 출력 감지는 확장이 설치된 뒤 시작한 명령부터 지원합니다. 0.2.8과 AutoApprove 0.2.43에서는 그 전에 실행한 터미널도 Mac의 화면 기록·손쉬운 사용 권한으로 원본 편집기 창을 표시하고 같은 터미널에 직접 입력할 수 있습니다. 웹의 연결 버튼이 해당 창과 터미널을 선택합니다. VS Code·Cursor·Windsurf·VSCodium의 로컬 macOS 창을 지원하며, 창의 상태 표시줄과 터미널 입력 영역이 보여야 합니다. 영어·한국어 입력 영역만 확인하며, 같은 창에 이름이 같은 터미널이 여러 개 있으면 창 캡처 연결을 거부합니다. Claude는 앱의 훅 연결도 사용할 수 있습니다.

0.2.5부터 웹 터미널로 원본 ANSI 글자색·배경색과 굵기·밑줄 등 셀 서식을 전달합니다. 활성 VS Code 테마와 사용자 지정 터미널 색상도 반영합니다. 앱에서 웹 접속을 켜면 같은 개인 네트워크의 브라우저에서 확인할 수 있습니다.

0.2.7은 웹 화면에서 직접 타이핑하고 Backspace·방향키·Delete·Home·End를 사용할 수 있습니다. 실제 VT 커서의 위치·모양·깜박임·숨김도 전달합니다. 최신 앱에서는 자동 승인 ON에서도 입력하며, 출력이 바뀌어도 같은 실행 세대의 키를 전달합니다. 작성 후 전송은 동일 화면을 확인하고, 모든 입력은 전달 기한과 중복 요청을 검사합니다. 구형 앱의 입력 방식도 유지합니다.

0.2.3부터 앱에서 **터미널 열기**를 누르면 선택한 터미널의 프로젝트명·TTY 알림과 3초 동안의 상태 표시로 이동 대상을 알려줍니다.

0.2.8은 앱 연결이 끊겨도 실행 중인 터미널의 출력 읽기를 유지하고 재접속 시 같은 화면을 전달합니다. 원래 명령을 다시 실행할 필요가 없습니다. 명령 종료나 실제 출력 읽기 오류는 화면 감지를 중지합니다. 원격 SSH·Dev Containers·WSL, shell integration이 없는 터미널은 출력 기반 자동 승인 대상이 아닙니다.

확장은 화면을 로컬 Unix socket으로만 전달하며 외부 서버로 보내지 않습니다. 자동 승인 요청은 앱에서 자동 승인을 켠 세션에만 전달합니다. 웹 직접 입력은 자동 승인 설정과 독립적으로 같은 원본 터미널에 전달하며, 실행 세대·응답 기한·중복 요청을 검사합니다. 창 연결도 현재 연결과 선택 세대, 만료 시간을 검사한 뒤에만 창을 선택합니다.
