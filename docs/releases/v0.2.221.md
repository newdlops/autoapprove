# 0.2.221 · 대화 기록의 연속 읽기와 위치 표시

웹 관리자의 **대화 기록**에서 페이지 버튼을 반복해서 누르는 대신 위로 스크롤해 이전 대화를 읽고, 아래로 스크롤해 이후 대화로 돌아갑니다. 새 구간이 추가돼도 읽던 메시지의 화면 위치를 유지합니다. 처음 열 때는 최근 사용자 질문부터 답변을 읽기 시작합니다.

- 상단 **읽는 메시지**에는 현재 작성자와 본문 앞부분이 표시됩니다. 선택기를 열어 불러온 메시지로 바로 이동할 수 있습니다.
- 하단 **불러온 범위**에는 현재 메시지 번호·개수, 위치 막대와 처음/이전/최신/이후 경계가 표시됩니다. 막대를 탭·드래그하거나 키보드로 움직일 수 있습니다. 위치는 불러온 범위 기준이며 서버가 제공하지 않는 전체 대화의 진행률을 추정하지 않습니다.
- 기본 탐색 조작은 스크롤과 **최신으로**입니다. 짧은 대화나 이전 조회 실패 때는 이전 대화 버튼을 보조 경로로 제공합니다. 조회 실패 후 자동 재시도를 반복하지 않습니다.
- 본문 글자·줄 간격·여백을 늘리고 사용자 질문·답변·문단·코드 블록을 구분했습니다. HTML은 문자 그대로 표시하며 전체 Markdown 문법을 지원하는 렌더러는 아닙니다.

화면에는 최대 세 구간을 유지하며 최근 128개 조회 위치의 메타데이터로 앞뒤 이동을 연결합니다. 보관 범위를 넘어선 최근 구간은 **최신으로**에서 다시 엽니다. 닫기/세션 전환 시 대화 본문을 폐기하며 원본 입력·메시지 초안은 변경하지 않습니다.

[정식 릴리스](https://github.com/newdlops/autoapprove/releases/tag/v0.2.221)의 DMG·서명 업데이트 ZIP·체크섬을 공개 다운로드로 확인했습니다. `/Applications/AutoApprove.app`의 실제 실행 **0.2.221/248**, 기존 세션 **19/19개** 보존, 설치된 새 읽기 UI 파일과 실제 대화 조회도 확인했습니다.

실제 Core 직접/중계 HTTP와 Chromium·WebKit의 모바일·태블릿·데스크톱 밝음/어두움 화면에서 탐색·위치 보존·오류 복구·빈/로딩·초안 보존을 검증했습니다. Chromium에서는 모바일 에뮬레이션의 합성 터치 스크롤과 막대 탭도 확인했습니다. 실제 사용자 대화를 브라우저에 렌더링하거나 실물 휴대폰에서 검사한 결과는 아닙니다. 상세 빌드·검증·배포·설치는 [검증 기록](../../VALIDATION.md)에 남깁니다.
