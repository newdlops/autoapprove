# 0.2.147 · 승인 질문의 반복 판별 경량화

승인 질문이 이미 처리한 요청인지 구분할 때 반복되던 공백 검사를 줄였습니다. 단일 ASCII 문자의 여섯 공백은 직접 확인하고, CRLF·결합 문자·특수 공백 등은 기존 `Character.isWhitespace`를 그대로 사용합니다. 기존 요청 지문과 승인 기록, 전체 원문·최신 화면·원본 프로세스·입력 검증은 유지합니다.

실제 Release Core에 같은 사전 준비 Cocoa 화면 16개를 넣어 각 500회 갱신하는 시험을 8쌍 교대로 실행했습니다.

| 처리 경로 | 이전 CPU 중앙값 | 변경 후 | 감소율 |
| --- | ---: | ---: | ---: |
| 변경 없는 화면 | 0.358489초 | 0.316026초 | 약 11.8% |
| 출력이 바뀌는 화면 | 5.418459초 | 5.018798초 | 약 7.4% |

각 버전·경로의 8개 표본을 모두 포함했습니다. 상태 각 4개와 갱신 알림 0/500회가 일치했고 실제 사용자 터미널 읽기·입력·캡처·서버 실행은 없었습니다. 이 수치는 합성 Core 처리 경로의 비교이며 앱 전체 CPU·메모리나 휴대폰·VPN 연결 속도의 개선율이 아닙니다.

비공개 문자열 비교 3,336,220건과 전체 회귀 검사 **371/371**이 통과했습니다. 새 회귀는 Codex·Claude의 공백·결합 문자·Unicode·Cocoa 문자열에서 기존 요청 지문과 전체 대화 바이트를 검사합니다. 일반 선택 질문의 수동 응답, Allow·현재 모델 유지, 위험 시스템 변경의 거절과 안전한 대안 안내는 유지합니다.

서명 패키지의 자동 응답 12건·명시적 웹 응답을 기다리는 질문 12건, 일시정지·재시작·응답 유실과 중복 방지, 로컬 웹·MCP·격리 PTY·입력 번들·DMG 무결성 검사도 통과했습니다. 새 서비스·자동 실행 등록이나 보안·VPN·권한 설정 변경은 없습니다.

PR #7의 Codex 기록 해석 경량화와 지난 웹 메시지·끊긴 Mac·경고 정리 기능도 포함합니다. macOS 14 이상 Apple Silicon용이며 빌드는 174입니다. 기존 발행자 인증서를 재사용합니다. 설치 방법은 [설치 안내](../../README.md#설치)를 참고하세요.
