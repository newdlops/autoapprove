# AutoApprove 0.2.308 · 빌드 335

바쁜 그룹장에게 여러 구성원이 동시에 질문해도 접수한 메시지를 잃지 않도록 로컬 수신함과 명시적 수신 확인을 추가했습니다. Codex↔Claude 질문·답변, 일반 그룹 메시지, 자동 작업 완료 보고와 선택지·권한 질문에 적용합니다.

- 디스크 트랜잭션 저장에 성공한 뒤에만 `accepted: true`를 반환합니다. 저장 실패나 미확인 메시지 1,000건 한도에서는 접수를 거부하고 기존 메시지를 보존합니다.
- `get_group_messages(groupID)`로 접수 순서대로 읽고 `ack_group_messages(groupID, messageIDs)`로 수신 확인합니다. 조회만으로 삭제하거나 완료 처리하지 않습니다. ACK 기록도 유지합니다.
- 발신자는 `direction: "outbox", includeAcknowledged: true`로 상대의 수신 상태를 확인합니다. 같은 메시지 재호출에는 같은 `messageID` UUID를 사용합니다. UUID 생략 시 같은 대상·본문의 미확인 메시지만 합칩니다.
- 입력 충돌·끊긴 연결·일시정지·앱 재시작 중에도 보관합니다. 원래 그룹 구성원의 연결과 빈 입력창을 재확인한 뒤 짧은 수신함 알림을 보냅니다. 기본 5초 간격으로 대상을 확인하고, 제출 여부가 불확실하거나 아직 ACK가 없으면 120초 뒤 알림을 재시도합니다. 메시지 본문은 반복 입력하지 않습니다.
- 그룹 ID와 안정적인 구성원 ID로 라우팅합니다. 같은 그룹 밖이나 다른 스레드로 우회하지 않습니다. SQLite 파일과 Unix 소켓, 기존 터미널 입력 경로만 사용하며 네트워크 격리 중에도 동작합니다.

보장하는 것은 **접수한 메시지의 보관, 재알림, 수신 확인 상태의 구분**입니다. 수신자가 계속 종료돼 있거나 새 수신함 도구를 사용할 수 없으면 미확인 상태로 남습니다. ACK는 에이전트가 받았다는 확인이며 작업 수행·동의·승인의 보장은 아닙니다. 알림은 반복될 수 있으므로 같은 메시지 ID의 작업을 다시 수행하지 않아야 합니다. 저장 장치 자체의 손실까지 복구하는 백업 기능은 아닙니다.

작업 지시는 기존 `assign_group_task`, 실제 선택지·권한 답변은 현재 화면을 다시 검증하는 `answer_group_question`을 사용합니다. 수신함에 남은 과거 승인 요청만으로 승인하지 않습니다. 일반 질문·답변이 작업 지시·승인 권한을 부여하지 않습니다.

이미 열린 에이전트는 이전 MCP 도구 목록을 유지할 수 있습니다. 새 `get_group_messages`·`ack_group_messages`가 보이는 MCP 연결이 필요하며, 앱 설치만으로 기존 세션의 도구 목록이 갱신됐다고 간주하지 않습니다. 진행 중인 사용자 CLI는 자동으로 다시 시작하지 않습니다.

Release 전체 회귀 **270/270**, Debug·Release IP 통신 차단 그룹 검사 **34/34**, MCP 발신자·재연결·소켓 차단 검사를 통과했습니다. 상세 결과는 [VALIDATION.md](../../VALIDATION.md)에 기록합니다.
