# AutoApprove 0.2.294

- Codex MCP 호출의 대화 메타데이터를 읽어 공유 서버의 PID와 실제 호출 대화를 구분합니다. Codex 0.169에서는 `conversationID`를 직접 지정하지 않아도 저장된 그룹을 조회합니다. 메타데이터의 ID가 충돌하거나 명시한 ID와 다르면 거절합니다.
- 터미널이 아직 확인되지 않아도 Codex 홈과 대화 ID가 일치하는 자신의 저장된 그룹 정보는 조회합니다. 이 경우 터미널 연결 완료로 표시하거나 다른 창으로 작업을 보내지 않습니다.
- 호출 메타데이터로 확인된 Codex 그룹장은 자신의 Codex 작업자에게 지시할 수 있습니다. 작업자의 실제 터미널 연결은 반드시 확인합니다. 그룹장 터미널이 미확인이면 보고는 대기하며, 그룹장이 상태 조회로 직접 읽거나 같은 대화의 터미널 연결이 확인된 뒤 전달합니다.
- Codex가 직접 연 대화 파일이 없는 경우 원래 터미널의 빈 입력 화면에서 `/status`를 조회합니다. 작업·질문·초안·입력 충돌이 있으면 보류합니다. 조회는 순서대로 처리하고 실패한 세션은 최소 30초 후에 다시 확인합니다.
- 확인된 새 대화 ID와 같은 대화의 새 실행 프로세스를 기존 Codex 그룹 구성원에 반영합니다. 같은 홈의 중복 대화, 다른 홈과 폴더는 자동 연결하지 않습니다. 승인용으로 저장했던 과거 연결을 현재 대화의 근거로 사용하지 않습니다.
- 새 대화 파일의 ID를 과거 `/status` 캐시보다 우선합니다. 화면 조회 캐시는 최대 2분간 사용하고, 새 대화의 초기 화면을 관찰하면 다시 확인합니다.
- Claude 식별·전달·상태 판단 경로는 유지합니다. 그룹 화면은 현재 세션 확인이 끝난 뒤 최신 저장 값을 읽습니다.

검증: 그룹 검사 22개(기존 Claude 회귀 포함), 실제 Codex 0.169와 격리한 로컬 모델의 MCP 호출자 자동 식별. 사용자 터미널에서 작업을 중단하거나 시험 지시를 입력하지 않았습니다. 터미널 조회에는 기존 입력 권한과 빈 입력 화면이 필요합니다.

이미 연결되어 있는 MCP 프로세스에는 이전 실행 파일이 남아 있으므로 새 호출 메타데이터 처리는 MCP 재연결 후 적용됩니다. 이 빌드는 저장소에서 보관하던 기존 게시자 키로 서명합니다. 다른 키로 서명된 0.2.293 설치본에서는 자동 업데이트의 동일 게시자 검사가 적용을 중단하므로 DMG로 재설치해야 합니다.
