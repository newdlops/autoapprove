# 세션 그룹의 요청과 응답 전달 설계

2026-11-19 설계 확정. AutoApprove는 같은 Mac에 있는 Codex·Claude 그룹의 라우팅 테이블과 통신 장부를 관리한다. 장부가 보증하는 사실은 **누가 누구에게 무엇을 보냈고, 어떤 응답이 어느 요청에 연결됐으며, 어디까지 전달됐는가**다. 응답의 충분성, 업무상 성공 여부, 다음에 할 일은 결과를 사용하는 세션이 판단한다.

## 요청과 회신

요청의 종류, 회신을 기대하는지, 회신이 있어야 다음 일을 진행할 수 있는지는 각각 독립적이다. 보낼 때 선택한 동작으로 다음 기본값을 정한다.

| 동작 | 회신 기본값 | 장부에 기록할 결과 |
|---|---|---|
| 질문하기 | 답변 기대 | 지정한 상대의 응답이 원래 질문에 연결되면 답변 도착 |
| 작업 배정 | 결과 보고 기대 | 작업자의 보고가 원래 배정에 연결되면 결과 도착. 실패 보고도 유효한 회신 |
| 회신 없이 지시하기 또는 일반 메시지 보내기 | 회신 없음(FireAndForget) | 전달 상태만 추적. 회신 대기 없음 |

회신을 기대해도 송신자는 다른 일을 계속할 수 있다. 진행이 막힌 요청만 대기 그래프에 넣는다. A가 B에게 Q1을 묻고, B가 Q1에 답하려고 C에게 Q2를 물으면 C의 답은 Q2만 닫는다. B가 Q2를 기다리며 턴을 끝내도 A에게는 Q1이 미응답으로 남는다. 이후 Q1을 재개한 턴의 응답이 A에게 돌아간다. B가 C에게 참고 사항만 보냈다면 C 쪽에는 대기 간선이 없다. 순환 경고는 등록한 의존성과 기존의 전체·일부 충족 조건을 기준으로 낸다.

## 앱이 한 건을 전달하는 과정

1. **접수.** 앱의 그룹 경로나 기존 MCP로 요청을 보내면 원문, 고정 요청 ID, 그룹 ID, 양쪽 구성원 ID, 대화 ID, 회신 방식을 로컬에 기록한다. 재개·재배정 시 어느 시도인지 구분한다. 답은 최초 지시자에게 돌아간다. 그룹장·부그룹장·동료가 여럿이어도 수신 대상을 바꾸지 않으며, 기존 작업 지시·승인 권한을 적용한다.
2. **요청과 턴 연결.** 앱이 입력한 요청과 그 입력에서 시작한 대화 턴을 연결한다. 근거는 로컬 대화 기록 또는 훅이 식별하는 대화·입력·턴이다. 사용자의 직접 입력, 수신함 알림 처리, 배정 재개를 구별한다. 터미널이 같거나 시각·본문이 유사하다는 사실만으로는 충분하지 않다. 요청 두 건 중 어느 쪽인지 입증할 수 없으면 출력은 원래 대화에 두고 회신은 미확인으로 남긴다.
3. **결과 기록.** 연결된 턴에서 작업자가 이미 작성한 응답 원문을 한 번 보존한다. 요청에 응답을 연결하고 원래 송신자의 로컬 수신함에 전달 항목을 넣는 일은 하나의 트랜잭션이다. ‘응답 도착’과 ‘송신자 대화에 전달됨’을 따로 기록한다. 수신 확인이나 본문 없는 턴 종료 이벤트로 회신을 생성하지 않는다. 회신 도착은 작업의 성공을 보증하지 않는다.
4. **결과 전달.** 정상 경로에서는 앱이 답변 본문을 원래 송신자에게 건넨다. 수신함 조회, ACK, 보고용 재작성 때문에 모델 턴을 추가하지 않는다. 송신자가 바쁘거나 초안·승인창이 있으면 결과를 보존했다가 안전한 시점에 전달한다. 등록한 대기가 풀리는 경우 결과 전달이 곧 재개 신호다. 여러 결과를 모두 기다리면 마지막 결과에서, 하나만 기다리면 첫 결과에서 한 번 재개한다.

그룹을 통해 접수한 뒤에는 양쪽 세션이 AutoApprove MCP를 다시 호출할 필요가 없다. 앱이 관찰, 타이머, 수신함, 재연결을 맡는다. MCP 없이 앱에서 시작한 요청에도 같은 규칙을 적용한다. 앱이 보지 못한 개인 대화의 답신 대상을 추정하지 않는다. 그룹 연결과 전달은 같은 머신 안에서 동작하며 외부 네트워크에 의존하지 않는다.

## 원문 보관과 토큰 비용

비용 설계의 전제는 **출력 토큰 단가가 입력 토큰 단가보다 높다**는 것이다. 이미 쓴 답을 받아 읽는 입력 비용, 답을 다시 요구하고 재작성하는 출력 비용, 추가 왕복 횟수를 함께 계산한다. 요약 전담 세션은 두지 않는다.

| 조건 | 한 번의 전달에 포함하는 내용 |
|---|---|
| 원문이 수신자의 전달 예산 안에 있음 | 원문 전체. 수신자가 전문을 다시 요청할 필요가 없다. |
| 한 답 또는 동시에 도착한 답들의 합이 예산을 넘음 | 전달 순서에 따라 예산에 들어가는 답의 원문을 담는다. 싣지 못한 건은 길이와 그룹 내 원문 참조로 전달한다. 수신자는 발신자를 깨우지 않고 필요한 범위를 읽을 수 있다. |
| 처음부터 전문 전달을 선택함 | 원문 전체를 전달한다. 터미널이 한 번에 안전하게 받는 크기 자체를 넘으면 그 이유와 길이·원문 참조를 제공한다. |

예산은 건별 한도와 수신자별 한 번의 전달 총량에 모두 적용한다. 예산 수치는 실제 Codex·Claude의 안전한 입력 크기와 왕복 비용을 측정해 정한다. 원문 참조를 열 때도 원 요청의 송수신 권한을 확인한다. 어떤 실패가 중요한지, 어느 문장이 결론인지 앱이 선별하지 않는다. B가 받은 C의 원문을 B의 응답에 자동 첨부하지 않는다. 명시적으로 수정된 응답은 새 버전으로 연결해 A에게 전달한 버전과 구별한다. 이후에 관측한 일반 발언은 기존 답을 덮어쓰지 않는다.

## 무응답과 중복 처리

- **상태와 결과.** 열린 요청 옆에 마지막 관측 시각과 ‘작업 중’, ‘유휴’, ‘셸 실행 중’, ‘연결 끊김’, ‘미확인’을 표시할 수 있다. 유휴 상태에서는 작업 완료, 백그라운드 대기, 임의 중단을 구별할 수 없다. 멈춘 명령과 정상적인 연결 유지 프로세스도 똑같이 ‘셸 실행 중’으로 보일 수 있다. 상태만 보고 완료 처리, 재배정, 프로세스 종료를 실행하지 않는다.
- **기한과 늦은 답.** 로컬 기한이 지나면 이번 차단 대기는 ‘기한까지 미응답’으로 한 번 끝난다. 요청은 원래 ID로 늦은 답을 받을 수 있다. 답이 오면 수신함에 보존하되 이미 만료된 대기를 다시 깨우지 않는다. 기한과 결과가 경합하면 저장 순서로 한 번만 대기를 해소한다. 주기적인 상태 질문이나 모델의 크론 호출은 필요 없다.
- **에코와 재시작.** 원 요청·응답 버전·수신자에 대해 하나의 전달 기록을 유지한다. 수신 알림에 반응한 턴은 새 회신의 출처가 될 수 없다. 재시작 후 미전송임이 확인되면 재개한다. 터미널 입력 직후 앱이 종료되어 제출 여부가 불확실하면 대화 기록과 먼저 대조한다. 확인할 수 없으면 수신함에 보존하고 ‘전달 미확인’으로 표시한다. DB 기록과 터미널 입력 사이에서 죽었을 때 같은 프롬프트를 무조건 재전송할 수는 없다.
- **대화 교체.** `/clear`나 재연결 뒤에는 검증된 구성원 소속과 원래 요청 ID를 사용한다. 옛 턴의 결과는 옛 배정에만 연결한다. 새 배정의 결과로 잘못 귀속하거나 다른 그룹에 있는 같은 이름의 구성원에게 전달하지 않는다.

## 기존 기능과 인수 조건

현재 앱에는 그룹 라우팅, 로컬 수신함, 질문 ID, 복수 의존성 대기와 순환 감지가 있다. 기존 경로의 수신함 조회·ACK 알림, 대기 이력이 있는 작업의 명시적 완료 호출, 600자로 제한된 완료 요약은 자동 원문 전달을 구현할 때 바뀌어야 할 지점이다. 기존 MCP 호출자는 계속 사용할 수 있어야 한다. 같은 회신을 명시적으로 제출하고 앱도 관측했다면 원 요청과 응답 식별자를 기준으로 한 건으로 합친다. 다음 조건은 구현 시 검증한다.

| 사례 | 합격 기준 |
|---|---|
| 양쪽 AutoApprove MCP 비활성, 외부 네트워크 격리 | 앱에서 시작한 Codex → Claude, Claude → Codex 요청 모두 수신자가 평소처럼 한 번 쓴 답이 원래 송신자에게 도착한다. 전달용 모델 출력과 필수 조회 호출은 0회다. |
| A → B → C, B가 C의 결과를 읽음 | B 수신함 1건, A 수신함 0건. B가 A의 Q1에 답했을 때만 A에 1건이 생긴다. |
| 일반 지시를 FireAndForget으로 보냄 | 지정 대상의 전달 상태를 확인할 수 있고, 회신 대기와 자동 역방향 전송은 각각 0건이다. |
| 같은 수신자에게 열린 요청 두 건과 사용자 직접 입력 | 연결이 확인된 요청만 닫힌다. 다른 요청과 개인 대화 내용은 전달하지 않는다. |
| 유휴 워커, 멈춘 셸, 장기 실행 중인 셸 | 앱은 관측 사실과 기한을 기록한다. 자동 성공, 자동 종료, 워커 재촉은 각각 0회다. 기존 회신이 있는데 대기만 남았다면 장부로 복구한다. |
| 기한 만료와 답 도착 경합, 중복 이벤트, 앱 재시작, 대화 교체 | 원 요청의 결과는 버전당 한 건, 동일한 차단 대기의 재개는 최대 한 번이다. 늦은 결과는 원래 건에서 찾을 수 있다. |
| 긴 응답 및 여러 건의 동시 도착 | 원문을 보존하고 기본 전달 예산을 지킨다. 싣지 못한 원문은 참조로 읽을 수 있다. 전담 요약·재작성·전체 그룹 복제는 0회다. |

## 0.2.331 구현 범위

그룹 창에서 질문과 FireAndForget 메시지를 접수한다. 직접 전달에 쓰는 입력을 대화 ID와 함께 로컬에 기록하고, 확인한 턴 하나에 묶는다. Claude는 제출·응답 종료 훅을, Codex는 로컬 턴 기록을 사용한다. 응답을 기록하고 회신을 저장하는 과정에 별도 모델 호출이 없다. 4,096바이트는 머리말과 본문을 합한 터미널 입력 한도다. 이 한도를 넘는 원문은 기존 수신함 조회로 접근할 수 있다.

0.2.332는 확인된 새 배정의 원문 보고, 복합 대기의 일괄 전달과 재개, Claude 질문의 로컬 기록 복구를 추가한다. 전송 한도는 계속 4,096바이트다. 전문 전달 모드와 수신자별 입력량 측정은 별도 검증 범위다.
