# AutoApprove 0.2.320 · build 347

세션 프로필에 모델·추론 수준과 Codex 처리 속도(Standard·Fast·Ultrafast·Flex)를
저장하고 복원합니다. 저장 화면에서 설정을 확인·편집할 수 있으며, 복원 시
해당 CLI의 모델·추론·서비스 등급 인자로 전달합니다. 프로필 형식은 4이며
기존 1~3 파일도 읽습니다. 설정이 없는 기존 항목은 CLI 설정을 유지합니다.

자동 저장은 대화 UUID와 로그인 홈이 일치하는 로컬 기록을 사용합니다. Codex는
해당 대화가 소유한 설정 체크포인트를 우선하고, Claude는 마지막 실행 모델과
추론 수준을 읽습니다. 일부 설정을 확인하지 못하면 저장 화면에서 알립니다.
전역 기본값으로 세션의 처리 속도를 추정하지 않습니다. 모델·계정이 지원하는
추론 수준과 처리 속도만 실제 CLI에서 사용할 수 있습니다.

`clear_session_group(groupID, requestID)`는 그룹 전체의 `/clear`와 새 세션 ID
갱신을 비동기로 접수합니다. 그룹장이 있으면 그룹장만 요청할 수 있습니다.
호출자도 포함하며 다른 구성원을 처리한 뒤 마지막에 실행합니다. 작업·질문·승인·
작성 중인 입력이 있으면 빈 입력창을 기다립니다. 원래 프로세스의 시작 시점·
터미널·대화와 소속을 다시 확인하고, 그룹장이나 소속이 바뀌면 대기 요청을
실행하지 않습니다.

새 UUID를 확인한 구성원만 갱신합니다. 그룹 구성원 ID·역할과 미확인 수신함은
보존하고, 초기화된 구성원의 미완료 작업은 이전 작업으로 분리합니다. 동일한
`requestID`로 재호출하면 기존 요청을 반환합니다. 앱 재시작이나 응답 유실로
전달 결과가 불확실해도 `/clear`를 자동 재전송하지 않습니다. ID 확인도 유한하게
재시도하며, 확인할 수 없는 구성원은 `needs_review`로 남습니다.

`get_group_clear_status(groupID, requestID?)`로 진행과 구성원별 이전·새 UUID를
조회합니다. 요청 ID를 생략하면 최근 요청을 조회하므로 초기화 뒤 새 대화에서도
결과를 찾을 수 있습니다. `done=true`와 `status=completed`를 함께 확인해야
전체 초기화·ID 갱신 완료입니다. 새 MCP 도구 목록은 기존 연결을 다시 연결하면
표시됩니다. 그룹 통신은 같은 Mac의 로컬 경로를 사용합니다.

검사는 소유한 파일·가짜 터미널·격리된 공식 Codex와 별도 프로필 QA 앱을 사용합니다.
검증을 위해 사용자의 실제 그룹에 `/clear`를 보내거나 기존 CLI를 재시작하지 않습니다.

검증 결과:

- Debug 핵심 검사 317/317, Release 핵심 검사 286/286, 오프라인 그룹 검사 45/45, 실제 격리 MCP stdio 검사 15/15 통과.
- 프로필 컨트롤러 검사 37개 통과. 모델·추론·속도를 편집해 형식 4로 저장하고 복원 명령에 전달하는 경로를 확인했습니다.
- 별도 QA 앱에서 모델·추론·Fast 편집, 저장, 선택 복원을 수행하고 저장 파일과 명령 인자를 대조했습니다. 실제 사용자 터미널 실행은 0회입니다.
- 네이티브 화면의 최소 크기·기본 크기·넓은 화면과 밝은/어두운 화면, 편집·잘못된 ID 오류 표시를 확인했습니다.
- 격리된 공식 Codex 0.169.0에서 모델·xhigh·Ultrafast 인자를 포함한 프로필 실행이 시작되는 것을 확인했습니다. 실제 유료 추론은 실행하지 않았습니다.
