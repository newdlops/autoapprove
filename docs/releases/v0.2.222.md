# 0.2.222 · 반복 네트워크 알림 중 HTTPS 연결 복구

네트워크 복귀·시스템 깨우기 알림이 반복되는 동안 HTTPS 중계 소켓이 응답하지 않으면 ping 확인 기한이 계속 갱신돼 복구가 늦어질 수 있었습니다. 진행 중인 ping을 하나로 합치고 최초 응답 기한을 유지합니다. 정상 응답·기한 만료·연결 교체 때 대기 상태를 해제해 다음 확인을 계속합니다.

인증·공개 주소 검증·입력 전달과 변경 요청 재전송 정책은 유지합니다. 이 수정은 전체 네트워크·자동화 안정성 목표 중 확인된 한 원인을 다룹니다. 실제 무선망의 UDP 검색·장시간 외부 HTTPS·화면/스크롤 변화의 전체 개선 완료를 뜻하지 않습니다. 검증·배포·설치 결과는 [검증 기록](../../VALIDATION.md)에 남깁니다.

실제 로컬 workerd와 Swift 중계에 300ms마다 복귀 알림을 보내는 검사에서 수정 전은 8초 제한을 넘겼고, 수정 후 **3,053ms**에 복구했습니다. 정상 주기 ping 두 번 뒤 같은 장애를 준 검사도 **3,075ms**에 복구했으며 정상 연결의 불필요한 재접속·변경 요청 중복은 없었습니다. 중계 fixture는 agent의 접속을 로컬 WS로 매핑하므로 이 수치를 외부 TLS·무선망 전체의 복구 시간으로 일반화하지 않습니다.

수정 전후 전체 Core는 각각 **614/614**입니다. [정식 릴리스](https://github.com/newdlops/autoapprove/releases/tag/v0.2.222)의 파일 4개와 설치·실행 버전 **0.2.222/249**를 확인했습니다. 실제 프로세스 세션 **19/19개**는 유지됐으나 PID 0 임시 훅 항목 2개는 재발견되지 않아 전체 21개 보존 검사는 실패했습니다. 해당 항목은 안정성 목표에서 추가 조사하며 전체 세션 보존 성공으로 표시하지 않습니다.
